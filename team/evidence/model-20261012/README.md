## 本轮交付与数据来源

[模型目录](../../models/vdot/README.md) 提供精确数学 oracle、候选编码检查、纯函数向量状态适配层、生成器与单元测试。正式数据为本轮首次生成：22 组定向算术、10,000 组 SHA-256 确定序列随机输入、54 组 smoke 输入、69 组状态/编码用例。smoke 是前述输入的子集，不是额外独立的随机覆盖。

[manifest](../../models/vdot/data/manifest.json) 保存合同、种子、序列算法、计数、模型/生成器源码及数据 SHA-256。检查过全部保存的算术期望值，而非仅比较生成器自己重跑的输出。生成器测试还验证：文件缺失、数据被篡改和源码来源变化时，`--check` 返回失败并保持被检查文件不变。

源码审查修正了一处用例分类问题：不匹配 vdot 的编码可能属于合法 LB/ADDIW，现以 `decoder_reject` 单独记录，不能作为全核非法指令异常预期。部分非法 vtype/vl 状态只是模型接口输入，已明确需要在后续硬件测试中转换成架构可达的准备过程。

## 复现命令与记录

在集成后的完整香山仓库根目录，或 Windows 材料目录对应的 WSL `doc/团队仓库材料` 目录中运行：

```bash
bash team/scripts/check-vdot-model.sh
```

Linux 源码目录与 Windows 材料镜像均已运行通过，验证脚本不依赖硬编码的工作目录。本目录保存第二个位置运行的 [完整检查输出](check.log)；日志执行时工作树尚未提交，模型与生成器内容以同一提交内 manifest 的源码校验和定位，最终提交号以 Git 历史为准。
