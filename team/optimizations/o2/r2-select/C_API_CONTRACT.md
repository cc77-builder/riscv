# R4 普通 C 应用功能合同 v1

合同身份：`r4-gemv-c-application-v1`。操作：`20261024-LiZufan001-r4-entry-0442`。本合同补充[新调用路径合同](ENTRY_CONTRACT.md)，不改变已运行性能批次的合同、源文件、镜像和计时定义。


性能夹具中已执行的叶函数另由普通 C 程序通过函数指针实际调用，覆盖 S1 的4种形状×basic/reuse×vdot/RVV共16个公共函数、3组数据共48个case。该程序采用未修改的 AM 默认启动与链接流程，关闭自动向量化；不使用性能夹具的固定槽布局。每次调用前建立有保护区的紧密 A||x 输入与毒化输出；独立标量C计算检查每个完整128位输出、全部输入、未使用尾部及边界保护区，并核对最终向量CSR。主机生成的FNV64只作第二道输出身份检查，UART写出实际输出计算值。

第一case执行低位、高位、输出保护区、输入字节、未使用输出槽5种软件破坏自检，必须全部检出并恢复；它们不替代真实DiffTest负控。新镜像顺序执行真实vdot高位负控、同BIN新进程正常恢复、正常功能重放，原始日志须表明48case/16函数全部通过、O2两槽事务闭合且每次正常运行1008条vdot提交。重放比较功能输出与判定，不产生周期样本；共96次正常case执行不计入性能矩阵的384个正式窗口。

`entry_c_api.py`固定生成、真实构建、运行与原始判定；`entry_c_evidence.py`单独封存C证据，并锚定完整性能档案的manifest哈希以复用相同硬件/参考库来源。C功能通过仅覆盖本合同的输入形状、布局、VLEN、ABI和执行计划；不宣称任意应用、任意指针别名、通用BLAS接口或完整应用加速比。新C程序及校验器均为团队新增文件，官方AM、NEMU和既有判定程序保持原样。
