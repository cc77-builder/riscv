# R4/O5：获选 GEMV 普通调用入口验证合同 v1

操作：20261024-LiZufan001-r4-entry-0442。来源提交：ac2f4082a6a4710dca6a739f66d6fa77c49552b8。此合同只新增软件调用路径；固定 O2/H1 合并硬件、正常 NEMU、官方程序及既有 S1/S2/SELECT 合同与证据原样保留。

## 目标与最小试验

将已有 S0/S1 GEMV 直线内核导出为按形状区分的普通 RV64 C ABI 叶函数，参数为紧密相邻的行优先 A[M][K] 与 x[K] 的地址，以及 M 个 16 字节输出槽的地址。结果低32位有符号、其余96位清零，输入输出不得重叠；VLEN128、SEW8、VS可用条件与现行规格一致。不引入运行时 dispatcher，不改变默认入口。每个形状提供 basic/reuse、vdot/RVV，S0保留回退；最终采用按真实数据决定。

调用函数内部包含向量状态建立、全部输入读取、累加和全部输出写回；不要求调用者预先清零向量寄存器。函数只使用标准调用者保存的整数/向量寄存器，返回时VL8/e8/m1/tu/mu、vstart0、vcsr7；不承诺保留调用者向量配置。软件无时钟/复位改动，硬件接口/II/时延均不改变。

先在8×32、dataset0、endtoend建立S0/S1各一个新ELF（每个仍含basic/reuse×vdot/RVV四case）。测量窗包含实参移动、一次真实直接调用、叶函数全部指令、返回和观测指针恢复。测量夹具自身的寄存器快照/栈帧建立在窗外，双方相同。保留原first/warmup及4正式repeat、AB/BA顺序；原周期不作为新路径分母。

## 正确性与公平性

- 新生成器精确再生；原S0/S1计算body逐行复用。完整128位、未声明scratch、CSR、canary、输出未用区仍由原harness检查。
- 公共函数与独立GNU汇编对象逐字节一致；计算body用已有独立有限机器模型检查所有3数据集、正负边界及随机/毒化初态，行边界读写受检。
- 保留四个8KiB槽、norelax与完整加载映像布局；成对S0/S1所有ALLOC节一致且槽外BIN逐字节相同，公开函数地址也成对一致。
- 新调用路径检查仅支持唯一直接jal ra与精确ret，拒绝分支、嵌套调用、逃逸及链接寄存器篡改；真实退休序列、CSR与UART逐项相符。调用/返回不允许隐藏在压缩退休事件中。
- 真实bit100负控重新绑定本次ELF首个vdot的PC/rd/word，随后同BIN、新进程正常恢复；原负控源码与正常黄金NEMU不变。
- S0/S1各一次新进程重放，全部first/warmup/正式窗口的cycles与instret精确相等。EMU顺序运行；构建可最多4个独立单核任务，并随其他Agent实占减少。
- 同新入口下比较S0/S1的全部basic/reuse RVV，取最快合格RVV；仅当S1 reuse vdot在最小试验仍胜强RVV且上述条件全过，才扩大三dataset/受影响形状。

## 范围与退出

首个试验无收益或失败时保留原镜像选择工具与RVV，不据旧10.75周期余量扩大。失败证据保留，只有定位到具体原因才修订。通过不代表T17干净硬件构建、默认切换、ASIC PPA或另一Agent的MERGE-REG交付。运行状态、精确输入与本轮结果在本模块独立证据及Issue中记录。
