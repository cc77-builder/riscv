## 已知边界

1. 冻结负向参考库把正常 NEMU 绝对路径编译进 ELF；入口已识别并核对。新机器需恢复该位置，或在 R4 单独重建并升级输入合同，随后重做负向注入和正常恢复。
2. 旧 O2 pins 对当前 build.sc 的严格检查会拒绝；R0 只承认精确的 O4 附加目标差异，没有改旧 pins。后续真正全核运行使用新构建的 pins。
3. 源码仓库不分发历史大二进制、构建目录和工具缓存。新成员按输入清单恢复并核验；R0 没有证明新机器可以只 git clone 就完整复现。
4. R0 仅锁定封存证据索引，没有重新复算全部旧日志；也没有新的加速比、PPA、全核 reset 覆盖或人工 ACK。
5. 构建命令在新 checkout 的完整执行仍需 R4/T17 验收。Maven/下载缓存及操作系统尚未成为完全封闭的离线构建镜像。
