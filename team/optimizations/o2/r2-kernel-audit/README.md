# R2 原内核反汇编与瓶颈审查（2026-10-21）

## 结论与分支范围

本轮完成 **R2 的第一轮原内核审查**，没有实施 S1/S2 候选，也没有完成整个 R2。

用户要求：后续工作只提交 `cc77-builder/riscv:zjhwork2`；`zjhwork` 保留为对照，不修改。审查基点为 `17bab1d6e51692ccf1cc007e1ec73054ceda168e`。旧材料中“只发布 zjhwork”等约定是历史任务记录，不适用于本轮。

主要发现：

1. **4×13 优先筛选 S2 安全向量尾部。** 原 reuse 内核有连续 65 条标量尾部指令，占其计算主体 117 条指令的 55.56%。这是指令数量占比，不是周期占比。
2. **16×64 的 S1 应审查跨域搬运和累加。** 原 vdot reuse 内核有 128 次 `vmv.x.s` 和 128 次 `addw`；这 256 条指令占主体的 31.30%。同样不能直接换算为可节省周期。
3. **不能给 S1 随意增加四个 scratch 向量寄存器。** 原 vdot reuse 已使用 v16–v19 装载、v20–v23 保存部分和、v24–v31 保存八个 x 块，16 个 scratch 寄存器预算已满。应先审查复用当前组输出寄存器作 INT32 累加器的合法性，或改变活跃区间；不得静默 spill。
4. **RVV 也有软件优化空间。** 16×64 的 RVV reuse 同样存在 64 次 `vmv.x.s` 和 64 次 `addw`，且每块清零归约种子。S1 必须给 RVV 对等优化机会，不能只改 vdot 后继续除以旧 RVV 成绩。

上述是已确认的静态开销和后续候选优先级，不是已经测得的动态停顿归因或新提速。

## 3. 4×13：标量尾部与 RVV 的结构差异

在原 vdot reuse 中，四条 dot8 只覆盖 4×8=32 对乘积；剩余 4×5=20 对、即总乘积的 38.46%，仍由标量完成。尾部位于 `[0x800031c8, 0x800032cc)`，共 260 字节/65 条指令：

- 5 次 x 尾部 `lb`，供四行共用；20 次 A 尾部 `lb`。
- 20 次 `mulw` 和 20 次标量 `addw`。

原 RVV 使用 VL=13，四次向量乘法和四次宽归约覆盖全部 52 对乘积，没有标量尾部。不能把这个 RVV 对照人为限制为 dot8+标量尾部。

S2 的下一关是：保留原标量尾部作对照；只安全加载剩余五项，明确确保未加载的三个 lane 为零，然后恢复合法 VL=8 执行 dot8。补零、配置切换、累加与存储全部纳入相同计时口径。不得越界读取紧凑布局中下一行的数据，不依赖尾部 agnostic lane 恰好为零，不把补零放到计时窗外，也不放宽生产指令的 VL 合法域。

这是待实现/待测的候选，不预报提速。

## 4. 16×64：跨域搬运、配置切换与寄存器预算

原 vdot reuse 每组四行、每行八个 dot8：总计 128 次点积。每个部分和立即经 `vmv.x.s` 搬到 t6，再 `addw` 到对应行的标量累加器；最后再通过 `vmv.s.x` 写回输出向量。机器码确认 128+128 次搬运/累加，以及 78 次 `vsetivli`。

这在四条点积突发之间插入配置切换、标量消费和后续装载，静态上限制了直接套用纯 batch 吞吐收益的依据；**本轮未测量这些操作分别造成多少 ready/busy、依赖或访存停顿**。

S1 应评估至少 INT32 精度的向量累加，并把新增配置指令、向量加法、寄存器活跃区间和任何 spill 一并核算。输入复用、四行交错、静态展开已经存在，不再把它们列为新成果。当前寄存器分配已满，不能以未说明的额外寄存器换取成绩。

RVV 每次处理至多 16 项，因此只有 64 个乘法/归约块。它也有跨域搬运开销，后续必须允许调整其归约种子/累加策略，再取合格 RVV 中较快者。S1 的指令数减少并不保证胜过更新后的 RVV。

## 5. 历史周期证据，仅复用而非新测量

来源为原 `results-03/comparison.csv`（Git blob `eeeb89edbaf95b375088a86f1d6e2e2ddb41d66c`），每个单元格 12 个正式样本。以下为历史 **O2 B0**，不是 H1 GEMV 新结果；H1 之前的固定微基准周期一致不能替代新的 GEMV 验证。

| 形状 / reuse 口径 | 原 O2 vdot cycles | 原 O2 RVV cycles | RVV/vdot |
| --- | ---: | ---: | ---: |
| 4×13 core | 165.00 | 148.00 | 0.896970× |

在旧 RVV 不变的条件下，4×13 端到端至少要从 209.5 降至 190 cycles，即减少 19.5 cycles/9.31%，才能不落后。该值只是筛选参照；RVV 也优化后须重新计算。

没有把 core 与 endtoend 的周期差线性归因为存储成本，没有把 65 条尾部指令解释为 65 cycles，也没有从本轮静态审查推出缓存缺失率、功耗、Fmax 或整核性能结论。本轮未重解析全部原始运行轨迹；精确动态瓶颈归因仍待后续定向实验。
