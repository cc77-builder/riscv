## 3. 拟提供的入口和接口合同

以下是设计，不表示文件已实现。使用独立文件名和宏命名空间：

| 项目 | 设计 |
| --- | --- |
| 选用头 | include/selected_gemv_c8.h，独立XS_C8_SELECTED_GEMV_H guard |
| 底层头 | include/config_reuse_gemv.h，从合格gemv.h原字节复制，仅改变产物文件名 |
| 默认别名 | xs_c8_gemv_8x32 → config_reuse_gemv_8x32_reuse_vdot |
| 显式RVV别名 | xs_c8_gemv_8x32_rvv → config_reuse_gemv_8x32_reuse_rvv |
| 强制回退 | XS_C8_GEMV_FORCE_RVV=1使默认别名也指向上述RVV；缺省/0使用vdot |
| 版本 | XS_C8_GEMV_API_VERSION=1，另设固定profile字符串；只表示构建合同 |
| 静态库 | libxs_gemv_c8.a，恰好一个完整gemv.o |
| ABI | void entry(const int8_t *packed_ax, void *output_slots)，普通RV64 lp64d C ABI |

开关最终展开只允许字面量0或1；非法数值、空值、表达式和未定义标识须编译失败。新宏不改变旧`XS_GEMV_FORCE_RVV`，旧宏也不改变C8选择。两个头的包含顺序均须测试；不得借用旧头的公共guard。

| 调用前提/效果 | 必须保持 |
| --- | --- |
| 平台 | 已验证的Nexus-AM裸机环境，RV64/lp64d，**VLEN恰好128（vlenb=16）**，VS已启用；vdot路径需当前自定义编码支持 |
| 输入 | INT8有符号行优先A[8][32]，紧接x[32]，共288字节 |
| 输出 | 8个16字节槽，共128字节；每槽低32位INT32点积，高96位零 |
| 内存 | 输入/输出分别16字节对齐、有效且不重叠；输出不能分配为紧密int32_t[8] |
| 状态 | 保持原ABI的栈/被调用者保存寄存器约束；向量及允许的调用者状态会改变 |
| 返回CSR | VL=8、vtype=0（e8/m1/tu/mu）、vstart=0、vcsr=7；不承诺保留调用者向量配置 |
| 责任 | 调用者负责打包、缓冲区生命周期、VS平台初始化；本层不隐式分配、量化、重排或保护CSR |

VLEN限制有具体源码依据：8×32函数使用`vs1r.v`写整个向量寄存器，而行地址固定加16；VLEN256会扩大写入，不能用“支持更大的向量长度”替代此合同。现有C程序在M态设置mstatus.VS，因此不自动授予Linux用户态资格。misa.V、编译器支持RVV或profile常量都不能证明CPU实现了项目的自定义vdot。

强制RVV只改变调用目标，完整库仍包含未调用的vdot函数，也不代表任意RVV机器均可运行。切换版本或宏后，必须完整重编所有相关翻译单元；头文件常量不能检测跨翻译单元遗留的旧对象。

## 5. 证据和工具如何接入

新工具显式接收repo、current identity、矩阵build/run/audit、C8 build/run/audit和新输出目录。个人绝对路径留在执行回执，不写死在公共Makefile中。输出不得覆盖源码、合格输入、旧运行或旧失败。

证据关系必须逐层核实：

current clean身份 → 第25条完整矩阵 → 第26条C8调用 → 当前完整对象 → 新库成员 → 新别名/显式调用者。

不仅检查文件“前后没变”，还要匹配选定的0f/clean-02身份。重新审计原始记录或核验其完整封存输入及审计关系；候选自己写的PASS字段不能成为独立依据。第25条历史ordinary-C=NOT_TESTED保持原文，C8资格从第26条单独关联，不能覆盖旧记录。

可复用的方法：

- `package/verify_package.py`：独立汇编、整对象/单库成员、48次矩阵叶锚、别名/显式caller.o与ld-r完整字节相等、nm未解析、SDK搬移、负控和输入哈希。
- `r2-config-reuse/library.py`：archive_member、consumer_references、byte_check的成员/重定位/叶字节检查方法。
- `r2-select/verify_firstdot_stable.py`：严格宏值、错选择、错误库和调用别名语义检查。

上述工具保持原文。前者仍有firstdot路径、45文件、四形状/八别名等硬编码；后两者的入口绑定旧T17/归档schema。应新增当前C8适配，不替换旧锁，不伪造旧资格文件名，不把旧工具的runtime=false直接改成true。当前C8的`current-matrix-anchor.json`、`current-c-qualification.json`与旧库期待的结构不同。

工具身份同时记录原路径、符号链接文本、解析目标、版本和内容SHA；只对明确列入工具链的链接作此解析。系统gcc/ld为符号链接已在上轮归档遇到，不能简单拒绝全部工具链接，也不能接受身份变化。

## 6. 下一阶段的最小验收

先实现下面这层，**预计新增EMU为0**；只有全部前提满足才能复用运行证据。

1. **当前资格绑定。** 复核0f/EMU/NEMU、完整矩阵及C8源/对象/原文关系；每个输入有角色及哈希。错误硬件、错误矩阵、缺项或混合来源明确拒绝。
2. **真实GNU构建。** 固定rv64gcv/lp64d/mno-relax，沿用实际C8工具；重建对象与完整合格对象相等。ar使用确定性归档，恰好gemv.o；目录、提取字节和完整对象一致，16公共符号及节/重定位保持。
3. **别名等价。** 缺省/显式0/显式1三模式覆盖两个别名；与直接调用预期config_reuse符号的完整caller.o及可重定位链接对象逐字节相同，核对实际未解析符号/重定位。`ld -r`退出0不能代替符号解析检查。
4. **语义负控。** 错别名指向basic或其他尺寸、错RVV选择、错对象/库/身份、重哈希后的错误映射仍须拒绝；另测非法宏、缺头、两种头顺序及新旧开关互不影响。负控只改新输出中的副本。
5. **搬移和回退。** 在脱离仓库的包目录编译/链接示例，证明不依赖仓库相对include。检查RVV回退、原firstdot入口保持和输入前后哈希，保存命令/退出码。仅编译的示例必须标记未执行。
6. **工程留档。** 报告“包/源别名/链接等价通过”，分别列出复用的功能及历史周期资格；不报告新的最终ELF、应用性能或人工验收。形成真实新结果后才追加下一条版本数据档案。

纯宏别名不生成额外ELF函数符号。检查器要证明这一事实及完整调用对象等价，不能仅凭“使用了宏”口头声称零开销。相等对象证明的范围限于所测试调用者和链接步骤。

## 7. 何时需要新的全核运行或性能测试

下列条件超出最小包：新增wrapper/dispatcher、参数检查、CSR保存恢复、混合/裁剪对象、修改编译选项、最终ELF或调用布局变化，或开始使用新的实际应用。

- 如将库重新链接回原C夹具，先比较完整装载映像/BIN、入口、调用表和输入计划。只有逐项相同才可明确复用该原映像的功能结果；单个leaf相等不够。
- 新映像或新运行行为按影响补功能、完整128位/NEMU/O2、故障拒错及恢复、独立重放。不自动授予新应用或Linux用户态资格。
- 需要评估性能时，先限定8×32/dataset0。候选、firstdot及RVV通过相同新增路径，检查/分派/打包成本计入实际比较窗口；保留basic/reuse×vdot/RVV和最快合格RVV分母。
- 可以沿现有两图探针的5进程结构：候选bit100负控、同BIN恢复、firstdot正常、两图独立重放。每图每轮24全部窗口（含首次/预热与16正式窗口），比较的两个新正常图合计32正式窗口。绑定当前硬件与新合同，不转借旧T17。
- 5进程只是可复用的运行编排。现有性能门禁要求唯一直接jal ra＋ret及固定7条调用额外开销，并拒绝额外分支/嵌套调用；若引入wrapper/dispatcher，必须另建实际新控制流的精确解码、退休计数、调用边界检查及负控。不能仅换镜像继续借用旧检查器，也不能用性能探针替代新增普通C应用自身的运行验收。旧门禁原文保留。
- 这5进程只够验证候选相对firstdot/RVV；若声称“集成相对原config-reuse不退化”，还需与集成前路径的合法配对控制。原装载字节/计划不相同时新增控制运行，不能把旧273 cycles当作新路径实测。
- 探针合格后按原三数据集合同扩展。聚合及每组数据严格胜过firstdot和最快同路径RVV，无未解释控制漂移或其他配对退化才考虑采用；不另造比赛百分比门槛。
- 功能/身份失败停止；控制漂移保留INCONCLUSIVE并先归因；收益消失保留原路径和RVV。不为追求PASS重跑择优样本。

不变的生产RTL、NEMU/EMU及配置无需重建；FU、真实父级和PPA不因新增头文件/库归档而重跑。新硬件收益、功耗、整LLM加速和比赛得分均未授予。
