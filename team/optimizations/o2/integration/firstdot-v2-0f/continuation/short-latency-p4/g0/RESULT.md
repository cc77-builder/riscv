# P4-G0 只读评审结果

**结论：有条件 GO，值得进入 P4-G1 的隔离最小实现与局部验证；当前不采用候选，不进入全核。** 这不是新硬件已通过的结论。当前稳定版仍为 **0f（O2两槽＋H1＋DIV取消保持修复）＋firstdot V2＋显式C8 8×32**。

本轮完成三项独立审查：事务协议、映射寄存器/组合路径/旧STA、真实父级验证缺项。唯一候选已收敛；未修改 RTL、未构建全核、未运行新综合/STA、EMU/NEMU，未提交或上传 GitHub。

## 1. 值得试的原因与不能承诺的部分

P2已从当前0f历史12个正式chain256窗口核实：每条VDot接受到响应2拍，响应后到依赖下一条接受5拍，总间隔7拍。内部2拍是能在FU边界内直接针对的部分；其后5拍的逐级解释仍是静态路径模型，不能靠改一个latency字段提前唤醒。

本次选择在接收端组合完成乘法和归约，保存完整结果与身份。既有组合算术模块可复用；两槽仍能成立，不需要改ISA、NEMU语义或DIV接收。主要不确定性是**乘法＋三层加法＋选择器能否在可接受的同约束时序代价内实现**。这只能由后续实际映射/STA回答。

## 4. 固定的代价筛选与验证门槛

赛事现有评分重视正确性、交付完整性、延迟对比及优化论证，没有规定面积上限或1ns门槛。以下是为控制本项目探索代价而预先固定的工程门槛：

- G1先过完整128位算术、两槽协议、异常/身份、真实父级DIV/SQRT/取消门控。
- G2再测同库同工具同约束：FU面积≤18163.158300 μm²（＋5%）、父级≤287461.095460 μm²（＋1%）。
- 五档父级局部时序代理Q=T−最差setup slack增幅≤5%；分别上限3.563697900ns（前四档）、3.583858950ns（20fF）。FU独立Q同样受对应上限约束。Q不是全核时钟或Fmax。
- 输出、ready和门控保护路径逐档增加≤max(旧值×5%,50ps)，完整路径组/新增结果槽计时，不能删路径、改例外或漏约束过线。详细旧值/上限见 [cost-screening-baseline.json](cost-screening-baseline.json)。
- 通过G2才进入全核；后续依赖链目标至少下降10%，single/batch/stream及C8配对均值退化不超过1%，沿用更严格的既有公平比较条件。仍须在目标运行前冻结完整执行合同。

5%代价预算不等于最终可接受5%应用退化。因为batch原本已II=1，即使chain周期改善，真实时钟变慢也可能使其他负载吃亏；最终采用必须同时报告收益与局部成本限制。

## 5. 本轮实际做了什么验证

- 独立抽象事务模型检查320组状态/取消/复位/反压组合，另查连续8笔最早1拍、II1、满槽pop/move/push，PASS。
- 根Agent复制脚本至新输出目录重新运行，协议结果、PPA映射归组/摘录/来源锁与独立审查输出逐字节相等。
- 额外4项抽象模型错误（旧头身份错绑、忽略头取消、满槽误接收、零拍偷响应）均被独立列表oracle拒绝。
- 已核实旧FU/父级测试和全核观察器硬编码两拍；下一轮必须独立适配，不仅改“2”为“1”。
- 默认父级测试未覆盖完整SQRT，后续应选择性复用已有115场景补充内容，重新绑定0f＋P4。真实双lane偏斜采用FP64最小subnormal/9及交换；不拿FP32初始化或C2-G0控制证明冒充动态SQRT算术验证。

**上述Python检查仅证明抽象方案与旧证据提取的一致性，不是RTL仿真、形式等价、真实父级或新时序PASS。** 完整未来验证清单见 [验证审查](reviews/validation.md)。
