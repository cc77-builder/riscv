# P1-R1：隔离计时前准备调用的单次修订设计

状态：**设计候选，尚未实现、构建或运行**。本轮P2只读结论支持做一次有针对性的干预；旧P1保持HOLD。此文件不授予性能升级、扩测或生产默认替换资格。

## 要回答的唯一问题

在相同0f硬件、相同输入/算法/完整计时工作与可核对的地址布局下，仅让计时前的conditioning准备调用使用独立的间接跳转位置，能否消除或缩小被测split_full→leaf调用的预测纠正差异，并通过原1%锚点和逐顺序3%收益门槛？

现有证据支持间接调用控制流纠正与调用到达区间承载差值；没有证明具体预测表污染，也没有保证复制调用点一定有效。全部20个正式split RVV普通窗也发生同一inner调用的纠正；即使隔离有效，RVV分母也可能改善，因此全部对照必须重新测量。本修订首先是测量设计干预，不把它包装成点积硬件提速。

## 最小改动边界

1. 新增只用于窗外conditioning的独立generic完整wrapper，保留与当前split_full一致的普通C传参/保存义务、间接leaf调用和8个INT32结果提取。
2. conditioning继续用原RVV3、原独立输入输出缓冲区、原调用次数及结果消费。只把conditioning的调用位置改到新wrapper；不针对vdot增加预热。
3. 被测packed_full、split_full、全部6对leaf、两层间接调用、计时边界、固定A/每次更新32B x、输出提取和完整128位正确性义务全部保留。
4. 所有12实现共用同一准备规则。禁止只给vdot固定直接调用、却让RVV继续承担间接调用成本。
5. 不修改生产RTL、NEMU语义、硬件配置或默认C8入口。无需重建香山硬件或重做面积/STA。

## 布局与对照先行

- 先尝试将新wrapper放入独立追加段，明确保留原计时链、叶函数、数据、栈、上下文及控制流程的地址和机器码。不能依赖编译器“看起来一样”，必须以最终ELF/PT_LOAD和完整路径审计为准。
- 最理想的有界因果对照是一对布局相同的镜像：两者都含同一新增wrapper，控制版的窗外conditioning仍调用原wrapper，候选版改调独立wrapper；只允许预先列明的窗外调用重定位/选择差异。不要同时调整其它循环、预热、算法或数据。
- 如果无法保持测量链和数据布局，先解决布局或明确设计混杂，不将跨布局周期变化全部归因于调用位置隔离。旧P1镜像与失败原文永久保留。
- 旧P0把历史ledger文件作为live pin的问题应在新身份中明确分离：历史引用绑定归档快照，新实验绑定实际源码/工具/镜像。不要修改旧SOURCE_LOCK或恢复当前档案以凑旧身份通过。

## 暂不采用的改法

把所有12实现改为固定算法wrapper加直接leaf调用可能有应用价值，但改变了P0泛型入口成本，并可能把计时器外层目标从2个扩大为12个。因此不与本次最小干预混做；以后确有一次选型、反复调用的消费者时另立接口合同。

当前也不因本项去改vdot算术流水、唤醒、旁路或DIV门控。首vdot入队到接受以及接受到响应未出现这次慢窗对应的额外差值。
