# P3校准运行器R1宿主修订合同

本轮仅宿主机制验证；目标执行、EMU/NEMU、核构建、RTL改动、GitHub写入均为0。
上轮所有失败、原freeze和代码不修改；本轮独立叶级目录和输出。

修复目标：
1. 每个模块显式引用pc_context.CAL_HERE，禁止通配导入。原始V1错误清单必须被新核验拒绝。
2. 预冻结显式必需文件集合＋全部直接Python源码＋加载依赖＋固定镜像/运行库/支持文件；清单覆盖、文件内容、预算、目录身份全部验证。缺项、根目录漂移、替换/新增代码、hash变化均失败即停。冻结写入排他且加载后二次检查；同名父目录文件不能充当新源码。
3. 触发线程限制时，持久化用于判定的整组PID/PPID/PGID/SID、进程与TID出生ticks、名称、命令、可执行文件、亲和及采样时间。首触发原因不可被清理原因覆盖。保留前序采样；进程组计数包括shell及辅助进程，不排除诊断成本。
4. 冻结上限保持：CPU允许4–7、整组最多4个OS线程、RSS12GiB、日志合计2GiB；负控300秒/正常2400秒，总2700秒，各≤100万guest（原生999984预留16拍），最多2串行，无重试、无自动正式探针。允许仅研究亲和收窄到CPU4这个子集，不增加资源或时限。
5. 宿主夹具可以链接固定Verilator运行时与spikedasm对象，不能链接/运行VSimTop/EMU主程序或NEMU；原诊断命令与可控辅助程序用于机制验证。宿主线程机制PASS不能转授真实目标拒错、应用周期或吞吐。
6. /proc轮询不是原子快照和实时调度；记录采样边界、已消失条目及最坏触发/回收开销。不以本轮夹具证明历史第5线程的身份。
