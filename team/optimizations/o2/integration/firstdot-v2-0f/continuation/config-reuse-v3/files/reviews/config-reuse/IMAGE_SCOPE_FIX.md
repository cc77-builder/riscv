# 配置复用试验 V2 → V3：镜像角色绑定修复

本项只修复验证适配层，没有改变生产 RTL、firstdot/config-reuse 生成器、指令语义、旧门禁源码或性能判据。

## 原失败

V2 的共享文件闭包同时包含历史合格 firstdot 对照 BIN 和当前被运行的 config-reuse BIN。冻结的 team/workloads/vdot-perf/check.py 第301～303行将所有以 /vdot-perf.bin 结尾的键解释为实际加载镜像，因此比较两个本就不同的摘要后报 loaded image mismatch。

原 recovery-config-reuse 目标退出0、UART的24个窗口计算无失败；但验证状态仍是FAILED，不将诊断性原文重放冒充新的正式运行资格。负控已成功拒绝bit100故障。原V2实际2个进程、原回执/日志/UTC均不修改。

## V3 合同

1. 完整外层 runtime-inputs 仍保存对照 BIN 的原路径及SHA；每次目标进程前后均校验完整闭包。
2. 仅在传给单进程执行器的输入映射中移除唯一共享对照 BIN；拒绝缺少/多个对照条目、摘要错误、缺文件和符号链接。
3. 原执行器为当前进程加入其实际加载 BIN；原检查器继续拒绝错误加载镜像。
4. 独立原文审计重新构造完整外层闭包与单进程映射，所有私有BIN/AUX/NEMU及原始日志继续检查。
5. V3使用独立目录重新构建两个镜像，重新实际运行五个进程；V2的两个目标不借作V3合格运行。两次构建的对应BIN摘要必须完全相同，确认修复没有改变候选程序。

V3主机测试61项通过，包括真实原日志的失败重现、临时副本限定修正后24窗原文检查、错误加载镜像仍拒绝，以及对照篡改/缺失/多条目/链接拒绝。首次测试因同一Python进程混入历史与clean仓库的同名模块产生2失败/1错误；随后诊断检查改为独立Python进程，运行适配器未因此修改。两次测试回执均保留。

静态检查、功能检查、性能筛选分别给结论。V3保留原8×32/dataset0、每格4正式样本、双版完整重放、同BIN firstdot对照、未变化RVV控制与其他单元格不明退化拒绝条件；没有放宽到“主项更快就算成功”。
