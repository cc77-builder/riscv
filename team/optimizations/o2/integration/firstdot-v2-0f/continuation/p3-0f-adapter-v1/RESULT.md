## 3. 检查器适配与失败即停

新代码只在本叶目录内。原退休、O2、fatal、DiffTest检查器及上轮策略只读复用，并核对其与固定供体副本相同。
实物0f源的16处观察点已绑定，包括CSR、计数入队、退休、VDot及DIV事件。解析器的真实兼容性来自已存在的C8日志；P3全规模覆盖来自明确标识的合成日志，两者资格分开。

完整退休路径来自**当前冻结ELF的实际机器字及已通过宿主模型**，不是用供体旧地址代替。
ROB压缩不允许吞掉branch/JAL/JALR。全程custom PC顺序必须155521笔完全相同，计时内62208笔还须精确匹配退休cycle、ROB代际/索引和PC。
UART必须完整且只有规定的功能/调用/窗口/结束标记，不能只凭GOOD TRAP判通过。

进程回执要求实际退出码、原始日志哈希、镜像/参考库/冻结身份、单调起止和耗时、guest上限、峰值RSS、线程及亲和采样、进程组清理。
普通退出成功但触发任何硬限不算完成。缺回执先拒绝，不进入昂贵日志分析。
本包只提供离线验证和纯状态机，**没有目标启动函数或可执行的准入令牌**。

22组最终宿主测试全部通过；早期失败包括模块重名、测试代码续行语法、负控末行截断、错误流上的无效变异、源清单定位和EMU_THREADS预期错误。完整日志及源码快照保留，最终负控增加“变异必须实际改变输入”的断言。没有为了通过而放宽原1%/3%规则。

## 5. 为什么预算仍HOLD

唯一复用的本机实际吞吐样本是旧C8正常运行：

- 1527663 guest cycles / 3065.826606单调秒 ≈ **498.287 guest cycles/s**。
- 程序自行打印的host time为2854.350秒，与外层单调计时差211.476606秒；不能把较小值拿来放宽准入。
- 实际编译EMU_THREADS=1；旧运行观察到4个OS线程及CPU4–7亲和，不代表仿真吞吐可以乘4。

按**旧C8速率**作条件情景计算：

| 假定完整guest cycles | 对应秒数 | 7200秒内 |
| --- | ---: | --- |
| 350万 | 7024.058 | 仅余约176秒 |
| 400万 | 8027.495 | 否 |
| 450万 | 9030.931 | 否 |
| 500万 | 10034.368 | 否 |
| 1800万上限 | 36123.726 | 否 |

这张表**不是对P3实际cycles的预测，350万也不是已证明的下界**。
按旧速率，7200秒仅容纳约358.77万guest cycles。P3包含新的量化、FP除法、向量/日志比例、main校验及缓存行为；尚无数据给出其完整周期数、实际吞吐或可靠上界。不能断言一定超时，也不能据现有证据准入。

日志按旧事件密度缩放的点估计约761015503B，低于2GiB，但不是上界；stall/DIV/redirect变化仍会增加量。
最后一次**合成日志离线审计**实际处理293661026B stderr＋802B stdout，耗时 **183.474秒**，峰值RSS **6664052736B（6.206GiB）**。这证明检查器也有明显开销，不能据此线性保证真实日志的时间和内存。
7200秒限额是每个目标正常进程；另有离线校验、哈希和归档成本。三进程的300+7200+7200=14700秒是目标预算总上限，也不是整体完成ETA。

因此结果为 **HOLD_BUDGET_NOT_DEMONSTRATED**，不是“已测性能不合格”。
admission-proof记录 budget_admitted=false、next_role=null，正式三个进程均NOT_STARTED。
