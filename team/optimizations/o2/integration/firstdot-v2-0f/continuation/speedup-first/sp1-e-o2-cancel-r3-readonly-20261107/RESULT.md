# O2补测R3：S0/S1未命中的只读归因与修订设计

**结论：原镜像不重跑。最小软件修订可进入宿主实现阶段（GO）；目标执行与第19项资格仍为HOLD。** 当前没有已证实的新重叠窗口，不能给“下一轮必命中”的承诺。正式进度保持18/20，默认仍是0f＋firstdot V2＋原C8。

本轮没有修改任何软件/RTL/运行器/检查器源码，没有运行EMU或NEMU、构建、EDA、切默认或上传GitHub。只重新分析R2既有完整日志，对照冻结软件、GNU对象和候选源码，并形成设计、合同和预算。本文的新数值均为旧日志的进一步归因，不是新目标测试。

## 1. 已经确定的事实

R2实际正常角色完整结束：607.969222秒、268036 guest cycles，41调用、77条custom退休、81次接受的完整128位结果和源输入/身份/元数据通过；逐调用数值、CSR及FP哨兵通过。S0/S1真实覆盖均NOT_HIT。原FAIL、锁、原始日志与selector结论保留。

- 81次接受全部DIRECT_R，全部在接受后1拍响应；ENQUEUE_P、STALL、KILL_P、PARTIAL_KILL都为0。
- 40对A/B均B.accept=A.accept+1=A.response；B在A出槽的同拍直接替换R，不需要P。
- 1008条STATE的outready均1。观察器在P/R有效、父级输入/取消等活动期间逐拍打印，所以能够排除这些有效R期间的反压；它不记录所有空闲周期，不能据此说整次运行每一拍ready都为1。
- 40个A从ROB ENQUEUE到FU ACCEPT相隔38～44拍。这是端到端等待，不等于某次load或某个FU自身延迟。
- 四次真正S1 probe的B虽然被接受，却都已先响应再被ROB取消，不能代替“B仍在P时被杀”。

## 3. 为何没有反压、没有P入队

### 3.1 接收速度不等于双槽占用

一拍候选满足 `rReady = !liveR || out.ready`、`directR = in.fire && !liveP && rReady`。P空、R可当拍出队时，新B必走DIRECT_R。要让B入P，至少要先有A在R且下游不ready，并让B在此时接受。实际40对恰好相反：R的81个有效响应机会都ready，没有积压。

### 3.2 写回竞争通路确实存在，但压力没有在A/B有效期生效

冻结Parameters与真实SP1-C构建日志一致：FEX0/F2v和VFEX4共用Vf/V0写回口3，前者priority0、后者priority1。RealWBArbiter在两者有效时优先前者。`vfmv.v.f`在LMUL1下拆成F2v写内部临时寄存器以及后续VFALU两段；8条架构指令不是8条VDot指令，也不是已测连续8拍反压。

更直接的问题是：`fmv.x.w`解码为FCVT，而FCVT和F2v都只有FEX0入口（构建日志明确二者needSingleIQ）。旧程序先排8条F2v，再排释放VDot输入的`fmv.x.w`，然后走andi、地址add、v8重载。它把压力生产者和VDot释放器放在同一发射通路上，又在释放路径尾部加入访存。

IssueQueue使用分区年龄选择与已入队优先规则；若旧F2v已就绪，它们通常先于更年轻的FCVT被选择。但由于缺动态FEX0 grant，不能把“8条一定全部先发射”写成已证时序。可确定的是：旧依赖设计没有独立、及时地释放VDot输入；实测有效R期间也没有竞争。压力排空是与源码及日志一致的首要解释，精确排空拍、VTYPE/加载/调度各占几拍仍未观察。

e32→e8是不同指令携带的向量配置，不能无证据地称为全核串行屏障。当前实际EMU为MinimalConfig，不是无D-cache的MinimalSimConfig；不把38～44拍归因成一个臆定的固定访存延迟。

## 4. 为何取消也错过窗口

旧S1为`ft0→fmv→t6地址`后分叉：一支`vle8 v8→A/B`，另一支`sub(t6-a0)→add分子→64位divu→branch`。第二支只依赖地址，不依赖v8加载值，更不依赖A接受。因此源码把divu写在A之后，不能保证它在A接受之后才开始。

实际VFEX4取消分别比A响应晚40、8、8、8拍，比B响应晚39、7、7、7拍。旧操作数的SRT16迭代数可由前导零算出，但这不是相对A的全核延迟；3个短间隔也不证明除法被缓存或降成了短迭代。没有scalar DIV发射和branch PC动态日志，不能再细分这些差异。

取消B留A要求：B已真实入P，下一拍P=B/R=A，并且实际VFEX4 flush到达时仍为该分配；允许A在取消同拍响应，B禁止响应/退休。当前连前置反压都未成立，单独更改phase或延长DIV不可能补齐S0。

## 5. 最小修订的取舍

详见DESIGN_CONTRACT.md：先将FMV移到8条压力之前，再用e8零增量的vadd.vx保持完整v8值并引入真实RAW，移除重复加载；S1将原数值除法前置，利用已知零位将它真实串到FP生产者之前，取消窗口内只留短整数依赖与原4档phase。保持41调用/77退休、320条架构F2v、原数据和完整输出、CSR/ABI合同。

这是可检验的机制修订，不是已测的新时序结论。八个高优先级写回机会与缩短的释放路径构成一个有根据的候选窗口，但其连续性、前后端排队与跨调度器唤醒未被观测证明。因此**GO只给最小软件宿主实现；当前目标HOLD，不能重复旧镜像，也不能直接补重放或进入第20项**。
