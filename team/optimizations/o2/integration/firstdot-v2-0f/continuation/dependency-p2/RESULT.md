# P2：依赖链瓶颈只读归因

**结论：值得做一次限定于VDot内部短延迟的P4-G0可行性评审，但当前不批准功能RTL实现。**
本轮没有发现可直接删除的“多余父级寄存器”或错误latency配置。
稳定版本保持 **0f（O2两槽＋H1＋DIV取消修复）＋firstdot V2＋显式C8**；P1-R1仍HOLD。
本轮新增EMU/NEMU、硬件构建、综合和STA均为0，未提交、未推送GitHub。

## 1. 实测依赖链分解

复用0f同镜像周期回归的3个数据集、12个正式chain256窗口（首次/预热另保留），
共3072条vdot、3060条相邻依赖边。398份生产源码与当前工作树相同；
当前保留的原EMU SHA256仍为2d1db77cc407486a2387a4a69da2498b68d44980239025eebcc02370c02826e8。

| 区间 | 所有正式样本 | 证据性质 |
| --- | ---: | --- |
| ACCEPT → MOVE（乘积槽转结果槽） | 1拍 × 3072 | 原始事件直接测量 |
| MOVE → RESPONSE（输出握手） | 1拍 × 3072 | 原始事件直接测量 |
| ACCEPT → RESPONSE | 2拍 × 3072 | 原始事件直接测量 |
| RESPONSE → 下一依赖ACCEPT | 5拍 × 3060 | 原始事件直接测量；聚合区间 |
| 相邻依赖ACCEPT间隔 | 7拍 × 3060 | 原始事件直接测量 |
| 每个完整chain256窗口 | 1857 cycles × 12 | 原CSR窗口；含首尾/循环开销 |

全部12窗严格满足：

~~~text
1857 = 起始37 + 255个依赖间隔×7 + 最后一条FU延迟2 + 尾部33
~~~

这不是1857/256等于FU延迟。链为 v10 ← dot(v10,v9)，每轮把前次低32位结果的字节重新解释为signed int8，
高96位清零；包含标量循环控制。独立复算完整128位结果，前次RESPONSE数据与下次ACCEPT的vs1逐位相等。
seq、ROB代次、pdest、父级同拍接收、退休PC/word及CSR/UART边界均绑定；未用邻近行猜配。

消费者在前次RESPONSE前4～35拍已分配ROB。但 **O2_ENQUEUE是ROB allocation，不是IQ入队**；
不能证明当时已驻留目标IQ、其他源已就绪，也不能排除所有dispatch停顿。
O2_COMMIT/T13_RETIRE是架构退休，不能当作写回；没有直接的WB/wakeup/select/bypass日志。

## 2. 五拍如何理解

同版RTL的正常无冲突路径是：WB唤醒更新IQ源状态 → IQ选择与deqDelay →
DataPath OG0/OG1 → 向量OG2 → VFEX4前输入流水。
该结构能解释观测到的五拍，但逐段时刻是**源码静态模型**，不是新增五个硬件观察点的测量。
前提包括消费者已经驻留IQ、其他源ready、无RF仲裁、取消或反压冲突。

FU响应到父级输出及向量WB仲裁为组合连接。在正常合法vdot且握手满足的条件下，
RESPONSE与写回接受同拍是源码推导；本轮没有独立WB日志直接证实该等式。
因此不能建议“删掉父级一拍输出寄存器”：这条路径上没有这样的寄存器。

VFEX4与DIV共享，不确定时延配置符合实际弹性协议；当前配置也没有把VFEX4列为IQ提前唤醒源/接收者。
只修改CertainLatency、piped或latency数字不会自动缩短实际流水，还可能破坏预约、背压和身份对齐。
2拍内没有观测到延后输出，因此增加槽深、继续优化吞吐II或修改DIV关钟没有本次链数据支持。

完整源文件行号、条件与SHA见[RTL审查](reviews/rtl.md)；不能把这五拍全部命名为“无用等待”。

## 3. Jade能说明什么

固定Jade a17e38128e589d745152f3ef4b595b4572b22b3d及10月17日统一批次，
复算Jade chain256均值1601.25、同批T14均值1857。Jade正式退休间隔主峰6拍（3030/3060），T14主峰7拍（3036/3060）。
Jade走VIAluFix/CertainLatency(1)，当前走VFEX4不确定时延两槽路径。

Jade只记录退休/CSR，没有ACCEPT/RESPONSE/WB；并存在同周期成组退休。
所以“退休间隔峰6拍”不是“FU执行6拍”，也不能证明历史差值全部来自某一个算术级。
当前0f的1857与历史T14数值相等，不使两次实验变成新同批对照。
Jade的异常合法域、反压/取消合同与本项目不同，且没有同约束PPA，不能直接移植或用其结果保证本项目收益。

## 5. 条件收益模型与成本

仅假设FU2→1、其他路径/首尾开销保持：

~~~text
37 + 255×6 + 1 + 33 = 1601 cycles
~~~

模型相对当前chain256少256 cycles（13.7857%），约1.1599倍；
**这不是新跑分、保证收益、普通C/GEMV收益或已采用版本**。
若只是假设后端五拍缩为四拍且FU仍两拍，模型是1602，不能混成1601。
若时钟周期增加约15.99%，第一种模型的物理执行时间收益就会抵消；
没有整核Fmax实测，不能用局部STA冒充整核频率。

| 三项主指标 | 保留的0f证据 | 本轮性质 |
| --- | --- | --- |
| chain256加速比 | 5440.5 / 1857 = 2.929725× | 旧合格周期复算；无新跑分 |
| 面积 | FU 17298.246 / 父级284614.946 μm² | 沿用历史综合，父级含FU，不相加 |
| 参考时序 | FU i2r1.190323/r2r1.163404ns；父级VDot r2r1.356106/r2o2.776701ns | 沿用布局前STA，无新测量 |
| 最差已报告slack | FU −0.268520 / 父级 −2.393998ns | 1ns参考未收敛，不隐去负值 |

条件为Nangate45 typical/25°C/1.1V、1ns/5fF。不能把旧两段arrival相加当作融合后的STA。
P4-G0必须在候选测试前固定面积/时序允许代价、完整父级比较与五档约束、停止条件；
保持两槽、II=1、完整128位、异常、反压、取消、DIV切换与真实门控合同。明显不划算就停止。
