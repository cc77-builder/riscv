## 问题、实现与身份

现有普通 C 消费者拥有分离的 A[256] 和 x[32]，旧两参数 leaf 要求 A||x，
因此每次完整调用先复制288B。本轮新增 `(A,x,slots)` 三参数 leaf 与
`split_full()`：直接读取分离输入，写出八个完整128位槽，再提取八个INT32。
vdot 和全部五类合格 RVV 都采用同一新接口，双方同时省去复制。

六组新旧叶函数长度相同；独立机器字证书遍历完整函数，仅允许参数保存的
两个搬移及 X 的基址/偏移变化，算术、CSR、存储机器字必须与冻结的原函数一致。
实际最终 ELF 另验证 VL/EEW 读足迹、128B槽/32B y 写覆盖、完整调用路径与
split 不读取/写入旧 packed 区。函数指针保持正确的三参数 C 类型。

## 完整调用性能：接口采用

一个 ELF 同时链接新旧六类算法。每数据集六轮，首轮与预热单列，四轮正式；
偶数轮正序、奇数轮反序。每轮前后有共同 split-vdot 锚点，每窗前同样执行
一次 split/firstdot RVV conditioning，并完整重置输入/输出/CSR。
计时记录行在矩阵结束后输出，窗口之间没有 UART。

共252窗：普通方法216窗，其中144正式窗；锚点36窗，其中24正式窗。
下表每行新旧各12个正式窗口（3数据集×4轮），单位为合同计数器周期差值。
周期包含 C 包装、间接叶调用、INT32 提取和相同计数器协议的固定开销，
旧接口还包含288B打包；没有扣除估算开销。初始化、conditioning及检查在窗外。

|---|---:|---:|---:|---:|---:|
| config-reuse / reuse vdot | 14,515 | 3,702 | 1209.583333 | 308.500000 | 74.495350% |
| S0 / basic RVV | 17,188 | 6,358 | 1432.333333 | 529.833333 | 63.009076% |
| S0 / reuse RVV | 15,507 | 4,635 | 1292.250000 | 386.250000 | 70.110273% |
| config-reuse / basic RVV | 15,818 | 4,781 | 1318.166667 | 398.416667 | 69.774940% |

采用门槛在 v2 首次构建前固定：六组各自总周期至少减少5%，且每数据集
四窗总周期不退化超过1%。判定用整数交叉乘法，展示百分比不参与门槛判断。
保留五类不同机器码 RVV，没有挑选较慢的 RVV 对照。

## 失败证据与框架预算修正

第一次 GNU 构建将 `split.c` 与 `split.S` 同时映射到 `split.o`，链接失败；
新叶汇编改名为 `kernels.S` 后重新构建。失败的 `build-01` 原样保留。
`build-02` 静态通过但未运行；门槛改为精确整数边界后使用 `build-03` 开始 v1。

v1 的实际高位负控通过，恢复输出84功能调用/6控制通过，但3,000,000拍预算
耗尽时仅完成51/252窗，最后一个结束于2,985,533拍。EMU本身退出码0，
团队验收器仍正确拒绝 `EXCEEDING CYCLE/INSTR LIMIT`，没有启动重放。
这次不完整运行没有性能取舍结论，其部分窗口没有混入 v2。

v2 在独立 `source-v2` 建立新身份：只优化窗外准备/检查，独立 C golden
一次预计算；真实 union 的对齐64位成员覆盖所有输入与packed字节，
全部槽、高96位、y、guard和CSR仍逐调用检查，没有校验和或抽样。
每次仍重置实际缓冲区，reference只按数据集/布局缓存。
算法、包装、计时协议、84功能、252窗、次序、conditioning、门槛及3m上限
都不变。链接布局已变化，因此 v2 单独执行负控、恢复和重放。

## 适用边界与路线决定

收益只适用于本合同的8×32分离输入、每次完整调用都要打包的消费者与固定平台。
输入原本已经连续、可复用打包、A固定只更新x，或改用其他memcpy/向量化打包时，
须按实际成本重新比较。该基线是冻结选项下已合格的 hoisted C 包装，
没有证明优于所有可能的打包实现。两个非对齐/地址顺序互换布局用于正确性；
性能仅采用合同指定的对齐、非相邻 X-before-A 布局。

采用这项可选接口，在本合同调用计划内推荐 `split_gemv_8x32_vdot`，并保留全部五个显式RVV入口。回退可切换同ABI的RVV，或恢复旧packed context/workspace/两参数入口，不能强转函数指针。无需重跑本合同或既有hoisted矩阵。后续先接入具体消费者，核实A/x生命周期、实际打包频率与调用序列，再判断应用收益；不凭这组数字扩大尺寸或直接切换R5默认。

本轮是 Agent 同机验收及封存原文复算，不是人工 ACK、新机器安装复现、
所有矩阵形状或完整 LLM 性能。保留更快的合格 RVV、全部原始及失败证据；
没有赛事报告、PPT、部署或赛事提交。
