# 8×32 普通 C caller：指针缓存与五类 RVV 的完整窗口筛选

操作：`20261025-LiZufan001-r2s3-hoisted-0326`，@LiZufan001 / Pro 主 Agent 实现，独立 Agent 只读审查。实验源码基点 `2329b79610d25d2f242391847ecd5b70e1bbace9`；本文件随成果提交，承载提交由 Git 历史定位。实际运行定位与接续见 [handoff.json](evidence/handoff.json)。

## 1. 结论与采用范围

**指针缓存包装的匹配基线收益成立；强RVV集合的最终采用决策为 `HOLD_CONTEXT_VARIATION`。** vdot与索引4/RVV的完整调用分别比本轮原caller对照少9.983807%和9.694339%周期，达到事前第一阶段门槛。全部六个案例完成正确性、负控、正常恢复和独立重放；但共同vdot的跨镜像锚点在三个数据集均超过1%门槛，`selected_method=null`，不发布最优内核选择。

本轮保留具有上述限定运行证据的可选 `caller_full` 源码和完整筛选结果。最低观测RVV是firstdot/reuse，不能仅以config-reuse/reuse作为分母宣称已击败最强对照；也不能将HOLD称为正确性失败。

R5/G5 默认和现有公共库保持原身份。这里交付的是固定 8×32、三组原数据、普通 C workspace 接口的独立可选实现；不把这组结果扩展为完整 LLM、任意新布局、其他尺寸、全局最优、硬件提频或 ASIC PPA 收益。

## 2. 为什么重新建立基线

[上一轮 caller](../RESULT.md) 的完整窗口只比当时选定的同路径 RVV 少约1%，独立 pack 诊断约1102周期。本轮据此检验一个局部假设：在完整调用内先缓存 context 的指针字段，减少逐字节循环中的重复访问。沿用原 hoisted C 草稿，保持逐字节打包、完整 leaf 调用及结果提取；没有增加 restrict、字宽搬运、向量打包、额外对齐或新编译选项。

本轮不再执行 pack/core/extract 独立诊断窗。由于删除这些窗口会改变执行上下文，不能直接拿旧144窗结果作性能分母。因此重建并实跑 `b4`：原 caller C、同一36窗计划、同一完整 RVV 链接集合、同一选择器，再与 `h4` 配对。两者的代码大小和链接布局差异属于候选软件整体，不将全部周期变化唯一归因于某类 load。

采用前置包含 context 与所有写区分离、字段在调用期间稳定，以及 A/x/y/workspace 有效且互不重叠。`entry` 只能指向符合该8×32/完整128位槽合同的合格 leaf，不能据此把任意函数或任意别名布局纳入资格。

[SCREEN_CONTRACT.md](SCREEN_CONTRACT.md) 在首个新构建前固定两阶段门槛。先要求 vdot 与索引4/RVV 各自的12个正式 full 总周期均下降至少5%，且每数据集不得退化超过1%；通过后才运行其余四类 RVV。第一阶段不通过则停止，不增加候选或采样来追逐结果。

### 4.1 事后时序观察：定位差异区间，不重定义门槛

在完整原文审计后，对每个正式full/vdot窗的32条真实退休指令，用完整ROB分配代、PC、seq和pdest关联接受/响应事件，再以已校验的cycle采样tick表示相对位置。六个案例的12个正式vdot窗均可提取，正常与重放的观察逐项一致，无事务越出计数窗；这些已退休事务的接受到响应全部为2拍。

| b4 | 16056 | 13417 | 1428 | 1211 |

“首接受”只考虑本窗口实际退休的32条vdot，不包含被取消的投机事务。这些区间来自同一full窗内的事件坐标，不是独立pack/core/extract测量；首接受前也包含其他准备、调用与leaf前缀工作。它们支持继续查看首接受前的执行上下文，但不能单独归因为缓存、分支预测器或某一条load，不能扣除差异后重新宣称通过HOLD。

## 5. 正确性与证据闭合

六个新GNU构建与事前布局/输入检查通过；先完成b4/h4，再按已固定条件扩大到四个其他RVV类。**实际新增EMU18次：6次预期故障负控、6次同BIN正常恢复、6次独立正常重放。** 六个主正常进程合计216个full窗口、144个正式窗口；另外216个重放窗口逐项一致，未重复计入统计。

事前9项绑定/路径拒错通过；b4/h4各完成7项含真实日志的拒错检查，其中共享的旧静态检查不重复计作新的独立类型。每个案例均重新验证真实vd0 bit100故障被捕获，再用未注入的正常参考恢复；不是借用旧镜像的负控。

六个案例分别完成原文审计、压缩封存和解包重算。随后整组在新临时目录中恢复全部载荷，再次重算六案例、9项绑定拒错、b4/h4日志拒错、跨镜像布局、两阶段门槛和最终HOLD；结果为 `HOISTED_MATRIX_RECHECK_PASS`，新增EMU为0。

每正常进程36个 full 窗口、24个正式窗口；实际 vdot 提交672次＝18个 full/vdot 调用×32＋3个原栈例×32。完整128位输出槽、输入/边界/CSR、实际 counter/ROB 和精确退休路径均由冻结团队检查器复验。原 `demo.c::gemv8` 是另一个直接调用 config-reuse/vdot 的栈打包实现，不调用新 `caller_full`；其三个例子的正确性不能替代新包装的性能或栈布局资格。

新增的 v2 适配器只装配本合同的窗口和实际 ELF 选择数据；16个原公共 leaf、原参考对象和额外三类 RVV 的完整函数机器码都绑定合格来源。原路径检查器内部的 reuse/RVV 调用计数字段保留历史名称，但其查找对象已绑定所选函数的实际地址和完整字节，`selected_rvv_symbol` 与生成 manifest 明确记录真实目标。没有依据 DUT 日志反推期望路径。

原团队源码、合同、判定器和官方程序均未改写。新 `checks.py` 是事前固定的外部分析身份；没有事后把它塞进旧构建输入。新 `recheck.py` 只处理交付复算，不参与实际仿真输入。

本轮新运行资格覆盖 `caller_full`；保留源码的 `caller_pack/core/extract` 没有获得新的独立运行或周期资格。三段时序观察若能从原文提取，也不能替代这三个独立诊断入口的测量。

## 7. 使用、回退与接续

保持 R5/G5 稳定默认，不建立新的自动方法分派。要使用本轮可选包装，调用者显式设置 `caller_context.entry`，遵守已验证接口与平台前置，并保留父目录原caller回退。当前没有取得“对全部五类RVV的最优选择”资格；最低观测行不自动成为默认。

本有界筛选到此关闭，输入不变时直接复算已交付原文，不重复18次EMU。后续优先取得真实消费者的布局与调用序列，评估减少重复打包/搬运的具体假设，同时给RVV等同优化；若继续研究上下文，应先定义能约束前序调用影响的新合同，再开展新身份实验，不能事后调整本次门槛。

接口、头文件/公共库依赖、单份实现链接规则及平台前置见 [README](README.md#使用与回退边界)。回退时选择父目录原 `caller.c` 重新编译，保留本目录源码和证据。稳定应用仍可直接使用 [R5/G5](../../../r2-select/STABLE.md)。新的调用布局、编译条件、硬件或真实应用均按变化影响验证；本轮结果不要求重复现有 EMU。
