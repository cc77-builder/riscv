# R2-S3：8×32 C 指针局部缓存候选 v1

合同 `r2-s3-caller-hoisted-8x32-v1`；仅改普通消费者的标量 C 实现，固定公共 leaf、RTL、计时与判定合同不变。

基线明确为 `r2-s3-caller-8x32-v2`，沿用其 `CW seq cycles instructions` 输出和300万拍资源上限。本候选的v1是独立版本号，与未通过完整运行链的caller-v1无关；只与合格caller-v2比较性能。

## 有界修改

在完整调用窗内把 A、x、workspace、y、entry 字段读取到局部变量，再执行与原消费者相同的逐字节打包、内核调用和提取。阶段诊断也使用对应的局部变量版本。没有新增 restrict、对齐前置、字宽访问、memcpy、向量打包、编译优化选项或形状。

接口要求延续非重叠且有效的 A[256]、x[32]、y[8] 与464字节workspace；明确 context 记录不与任何写区重叠，调用期间其指针字段稳定。捕获指针及所需寄存器保存/恢复全部计入 full，不在窗口外准备。双方使用同一个消费者，只改变已经合格的 vdot/RVV 入口；优化后的 RVV 必须一起重新实测。

## 复用与身份

`candidate.py` 只在独立 Python 进程中装配本候选：逐字节核对原消费者8个合同源文件，复用其生成/构建/计时/路径/运行/检查函数；只替换生成目录中的 `caller.c`，增加本候选3个源码文件和两个辅助检查/归档程序的冻结快照及单独合同标识。原 caller 源文件、原产物和原运行不修改，不继承原运行 PASS。

全部16个公共 leaf 和完整参考对象仍逐字节固定。独立路径必须按新 ELF 重新计算，三组输入、144窗口、96正式窗口、首次/预热/AB/BA规则、全128位槽/输入/边界/CSR检查不变。同一新 BIN 进行实际首条vdot高位负控、正常恢复和独立重放；性能EMU串行。

## 判断与解释

回答两个问题：新完整消费者相对原消费者是否更快；在新消费者内，vdot是否胜过最快合格的同轮RVV。旧消费者证据保留可回退。不同ELF布局属于整体候选差异，不能把全部周期差精确归因于删除某种load；pack/core/extract仍是不可相加的独立诊断。

只有 full 实测改善、正确性和重放通过才接受候选。未改变R5默认，也不扩大到完整LLM、其他形状、新RTL或ASIC PPA。
