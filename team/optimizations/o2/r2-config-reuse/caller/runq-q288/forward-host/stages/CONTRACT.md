# 完整 forward 阶段边界与 RoPE 复用候选 v1

身份 `r2-s3-runq-forward-stages-v1`，基点 `b1d3f136dafae81cf76d2c1f35079cb1465ce7af`。
这是独立团队适配器，不改变原样上游、旧 observer、active、任何冻结合同或 R5。

## 问题、假设和事前边界

当前目标结果只覆盖 FP32→QKV，不能提供完整 forward 阶段份额。先建立可实际执行、可检查的完整阶段边界。独立候选仅把同一 token 的 24 对 RoPE 角度计算一次，在六层/六头复用；使用原 binary32 表达式和同一 libm，192 B 角度表只在当前调用的栈上存活，准备时间包含在完整调用中。不缓存前一位置，不改量化、矩阵算法、累加顺序、KV、attention 或 classifier。

模型沿用 D288/H768/L6/heads6/kvheads6/V32000/seq256/GS32、固定未训练权重和种子。前三 token 为 `[1,7,19]`，位置连续从 0 开始；扩展功能检查使用明确的确定性 token 序列，最多到位置 255，不用于模型质量评价。此处矩阵均为原 scalar `matmul`，没有把 TA/FR 有限模型的宿主耗时混入计时，也没有目标 vdot/RVV 对比资格。

原 `runq.c` SHA256 必须是 `ba9cc681afca79f994f815dfeffc4a61c5b3ca8c5d4d4dcb75c8d375856ba548`；原 observer SHA256 必须是 `92bd2986e8bca35dc2ed30d0338eac2a0c96ef6a54d766835c793ad6fb9e8236`。只复用其固定模型构造，不启动原 observer，不启用函数 instrumentation。生成器去掉准确的标记并恢复函数名/量化调用后，完整 baseline 正文与原 forward 相同；candidate 只允许两段明确 RoPE 变换和局部表声明。

## 完整功能验证

原 forward、带阶段标记的原算法、无标记候选、带阶段标记候选分别推进独立 RunState。所有 16 类可写缓冲范围互不重叠；每一位置逐字节比较全部缓冲，而不只 logits。每次 forward 仅当前位置的 KV 行可变；所有权重和 embedding 保持原字节。验证构建在生成的三路每次量化前检查全部组的有限值/正尺度/定义良好的 int8 转换，原 forward 在已验证同输入的 baseline 之后执行。新位置若触发域外，保留失败并停止，不改参考。

完整正常序列通过后，再在独立进程执行有针对性的破坏：丢阶段、错层标签、错角度、历史 KV 改写、状态别名。均须在对应检查上失败；不能用任意崩溃代替拒错。单个工作进程最多一核。ASan/UBSan 若可用，只用于实际内存/转换风险检查，不能当作目标验证。

## 阶段与计时

固定容量的内存记录器保存 120 个边界、119 个半开区间：embedding、RoPE 准备、每层 19 段、末尾 norm/quantize/classifier。连续时间戳相减必须严格闭合到首末标记跨度；外侧完整函数调用单独计时，首末标记外的入口/返回费用单列。计时体内不输出日志、不进行完整比较、不调用 Python 或解释器。

验证构建的时间戳含量化检查开销，不可用于性能。独立 timing 构建取消全部量化检查，以宿主 `CLOCK_PROCESS_CPUTIME_ID` 纳秒只检查测量接口，保留原始观测与系统/编译/库身份。不扣除估算标记费用，不把两份链接布局当作机制净因果对照，不按宿主阶段份额选择香山优化，不设置或发布目标加速比。正式目标性能仍须同一新最终 ELF、完整消费者、合格强 RVV、预热/顺序/重复规则和新合同。

## 停止与目标依赖

本轮停止条件是完整功能/阶段闭合及真实破坏检查完成、或发现定义域/等价失败。目标通道不可用时，不扩展微基准、不重建 EMU。目标完整 forward 另需数学库实际链接闭包（编译器可能产生 `sincosf`）、状态分配/初始化、输出适配、内存预算与原样 DiffTest。当前 AM 只提供 AM/klib，不能把宿主成功写成 target-ready。

记录 PASS、BLOCKED 与 NOT_TESTED：本候选宿主合格不表示目标收益；R5、旧 TA/FR、旧 HOLD 与原始/失败证据保持。主 Agent 负责实现，独立 Agent 只读审查。
