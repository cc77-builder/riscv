# 六层 RoPE 合并边界的目标判定实验 v1

身份 `r2-s3-rope-stage-v1`。本实验只测给定位置的六层 Q/K 旋转紧密串联、自预热后的成本；不是六层交错于完整 forward 中的缓存环境，也不授予完整 token 性能或最快通用非缓存实现资格。

## 输入与源码

沿用原样 runq、D288/H768/L6/heads6/kv6/GS32/V32000/S256 及种子 `0x53485041`。连续执行 p0…255，tokens 前三项 `[1,7,19]`，后续 `(p*7919+17)%32000`。从经过完整原文恢复证明的 traced 原算法，在各层 `rope` 与 `kv_write` 边界立即保存 pre/post Q/K；捕获路径每位置的全部16个状态span必须与独立原样 forward 相同。只抽取位置 `[0,1,2,31,127,255]`，每侧各82,944 B；不从末层状态或逆旋转重建早期输入。

目标本轮只执行已固定的 **p2**，每次完整处理六层各288个Q和K，共13,824 B。独立裁出的原RoPE循环必须逐字等于固定原文；缓存函数仅把相同角度式移到六层循环前，每次准备24对FP32数组，逻辑192 B；删除准备、恢复角度式后循环等式成立。

两种方法同一ELF、同一完整输入、同一工作缓冲地址与对齐、同一编译与静态libm政策。沿用完整目标消费者的 freestanding/no-builtin、禁fast-math/FMA收缩、禁向量化和跨过程特化；实际调用与最终反汇编保存。该政策不会自动获得允许builtin/sincos合并的更强非缓存基线资格。

## 一个进程的工作

固定样本顺序原、缓存、缓存、原（ABBA）。每个样本先恢复pre-RoPE原始字节，执行同方法完整自预热，再次恢复原字节、清完整fcsr并设置errno sentinel，然后读cycle/instret、调用完整方法、再次读counter并立即保存fcsr。每个counter读取的两侧均用 `fence rw,rw`，沿用既有目标测量包装，使前序输入恢复及最终输出store按同一规则排空。缓存准备和调用开销在窗口内，输入恢复、完整逐位比较、guard、摘要和UART都在外。counter与fence成本保留，不扣估值。全部输出逐位与宿主post-RoPE比较；外部另核对固定FNV-1a64摘要和完整fcsr，摘要不冒充逐字节导出。全部原/缓存fcsr相同，固定输入要求仅NX置位且FRM=RNE，errno与TLS/数据guard保持。

应用负控只在首个缓存正式样本计算完成后翻转输出首字节bit0，要求完整比较器报告指定位置并以91退出；它不是官方DiffTest架构差异注入。正常DiffTest、应用负控、负控后的原镜像恢复及独立重放均须完成。三个正常进程的原始样本、摘要、flags、目标counter必须完全重现。

## 有界运行与解释

固定T17 EMU、NEMU、AM、klib、flash及实际硬件profile，官方依赖保持原样。每进程最多6,000,000目标周期、7,200秒外部超时，输出单文件上限128MiB。允许独立进程在不同宿主CPU上最多三路运行，输入只读、目录/PID/状态隔离；恢复只在负控退出并验证后启动。比较的是同一模拟时钟域的架构cycle计数，不能采用宿主耗时；若并行重放的counter不能严格重现，则本合同不授予周期资格。总CPU预算不超过四核。

仅在所有功能、原始差分输出、负控、恢复、重放、输入身份与进程清理门槛通过后，报告p2这个热边界的两个原样本、两个缓存样本及局部差值。不按六层再次放大，不把宿主约0.2%的占比迁移到香山。此实验用于判断后续投入；强FR、R5默认和已冻结消费者保持。
