# 首 token 目标正确性资源合同 v1

对应 `r2-s3-w2-norm-first-token-v1`，资源身份
`r2-s3-w2-norm-first-token-resources-v1`。这是本入口的首次完整目标实验。

每个独立进程固定原 T17 EMU、原 NEMU/flash、seed=1、RAM=128MiB、
`--log-end=0`；原裸 O2/T13 输出、UART、DiffTest 保持。四个独立案例为
真实 TA 最后 logit 负控、FR-cache、TA-cache、TA-cache replay。必须先完成
精确新镜像的四例原参考资格，包括真实 code94 BAD trap，才生成本 profile。

每例上限固定：40,000,000 guest cycles、28,800 秒墙钟、每条原始输出流
4 GiB。总共仅四次 EMU，最多四个指定 CPU，独立镜像、cwd、文件、进程组。
本轮采用四独立案例并行；首 token 负控同样执行完整消费者，参考负控已先行
验证，最终 campaign 必须等到目标负控和三个正控全通过才授正确性资格。

预算依据是实测新参考完整调用：TA 正控含完整比较约 13.82M 退休指令，
窗口内约 10.12M；FR 正控约 11.20M，窗口内约 7.50M。这些不是目标周期
预测。旧 300k 目标探测仅有约 56.6MB stderr，无法证明完整耗时。此一次
显式预算为完整调用及慢速原观察器留出空间，同时以原始日志上限限制存储。
所有实际退出耗时和日志大小必须报告；不自动追加预算，不因输出量去掉门禁。

`run.py --freeze` 在任何本实验 EMU 前保存实际 ELF/对象/工具/模型/源码/
参考完整证据/物理配置及运行参数的摘要。运行前后逐项核对，输入不可变。
超时、cycle-limit、日志上限、进程残留或 raw 审计失败都保留真实失败结果。

仿真过程只使用四个指定 CPU；其他工程压缩/复核若并行，须限制在同一总四核
预算内。这里无公平性能采样合同，`performance_qualified=false` 永久保留；
各独立 guest 的计数器仅作为此完整正确性链的观测数据。旧 norm 和 W2 的
性能 HOLD 不因本实验而改变。
