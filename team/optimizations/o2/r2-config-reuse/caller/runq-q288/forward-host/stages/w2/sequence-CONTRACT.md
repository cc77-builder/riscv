# 完整支持序列的参考正确性补充 v1

身份 `r2-s3-forward-consumer-w2-sequence-v1`。本补充检验已合格且不变的 `consumer-w2.o` 在接口完整位置域 p0..255 的行为；不改变内核、consumer、旧合同、旧工具或官方 AM/NEMU，不运行新的 EMU，不取得目标性能或训练质量资格。

## 输入、比较与接口

同一固定未训练 D288/H768/L6/HQ6/HKV6/V32000/S256/GS32 模型、五份 immutable 模型数据、RNE。三个独立 state 使用原 scalar、FR-cache、TA-cache，同进程按每位置依次运行，token 前三项为 1/7/19，之后为 `(position*7919+1)%32000`。先用原独立 host 的三份全部 3,691,424B 状态核对 scalar 的前三位置，再在每个位置将两种向量方法的全部状态逐字节等价比较原 scalar，包括全部 KV、scratch 和 32,000 logits；每种方法的 fcsr 必须为 RNE 且三者 flags 相等。

检查 TLS/errno、三个 state 的前后保护区、模型全部字节不变，以及 p256 的三个调用均拒绝。768 次有效 forward、512 次完成的全状态比较、三个独立 host 前缀比较和三次越界拒绝均由实际报告证明；完整十项 dump 保留报告、三个最终 live state、全部位置 flags/tokens、五份模型和 host 前缀 gold。GNU 链接复用原 `consumer-w2.o`，不重新编译核心；四个内核的实际完整函数机器码仍与已合格对象相同。

## 实际负控、恢复和资源

先运行单独负控进程：同 ELF 只改变第一个 control word；在 p0 的三次真实 forward 与 host 前缀检查后翻转 TA-cache 的实际最后 logit bit0。FR 比较先完成，TA 比较必须在 state byte152476 拒绝，原参考必须产生 BAD TRAP、halt_ret=94、exit=2；负控不继续 p1。随后新进程运行正常 p0..255，作为真实负控后的完整恢复。

普通参考旧 team adapter 将 API 调用上限固定为 10,000,000,000。新长序列的实际成本依据是当前 scalar 三位置 364,544,121 次 API 调用、FR-cache/TA-cache 三位置 26,503,299/34,360,983 次；这些只用于宿主运行预算，不是香山周期。为容纳约 256 位置的新单次运行，单独构建一个 team adapter 派生副本，仅将上限常量改为 48,000,000,000，并证明完整源码可反向恢复；原 adapter、官方参考及所有数值/异常/完成判据保持原字节。新 adapter 有独立构建、源码、命令、依赖、二进制和运行身份，不继承旧执行的 PASS。

仅 CPU3，顺序运行两个进程；与 CPU0..2 的既有 EMU 合计不超过四核。负控上限 1G API calls / 120秒，正常上限 48G / 2400秒，外部超时各加30秒，每文件128MiB。超限或错误保留原始现场并明确 FAILED/PARTIAL，不自动放宽或从头重跑。源码与所有共享输入冻结，输出新建且隔离。此补充不宣称完整256位置的第二次独立重放，也不把参考机调用数当作应用速度。

## 原始证据与复算

保存两进程回执、ABI、寄存器/CSR、实际镜像、十项内存 dump、原始 stdout/stderr 和终态。实际负控必须由同一正常比较逻辑拒绝，正常最终三份完整状态必须相等；原始报告的每位置 flags、token 和完成计数必须准确。原字节归档、恢复及捕获的原验证器复算单独记录。完整香山 forward DiffTest/周期、任意 checkpoint/模型质量、冷加载、多线程及 ASIC PPA 不在本补充范围内。
