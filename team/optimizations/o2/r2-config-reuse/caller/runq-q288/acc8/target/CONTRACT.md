# ACC8 完整 Q 目标功能与成本小批合同 v1

合同：`r2-s3-runq-q288-acc8-target-v1`。在任何本合同 EMU 启动前冻结。

## 1. 目的与范围

落实 `../../RESEARCH.md` §6A 的首批 10 Q。沿用固定 T17 单核、原 AM、原 NEMU/flash、原计数器协议和负控转接 fixture；官方参考程序、硬件、原六个整数叶、旧包装及 acc8 源码全部不变。新适配器仅组织混合 ELF、校验与证据。原 firstdot V2 默认和 V1 回退资格不变。

本阶段验证完整 288×288、GS=32 的预量化 Q 投影及其实际成本；不覆盖量化、完整模型、token、模型质量或 ASIC PPA，不选最快 RVV，不解除既有 HOLD，不取得公平加速资格。

## 2. 固定调用计划

同 ELF、同一个计时入口、同 packed 权重及结果/槽地址。旧包装与 acc8 独立 C 翻译单元；只通过符号宏给旧包装改名，不改源逻辑。共同 pack 执行一次，单列计时。全部六个合格叶留在 ELF 并重做完整机器码证书，实际只调用 vdot 和 RVV4。

| Q 顺序 | 包装 | 整数叶 | 输入 |
|---:|---|---|---|
| 0 | 原 | vdot | x0 |
| 1 | 原 | RVV4 | x0 |
| 2 | acc8 | vdot | x0 |
| 3 | acc8 | RVV4 | x0 |
| 4 | acc8 | vdot | x1 |
| 5 | acc8 | RVV4 | x1 |
| 6 | acc8 | vdot | x0 回访 |
| 7 | acc8 | RVV4 | x0 回访 |
| 8 | acc8 | vdot | x2 |
| 9 | acc8 | RVV4 | x2 |

这 10 次同时承担功能检查和成本观察，不能重复相加为 20 次。没有额外 warmup、conditioning、目标 scalar oracle 或 324 叶逐组扫描；严格数值 golden 来自已固定的独立 host C/Python oracle，并与新 ELF 中每一字节绑定。第一步 host 检查不自动转移目标 PASS，目标每次仍须真实执行和判定。

每个完整正常进程：11 个计时窗（1 pack + 10 Q），3,240 次合格整数叶调用，5 次 vdot Q 的 51,840 条 custom，加原 11-word 隔离 probe 的 1 条，恰为 **51,841 个 vdot COMMIT**；44 个 COUNTER_ENQUEUE 与 44 个 CSR_SAMPLE。完整 Q 内有 25,920 次 signed 转换、51,840 次 FP32 乘、25,920 次 FP32 加。负控提前拒错，不套用正常进程总数。

## 3. 正确性与实际路径

RNE、禁 FMA/重结合/向量化/LTO、普通不透明叶 ABI、原严格逐组 FP32 舍入顺序均保持。新 ELF 的旧/acc8 包装、pack 与全部叶体必须分别与第一步 ZIP 中的真实 ELF 完整字节一致；新编译命令、输入、计划和指针表均绑定实际产物。

每个 Q 真实逐位检查全部 288 个输出、最后一组 8 个完整 128 位槽、guard、context 指针及 vl/vtype/vstart/vcsr/frm。十次共 2,880 个输出和 80 个末组槽观察；不声称目标软件读回了全部中间槽。保留 6 个真实内存判定负控并恢复。pack 后和整个批次结束分别核对全部 82,944 个 packed 字节。输入只读还由实际 ELF 的完整地址/写足迹证明和精确 RETIRE 路径闭合；不虚称目标逐窗扫描所有只读数组。

每个 `(包装, 叶, 输入)` 显式传入 dataset 重做控制/地址路径，分别使用原 row 与 acc8 group 尺度顺序，验证完整 FP callee-saved 64 位恢复、栈恢复、324 次调用参数、尺度地址与全部输出覆盖。复用同一 PC 路径前须证明各输入 PC/word 序列完全相同。实际退休、CSR 与静态指令三者闭合；压缩 ROB 不允许隐藏 branch/jal/jalr。FP 数值在静态地址检查器中仍为 unknown，数值资格依赖实际目标判定和完整 DiffTest。

## 4. 执行、预算、停止

串行实际 `negative → recovery → replay`，同 BIN/seed/固定依赖、三个独立 PID；EMU 至多一个，同机 CPU 总预算不超过四核。每进程 `--max-cycles=12000000`，父运行器墙钟上限 7200 秒。负控须由实际第一条 vdot 的 PC、`0x0388000b`、vd0 bit100 和原门禁拒错闭合后才继续。

任一正确性、ABI、路径、协议、身份、完整退出或时间预算失败即停，并保留原始证据；不拼接旧批次、不自动加样本直至通过。正常与独立重放完整 validation JSON 必须相同，重放不是额外统计样本。只有三进程和原始证据闭合，才标记 `TARGET_FUNCTIONAL_AND_COST_DIAGNOSTIC_PASS`。

## 5. 成本口径与下一步

窗口包含完整包装保存恢复、324 次叶调用、严格 FP32 消费和输出写入；pack、准备、判定、probe 和 UART 在 Q 窗之外，不扣估计开销。各计时窗之间不输出 UART；全部结果在批次结束后打印。

逐窗报告包装、叶、输入、调用位置、cycle 与 instret。原包装仅一次 x0，acc8 两次 x0 的位置和缓存/预测器历史不同，没有共同性能锚点，因此不计算公平 speedup、不应用 5% 性能门槛、不称稳态或冷缓存。可以在新 ELF 和真实 instret 均闭合后报告同叶指令差；首次周期较大本身不是性能 STOP。

后续选择依据实际成本与正确性：有潜力时另立公平比较或候选合同，不能把本批描述性观察提升为正式性能结论。所有来源、命令、失败、原始日志和归档哈希保留；ZIP 必须以 binary Git 属性提交并检验 Git blob 原字节。
