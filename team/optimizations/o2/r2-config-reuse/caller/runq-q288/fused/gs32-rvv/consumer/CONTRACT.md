# GS32 K288 消费者独立入口：有界参考正确性

合同：`r2-s3-forward-consumer-gs32-v1`。本合同不修改稳定默认入口，不授予完整应用周期或加速比资格。

## 规格与边界

新增 `r2_w2_gs32_forward(state, token, position)`，沿用 `r2_w2_init/reset`、原固定模型的状态结构、缓冲区所有权、对齐和连续位置要求。固定配置为 D288/H768/L6/HQ6/HKV6/V32000/S256/GS32。旧方法枚举 0–4、原 `r2_w2_forward` 的分派和方法 5 非法约定保持原样。

新函数复用原 FR-cache 模板：Q/K/V、Wo、W1/W3、classifier 七处静态调用走已筛选且通过固定 Q 目标验证的 GS32 K288 汇编；唯一 W2 调用逐字保留原 `route_fr`，因此仍走 K768 FR。W1/W3 的输出为 768，但输入仍为 K288。新路由仅供这一内部固定模型模板使用，不作为任意维度接口。

所有旧消费者函数完整保留。新模板除函数名与七个路由名外必须可精确逆向恢复为原模板。量化、权重打包、尺度、FP32 乘加次序、RoPE cache、norm、attention、SwiGLU、状态写入均保持。INT8 乘积以 INT16 表示、整组和以 INT32 表示；组和范围仍为 [−520192, 524288]。GS32 汇编的具体寄存器、CSR、槽、数值与目标合同见父目录，不把较少架构指令当作应用周期收益。

新公开入口沿用原初始化、非空状态、token 范围 [0,32000)、position 范围 [0,256) 检查。原 `consumer.h`、`consumer_w2.h` 与上游 runq.c 原字节不变；官方 AM、参考模型、参考调用器和既有数值验证器不改。

## 输入身份和构建

父输入是实际编译并完成参考验证的 norm/W2 `consumer-build-02`，而非重新根据当前 HEAD 推测的旧版本。父 result SHA 为 `8ad05a4aa3bee2bd23d14f698c43ebfa445703aa19e2f2951d079b655d76482d`。父源码、工具、归档库、fixture、独立 host golden、旧数值验证器及其实际运行证据分别固定 SHA。必要时从既有运行的源码快照加载旧验证器，不要求更新后的工作树伪装成旧版本。

新构建只写隔离输出。复制实际父编译源，新增头文件和入口；复用父派生记录中的真实 GNU 编译参数，仅更换源/对象输出路径。保留 `-O2`、`-ffp-contract=off`、`-fno-fast-math`、禁用自动向量化和原 ISA/ABI；构建至多使用一个获协调的 CPU。原 norm 两个对象直接复用，GS32 使用原 v2 实际汇编中的完整函数，新 ELF 中的函数体必须与筛选 ELF 完全相同。父四个 K288/K768 汇编函数同样逐字节保持，norm 只允许原检查器明确识别的链接地址修正。

最终 ELF/BIN 必须一致，所有模型字节、TLS 和观测缓冲区的实际初值须检查。查看实际链接的公开入口、七处 K288 路由与保留的 W2 FR 路由；仅有同名符号或数值相等不足以证明路由。原四个 C 消费者不要求跨 ELF 的裸字节 SHA 相等，因为合法的 PC 相对链接地址可能变化。

## 三个新的独立参考进程

顺序固定为 negative → recovery → replay，最多一个参考进程。每个进程使用原固定参考库与原参考调用器，原独立 host golden、完整输入和 dump 格式不变。不重跑旧八方法 campaign，不启动新 EMU。

1. negative：实际运行新入口的第 0 步，随后在 guest 内翻转末 logit 的最低位，要求 BAD94、退出码 2；原完整状态比较器必须在 byte 152476 拒绝，且整份状态只能有这一个预定比特不同。
2. recovery：新进程，tokens 1、7、19，位置 0、1、2；每步完整 3,691,424 字节状态与独立 host golden 相同，最终 live state 相同，所有模型输入不变，未使用快照/flags/time 区域保持零。
3. replay：又一个新进程，完整复现 recovery 的验证结果、状态、flags、参考退休量与参考计数样本。重放用于确定性，不增加性能观察样本。

复用原 W2 `validate()` 的数值及过程判定，只绑定新镜像构造函数。新协议的控制与 report 第 2 项是独立入口标签 `0x47533332`，不是旧方法枚举；绝不把标签传给 `r2_w2_forward`。新结果把原验证器输出作为明确标注的复用部分保存，外层使用本合同与新入口身份。

运行前重审旧 scalar 的实际 raw dump、过程回执与记录。新入口每步 fflags 必须与该 scalar 的 `[1,1,1]` 精确一致，并保持 RNE。实际 guest 还检查未初始化、新入口空状态及 token/position 越界均返回 NULL、状态无改动，以及旧方法 5 仍返回 NULL。整个控制流的真正新入口调用由实际 ELF 标签和调用目标核对。

若旧原路径中的大文件已封存，则用既有 `stages/archive.py` 校验已发布 ZIP 的整体 SHA、清单和每个对象，只把原 scalar 子集还原到新审查目录；保留原回执中的历史路径，并逐字节核对仍在原目录的文件。不得从 golden 重造原始输出，不得修改原目录或将恢复误记为新的运行。

原运行源码快照只包含实际导入的模块，可能缺少固定身份门禁另行读取的源码。此时允许 `snapshot_support.py` 在新的外部目录复制完整支持文件：原模块按历史清单 SHA 保留，补充文件按原门禁的 SHA、固定 Git blob 和 T17 adapter 清单核验。运行用显式 `--support-snapshot`，不补写历史快照。原门禁中的 `git show BASE:path` 在身份检查期间只读使用常驻仓库的真实 Git metadata，之后恢复进程环境；不创建新检出，不改变 Git 对象或门禁代码。原构建、旧控制器和失败回执继续保留，新运行器和完整支持快照另记运行输入身份，不能重算旧构建清单来掩盖漂移。

所有进程需记录 PID、独立进程组、退出与回收。未知回收状态或输入身份漂移不得记 PASS。保留完整原始与失败证据，所有原父结果不回写。

## 资格与回退

PASS 仅表示本固定合成模型及三步位置的新增入口参考正确性。它不自动覆盖全部 256 步、其他模型、训练模型质量、双状态并发隔离、目标整核时序或完整应用性能。已有旧入口和父对象保留，调用者恢复旧命名入口即可回退。

GS32 固定 Q 相对当前较快 TA 的保守周期改善为约 1.37%；本合同不为此单独启动长整应用性能 campaign。以后若需比较完整路径，必须用新的公平最终 ELF 合同，保留最快合格 RVV 与原 FR 对照，并计入所声明的完整消费者边界。
