# GS32 完整组 RVV：独立软件候选

当前筛选合同 `r2-s3-runq-gs32-rvv-screen-v2`（共享零种子）。v1源码、ELF与结果冻结于 `runs/gs32-rvv-20261106-0640/screen-01/`；v2必须重新编译和筛选，不继承v1 PASS。对应 Issue #2 WORK 6671408286；本包只新增独立源码、检查与结果，不修改原公开库、生成器、官方程序、生产硬件或稳定入口。

## 目的与适用边界

当前 FR 对每个 GS32/八行块执行两次 VL16 的乘法与归约。本候选以标准 RVV 的 `e8/m2/VL32 vwmul.vv` 和 `e16/m4/VL32 vwredsum.vs` 一次完成每行完整量化组，减少重复归约、地址和向量配置指令。它首先是更强 RVV 对照的候选；不能从架构指令数或模拟模型推断周期收益。

入口 `q288_gs32_rvv` 接受原 `q288_context` 前六个指针：packed W、quantized X、row-major Ws、Xs、Y、末组 slots。尺寸固定 288×288、GS32、八行 tile、VLEN128；每个 tile 的组顺序 g0→g8，P[t,g,row,k] 及原尺度布局不变。第七个 entry 字段不读取。quantized 数据允许任意字节对齐，float 指针4B、slots16B对齐，各区域不重叠。要求 FS/VS enabled 和 FRM=RNE。

每组 INT8×INT8 积精确保存为 INT16，32项之和用 INT32 表达；所有 INT8 输入的和范围为 [−520192, 524288]。单组完整求和与原两半组整数求和严格相等，无饱和或溢出。后续每行仍执行 `((float(dot) * Ws) * Xs)` 后逐组 FP32 相加，不融合乘加、不预合并尺度、不重排浮点运算。

## 寄存器与可观察状态

| 寄存器 | 用途 |
| --- | --- |
| v0…v7 | 八行 INT32 结果；入口以四个m2清零覆盖八个完整128位寄存器，归约仅写低32位 |
| v8…v9 | 八行 FP32 累加 |
| v10…v11 | 归约后收拢低32位；整数阶段空闲 |
| v12…v13 | 单行32B权重，读后立即乘；随后复用作尺度 |
| v14…v15 | 共享32B输入向量 |
| v16…v31 | 四组 m4、INT16 乘积，分两批四行归约 |

所有 m2/m4 向量组起点按 LMUL 对齐，宽乘目的与源不重叠。归约的标量源/目的按 RVV 规范占单个向量寄存器，不要求按 m4 对齐。使用 `tu,mu` 保留末组槽高96位；t4 在入口设置 AVL=32，再用 `vsetvli`，不使用无法编码32的 `vsetivli`。

v2在入口e32/m2/VL8下清零v0/v2/v4/v6四个组。每组只在e32/m1/VL4下清零v0，全部八次归约以v0[0]为零种子；处理行顺序固定为(1,2,3,4)、(5,6,7,0)，最后一条归约才覆盖v0。因所有其他归约保持目的高96位，入口清零一直有效。浮点消费仍按行0…7收拢、每行g0→g8累加。v2减少每组七条清零，增加函数入口四条；可能产生跨组旧目的尾保持依赖，不能静态宣称周期改善。

仅最终组写八个完整128位 slots，每个 tile 写八个 Y。入口重置 vstart=0、vcsr=7；出口保持 vl8/e8/m1/tu/mu、vstart0/vcsr7。原标量/浮点 callee-saved、sp、ra 保持；无栈分配，无输出读回。异常标志随合法 FP 运算累积，不宣称支持中断恢复或非RNE扩展域。

## 验证与后续决策

1. 固定父生成器及公开汇编 SHA，真实 GNU 编译 RV64GCV，读取实际 ELF 机器码及符号；旧 FR 与新候选同时保留。
2. 复用原有限 binary32 运算和独立 row-major C/Python golden。新模块只扩展实际机器码解释器所需的三类宽向量操作和寄存器AVL设置；原模型与验证器文件只读。该模型不是CPU、NEMU、DiffTest或周期模拟器。
3. 执行完整288×288，核对所有288输出逐位一致、324组、每个输入字节精确访问次数、最后八槽、输入不变、寄存器/CSR/栈；沿用 x0→x1→x0→x2、极值、零值和额外字节对齐用例。新指令必须使用全部32元素，拒绝短VL、错误源地址/组对齐和改变FP顺序的实际ELF反例。v2另拒绝缺共享种子清零、缺入口结果高位清零两个反例。
4. 静态通过仅表示值得测量。后续目标合同必须固定同一硬件、reference、数据和完整调用边界，保留现有合格 FR/TA 与本候选；比较包含全部已测锚点，不把局部周期或指令数当完整应用收益。
5. 若完整Q未显示有意义的改善，停止扩展到完整forward；若有改善，再在原数值与调用协议下验证 K768/W2 和完整消费者。新候选实际目标PASS不能从历史旧FR结果继承。

回退通过继续选择原FR/TA符号完成；本候选不改变默认、权重格式或持久模型。相关标准依据：RISC-V V 1.0 的向量组、widening multiply、widening reduction 和 vsetvli 规则（<https://docs.riscv.org/reference/isa/v20260120/unpriv/v-st-ext.html>）。

## 新目标合同 v1：完整 Q288 与两个保留对照

合同 `r2-s3-runq-gs32-rvv-target-v1`；只比较同一新ELF内 GS32、已有TA、已有FR，符号依次为 `q288_gs32_rvv` / `q288_tail_vdot` / `q288_fused_rvv4`。本边界是预打包数据的完整288×288浮点输出，不含quantize、packing、完整token或模型运行。完整新函数的机器字节必须与v2已筛选ELF一致；FR和TA全函数字节以旧证据SHA绑定，共同计时器全函数与旧目标ELF字节一致。

`target.py` 复用原固定数据生成器、guest judge和计时器，只替换生成后的第零个wrapper、方法标识和新合同名，追加GS32函数。原 `phased/tail/target/main.c` 字节不改。先用dataset1、2对每种方法做六次功能调用，再用dataset0按 FR→GS32→TA→FR / FR→TA→GS32→FR 执行八窗口；每个窗口前有同方法selfwarm。总共22次完整调用，每次检查288个结果、末组完整槽、边界守卫、上下文与CSR；原5个guest判定器故障控制保留。全程custom指令为6×10368+1独立probe=62209；GS32无custom指令。

`check_target.py` 核对完整ELF/BIN对应、实际数组、函数指针、调用计划，并以真实链接地址建立三种方法在三个dataset下的完整PC/word路径。由未修改的counter解析器核对CSR采样、fence顺序、退休事件和静态完整路径三方一致；由原O2解析器核对全程custom接受/完成/提交协议。完整路径CSR instret预期为GS32 20134、TA 49613、FR 35681，这是实际计时点之间的指令数，不是周期预测。父生成器的 `.gz` INPUT_PINS 是解压内容的SHA，核对按原 `raw()` 语义进行，同时记录物理压缩文件SHA；不把两者混用。

硬件固定既有T17的EMU `ff840528...`，正常NEMU `8af118e5...`，完整SHA、构建身份和flash由 `run_target.py` 固定并在每次运行前后核对。固定seed1、128MB客体RAM和12M周期上限。先复用既有团队测试专用bit100负控wrapper，仅损坏返回给DiffTest的状态副本，不修改原NEMU或其执行状态；要求精确的probe PC→高半bit100差异→ABORT→exit1拒绝链。成功拒绝后才启动正常reference的recovery与replay。

这两个正常运行以独立CWD/输出和不同CPU affinity并行，每个EMU的原构建 `EMU_THREADS=1`，最多同时两个EMU，总项目CPU仍不超过人工授权四核。主机墙钟耗时只作运行成本；性能只用客体CSR与RTL全局时钟一致的周期。replay要求八窗口的周期、instret、计数器值/采样时刻和custom PC序列与首次正常运行一致，不充当新统计样本。不为占满四核增加无决策价值的重复运行。

所有观测都保留，同一组四个FR锚点要求max≤1.01×min，否则结论为HOLD。对每个对照以最慢GS32/最快对照作保守比较，只有同时比TA和FR至少快0.5%才得到本固定Q计划的候选优先资格。若只赢FR而仍输TA，可记录为更强RVV备选的局部证据，不宣称全路径优化完成。无论结果如何，本合同均不自动改变稳定入口。
