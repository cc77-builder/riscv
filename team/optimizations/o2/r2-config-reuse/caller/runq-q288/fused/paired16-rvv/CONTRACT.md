# Guarded paired16：完整 Q288 的标准 RVV 候选

合同 `r2-s3-runq-paired16-rvv-screen-v1`；独立工作包 `20261106-LiZufan001-paired16-rvv-pro6`，Issue #2 WORK 6672431323。本阶段只形成实际 GNU ELF 和主机数值/地址筛选；不授予目标 DiffTest、周期或完整应用收益资格，不改变默认入口。

## 接口和数值域

入口 `q288_paired16_rvv` 接受已有 `q288_context` 的前六个指针：原 packed W、X、row-major Ws、Xs、Y、末组 slots；第七个 entry 字段不读取。沿用完整 288×288、GS32、八行 tile、VLEN128、FS/VS enabled、FRM=RNE。量化数据允许任意字节对齐；float 指针4B、slots16B对齐；各区间不重叠、输入只读。原 P[t,g,row,k]、尺度和 g0→g8 消费顺序不变。

输入仍为完整 signed-int8 域。每个 s8×s8 乘积范围 [-16256,16384]；两项和为 [-32512,32768]，唯一 s16 溢出是两项都来自 (-128)×(-128)。如果 X 不含 -128，则任意 s8 W 的成对乘积和落在 [-32512,32512]，可以精确保存在 s16。

函数入口完整扫描 X 的288字节一次，累计其中 -128 的个数：九次 e8/m2/VL32 装载、signed vmslt.vx 与 -127 比较、vcpop.m、addw。检测始终覆盖九组，不提前退出；VL32通过寄存器 AVL 设置。存在任何 -128 时，进入同一函数内的固定 FR 完整主体；否则进入 paired16 主体。检测、重复初始化、分支和回退都属于候选函数的实际执行，不能移出计时区。一次检测有效依赖上述既有输入只读/非别名合同，未增加新的输入限制。

快路对同一 GS32 内前后16项执行 e8/m1/VL16 的 vwmul.vv 与 vwmacc.vv，再以 e16/m2/VL16 的 vwredsum.vs 归约到 s32。完整32项和精确等于原两半计算；没有跨量化组求和、饱和或舍弃进位。回退逐字保留原 FR 算术和完整消费主体（仅重命名内部标签）。全域和范围仍为 [-520192,524288]。

## 寄存器和可观察状态

| 寄存器 | 快路用途 |
| --- | --- |
| v0…v7 | 八行 s32 结果，高96位保持零 |
| v8…v9 | 原八行 FP32 累加器 |
| v10…v11 | 原低32位收拢和 FP 转换 |
| v12/v13 | 一行 W 的前/后16字节，随后复用为原尺度暂存 |
| v14/v15 | 一组 X 的前/后16字节 |
| v16…v31 | 八组 m2 的成对 s16 乘积和 |

固定 VLEN128 下，vl2re8.v 以32字节装满两个完整寄存器，独立于当前 VL16。X/W基寄存器分别14/12，所有宽乘目的16,18,…30，均满足组对齐且不与乘数重叠。每行的后半 W 在下一行装载覆盖前已被对应 vwmacc 读取。

快路在检测后以 e32/m2/VL8 清零 v0/v2/v4/v6，覆盖八个完整结果寄存器。每组以 e32/m1/VL4 清零 v0，再按行1…7、行0的顺序归约，以 v0[0] 作为共享零种子；所有归约使用 tu 保留高96位。末组仍写八个完整128位 slots，每个 tile 写八个 Y。

后续原 FP 主体逐字复用：收拢、signed int32→FP32、乘 Ws、乘 Xs、逐组加入 FP32 累加器。禁 FMA、预合并尺度、重排 FP 次序。入口和被选主体保持 vstart/vcsr 初始化；出口 vl8/e8/m1/tu/mu、vstart0/vcsr7。保留整数/FP callee-saved、sp、ra，无栈分配和输出读回。当前主机模型只证明 RNE 的有限值/有限结果，沿用原模型对 NaN/Inf、非RNE和异常标志的证据边界。

## 新的精确访存边界

两条候选路径都先完整扫描 X，再完整执行一个计算主体。每个 W 字节读一次；每个 X 字节读37次（36次原计算+1次检测）；每个 Ws 字节读一次；每个 Xs 字节读36次。context 的前48字节各读一次，其中 X 指针字段8…15另读一次；不读 entry 字段。每个 Y 字节与最终 slots 字节恰写一次，输入和 context 不变。不能套用旧候选 X 只读36次的特殊计数，也不能放宽为任意额外读取。

## 验证和决策

1. 固定父生成器/公开汇编/strict-FP 模型/整数模型/独立 oracle 的 SHA。实际 GNU RV64GCV 编译，保留 ELF、反汇编、编译命令和失败日志；旧 FR 单独符号继续保留。候选内回退主体的机器码应与旧 FR 完整函数体逐字一致。
2. 复用原有限 binary32 模型与独立 row-major C/Python golden；新类只扩展检测所需寄存器AVL/m2加载/比较/计数、whole2 load 和 vwmacc。vwmacc 按真实 s16 回绕建模，禁止以“模型不允许溢出”替代反例执行。
3. 检查所有288输出逐位一致、末组八个完整槽、324个正确整数核路径、输入只读、新逐字节 footprint、ABI/CSR、原 FP 操作计数。覆盖原 x0→x1→x0→x2、快路 s8 W=-128/X=±127、回退全-128及边界位置 X=-128；继承脏向量状态并覆盖原字节非对齐域。
4. 实际 ELF 负控至少包含关闭guard导致32768回绕、漏扫最后一组、错误后半乘数、缺入口高位清零/共享种子清零、错误FP尺度顺序。关键溢出负控应执行至普通返回，再被独立数值结果拒绝，不能仅由路径白名单拒绝。
5. 静态指令/uop只作投入判断。当前目标硬件与旧 FR/TA、更快合格 GS32 的同输入完整函数比较另立合同；必须计入检测和回退，先看完整Q收益再决定是否扩展完整forward。此包无 RTL 变化，无新的时钟/复位或FU时延承诺。

标准依据：[RISC-V V1.0](https://docs.riscv.org/reference/isa/v20260120/unpriv/v-st-ext.html) 的 whole-register load (§30.1.7.9)、widening multiply/MAC (§30.1.11.12/14)、widening reduction (§30.1.14.2)、向量组与 vsetvli 规则。静态拆分依据团队固定 T17 源 `34bae6d4acceac939f958199dae53c14bc1f6183` 的 VecDecoder/UopInfoGen/DecodeUnitComp；不以该源码账本代替目标测量。
