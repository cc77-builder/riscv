合同：`r2-s3-fixed-weight-8x32-v1`。原实验操作：`20261025-LiZufan001-r2s3-fixed-weight-0920`；交付接续：`20261025-LiZufan001-fixed-weight-delivery-1432`。下文运行矩阵属于原实验，本次接续仅恢复、复算和交付，新增 EMU 为 0。

**N=1、N=4 均为 `HOLD_CONTEXT_VARIATION`，未选定性能优选方法，R5 默认不改。** 正确性、504 窗完整重放、封存原文独立复算及可选静态库交付均通过。

两组的六对 split/packed 检查均满足预设接口门槛（`interface_qualified=true`），但最大锚点变化分别为 **6.677019% / 2.237354%**，超过事前 1% 上限；两组 `selected_method=null`。因此提供按正确性与实际链接证据支持的显式可选接口，保留全部 RVV 和 packed 回退，不把本计划的观测周期减少升级为合格性能收益。

## 1. 本次解决的问题

上一轮 split 调用对照在每次 GEMV 前复制完整的 288 字节输入。固定权重消费者可以复用 A 的准备工作，因此不能直接套用那一轮的接口收益。本次先把 packed 对照改为：每个完整 stream 只复制一次 256 字节 A，每步仅复制新的 32 字节 x，再与直接访问分离 A/X 的 split 比较。

两边使用相同六类既有算术实现，捕获一次 context 字段，每步一次间接叶调用，并保留每步的完整 128 位槽和 INT32 输出。没有把复制移出 packed 计时窗、删除较快 RVV 或合并不同镜像的数据。主组 N=4；N=1 是初始化对照，其他 N 不在本合同内。

计时包含 stream 函数内的 A 准备、x 更新、循环、调用、槽写入及输出提取。context 构造、guard/golden 准备在两边计时外。每窗前使用同一 firstdot RVV 做一次匹配 N 的完整 conditioning，全部计时结束后才输出 UART。总周期/N 是包含初始化的摊销均值，不是通过 N1/N4 相减推导的稳态成本。

## 2. 本计划的观测数据与事前门槛

每 N/普通方法有 12 个正式样本：三个数据集、正反两种调用次序、每格两个样本。完整计划为 504 窗，含 288 个正式方法窗和 48 个正式锚点窗；first/warmup 同样保留在原文中。正常恢复与独立重放的全部 504 窗逐项一致。

接口配对门槛按 N 分别判断：六组同算法 split/packed 均须减少至少 5% 总周期，任何数据集退化不得超过 1%。算法选择还要求每数据集锚点变化不超过 1%，且 vdot 在全部六个 dataset×order 格中至少胜过该 N 的最低总周期 split RVV 0.5%。全部使用原先固定的整数比较；没有事后放宽门槛。

`interface_qualified` 只记录合同中的配对检查结果，不覆盖整体 `HOLD_CONTEXT_VARIATION`。以下周期减少是本计划的描述性统计；锚点变化不是各方法比较误差的已证实上界，不能用“观测差异更大”来解除稳定性门槛。相同计划的完整重放也不自动消除这一限制。
