# R2-S3 重复配置：独立候选与主机验证合同 v1

合同：`r2-s3-config-reuse-c-abi-v1`。本阶段从固定 firstdot C ABI 生成器建立候选，证明受限正常路径的状态语义，生成真实 RV64GCV 机器码并使用团队已有模型检查。**该阶段没有整核运行或周期资格，也不修改稳定默认。**

来源提交：`c362ca74194f238afe7a84247ccd3e1cb7da36d2`。源码所有权与来源保持：只新增本目录，旧 firstdot/S1/S2、官方权威程序、RTL 和归档不改。精确父源码由 [candidate.py](candidate.py) 的 Git blob 清单锁定，新增代码和验证器另记录 SHA256。

## 1. 假设与范围

firstdot 内存在同一配置区间中重复的 `vsetivli zero, imm, ...`。如果配置和 `vstart` 已满足其执行后状态，这条指令对当前函数计算需要的状态是恒等转换。删除可能降低软件开销；是否降低周期必须实测，不由静态指令数决定。

对 vdot/RVV、basic/reuse 应用同一规则。四形状为 4×8、8×32、16×64、4×13，三份固定输入保留原来生成方法。仅允许 `endtoend` C ABI 调用窗；这里的命名仍表示原 GEMV 调用边界，不能扩大为完整应用或 LLM。

不开展死配置删除、跨函数传播、寄存器分配、数据布局或 RTL 优化。仍以两个指针传入紧密 A||x 和每行16字节的完整128位输出；首条状态建立、尾部处理、读写顺序和调用/返回保持。向量配置属于调用端可破坏状态，入口不依赖 caller 已有 `vl/vtype/vstart`。

## 2. 状态证明

规范依据为 [RISC-V V1.0，20260120手册](https://docs.riscv.org/reference/isa/v20260120/unpriv/v-st-ext.html) 的 §30.1.3.7、§30.1.6、§30.1.6.3、§30.1.7.7；自定义指令依据团队 [vdot 合同](../../../spec/vdot.md)。标准规范不为自定义编码授予官方认可。

维护 `(实际vl, SEW, LMUL, vta, vma)` 及“已知vstart=0”。候选限定 VLEN=128，配置合法、保留位为0、vill=0，AVL不超过VLMAX和5位立即数范围：e8/m1的VLMAX为16，e16/m2为16，e32/m1为4。因此配置执行后的vl可直接取AVL。

删除一条配置的必要条件同时为：

1. 全行严格匹配所支持的 `vsetivli zero, imm, ...`；rd必须是zero。
2. 执行前已知完整配置与执行后相同；策略位也参与比较。
3. 执行前已知vstart=0。相同配置不能代替这一条件。
4. 从建立状态到当前位置没有未建模的状态变更或控制流入口。

每个body从未知状态开始，首条配置保留。严格白名单内的标量运算不改变向量配置；已知普通向量操作在正常完成后保持配置及已知零vstart。实现保守地不利用“从未知或非零vstart恢复”的推断。`csrwi vstart` 仅更新零值事实，`csrwi vcsr` 不与这两个状态混淆，两种写均保留。

`.word` 必须精确匹配 `mask=0xfe00707f, match=0x0200000b`，并且当前为e8/m1/vl8/tu/mu/vstart0，才按团队vdot合同保留已知状态。非零vstart下vdot应非法，不能用它清零。其他机器字、`.insn`、未知CSR、调用、跳转、标签及fault-only-first均清空已知事实；固定父生成器若出现此类屏障，本候选生成直接拒绝。

归纳论证：首条保留配置建立已知状态；每条被保留的已识别操作保持或明确更新事实；每条被删除的配置在上述事实成立时既不改变vl/vtype/vstart，也不写任何有效整数目的；因此下一个保留操作看到相同输入状态。所有非配置指令及其顺序保留，输出、约定CSR和实际输入读取边界可在同一正常路径保持。

边界：VS开启、受支持的向量配置、有效的普通内存和正常完成是原函数前提。异步中断只有在处理器/处理程序正确保存和恢复该线程向量状态时可按原程序继续；本阶段不验证任意陷阱处理器、精确PC、异常观测时刻、特权Dirty位或调试观察等价。移除指令本来就会改变退休计数、PC及可能的时序，它们不在功能等价集合中。

## 3. 真实汇编及主机验收

首选复用现有工具。当前独立云端环境具备LLVM20动态库，采用其真实RISC-V汇编后端，不编写自制汇编器。明确标记LLVM静态对象；不记作GNU重建、可执行AM ELF、NEMU或EMU PASS。

必要检查：

- 两变体从相同父生成器、相同数据、相同wrapper产生；父firstdot产物与原生成器逐字节一致。
- 24组生成结果串行/最多四路并行相同，私有renderer互不污染；已有输出和来源树重叠输出拒绝。
- 各对象为RISC-V ELF64 ET_REL，无未解析强符号和重定位；禁止压缩和relaxation。wrapper保持四个8KiB槽，公开leaf与wrapper内leaf机器码相等。
- 基线的16种leaf与固定已封存GNU对象中的对应firstdot符号逐字节相同。该锚只证明本次LLVM基线机器码身份，不转移历史运行资格给新候选。
- 独立按机器码检查候选仅移除批准的配置word，其他word、顺序、ABI前后缀不变；不只核对助记符数量。
- 复用未修改S1机器模型检查完整128位输出、所有向量/标量寄存器、约定CSR、访问与存储序列、紧密行边界、毒化寄存器和不同入口向量状态。与独立整数GEMV黄金值同时相符。
- 负控必须保留或拒绝非零vstart、FOF、非zero目的、策略变化、控制流、未知机器字、夹带第二条指令及超界AVL；机器码篡改不得通过验证。

保存实际生成源、对象、构建命令/退出、模型输入、拒错结果及来源哈希。失败尝试保留，报告PASS/BLOCKED/NOT_TESTED分别列出。

## 4. 整核筛选前的缺项与停止条件

本阶段不能直接把新manifest交给冻结firstdot运行器。下一阶段先按协作Issue认领并核实本机实际来源、进程、四核总预算和T17物理输入；补充独立新合同的GNU/nexus-AM构建及运行适配，不改变旧门禁。

先仅做8×32/dataset0，保留firstdot基线和config-reuse候选；两边各含basic/reuse vdot/RVV，配置删除对RVV同等开放。还要保留此前更快的S1 RVV作为明确的参考候选；最终比较只能用同次新入口/同硬件/同条件实测的最快合格RVV，不借旧周期当分母。

最低进入条件是完整加载布局/槽外字节对照、真实新PC和目的的bit100差分负控、同BIN正常恢复、全部窗口语义/CSR/退休/O2协议以及独立进程重放。调用窗计时口径沿用原合同，性能进程串行。新代码即使目的寄存器未变，PC可能改变，不能复制旧负控配置。

只有候选同时优于同次firstdot和最快合格RVV，且无未解释退化，才扩大矩阵和普通C库资格；无收益则保留较好基线并关闭此假设。此前已经合格的36次firstdot执行不重跑为本阶段凑样本。

RTL不变：复用O2两槽/H1原硬件，既有无停顿首响应2拍、II=1只是该硬件基线属性。时钟、复位、接口和位宽未改；不新增面积、STA、频率或功耗结论。稳定R5默认与可选firstdot库继续使用各自原资格。
