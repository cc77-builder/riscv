# dot16 whole2：独立软件供数变体

合同：`r3-dot16-whole2-host-v1`；2026-11-06 UTC；工作包 `20261106-LiZufan001-paired16-rvv-pro6`。

## 目标与范围

以不同符号 `q288_dot16_whole2` 复用已有 plain-dot16 算术，检验 whole-register load 能否在保持原始 packed W 布局、完整输出和逐组 FP 次序的前提下减少供数指令。只写本叶；原 `dot16/candidate.py`、`screen.py`、旧四臂 P/G/TA/FR、硬件、NEMU、官方权威代码及冻结输入保持原样。原 dot16 原型或生产 FU 的历史 PASS 不转移为本函数的目标资格。

本合同是 GNU 实际 ELF 和有限主机模型筛选，不是目标核、DiffTest、异常模型、周期模型或 ASIC PPA 验收。无新 EMU；不据静态指令减少改变稳定入口。

## 固定接口和算术

保持原 full-Q 调用接口：`a0` 指向原 context，依次读取 packed W、X、W scale、X scale、Y、八个最终128位 slots 的六个指针；不读或更改后续字段。不使用栈，普通 `ret` 返回，保存原标量/浮点 callee-saved 约束。N=K=288、GS=32、36个八行 tile、每 tile 九个完整组；不处理短尾，不新增矩阵重排或对齐要求。

VDot16 编码保持 `MATCH=0x0e00000b / MASK=0xfe00707f`；本函数使用 `vm=1,e8,m1,VL=16,vstart=0,vill=0`，16个 signed-int8 乘积的精确和范围为 [-260096,262144]，需要20个有符号位。结果低32位符号扩展，高96位清零。两半相加范围为 [-520192,524288]，32位整数足够；原 dot8 不变。ISA 合同允许源/目的别名，本函数只使用下面明确的寄存器分配。

这是软件变体，没有新增时钟、复位、FU接口、流水级、时延或吞吐保证。目标硬件资格须单独绑定实际配置和输入；独立 FU 连续输入 II 不等于本函数的依赖链或应用吞吐。

## whole2 寄存器供数与生命周期

固定 VLEN=128；`vl2re8.v` 每次装入32字节并写两个连续完整向量寄存器，基寄存器必须为偶数。整数核心先设 `VL16/e8/m1/ta,mu`（实际机器字 `0xc4087057`）；whole-register load 使用整个二寄存器组，不能错误建模成仅装当前 VL 的16字节。此合同固定 `vstart=0` 和有效 vtype，两个寄存器的全部字节均被定义；只在完整32字节源缓冲区内读取，不泛化到短尾。

| 内容 | 寄存器 | 生命周期 |
| --- | --- | --- |
| X低/高16字节 | v14/v15 | 一个组的全部16条dot16完成前保持 |
| 一个四行批次的W | v16/17、v18/19、v20/21、v22/23 | 先装4×32B，再完成该批次两半点积，之后才覆盖为下一批 |
| 每行低半部分和 | v0…v7 | 在两批次及最后整数归并前保持 |
| 每行高半部分和 | v24…v31 | 对应最终归并前保持 |
| 原FP累加/收集/尺度 | v8…v13 | 整数核心不得写入 |

两批次行号为0–3和4–7，W起点为 `a2+row*32`。末尾固定 `VL4/e32/m1/tu,mu`（`0xc1027057`），八条 `vadd.vv` 合并两半。整数核心不更新 `a1`；原后缀保持 `addi a1,a1,32`，每组净前进32字节。不能沿用旧 plain16 的“核心+16、后缀+16”安排。

## 完整函数、FP与计数边界

原 fused-vdot 完整机器字800B SHA `9a155c33b9f27ca04d68ab3e0d883d6819876db6dc1c5d6f55ba9a3faa435648` 是 shell 的固定参考。新函数预期412B/103条固定宽指令：前60B保持，整数核心 `[60,232)` 为43条，最后45条与原 `[620,800)` 后缀相同，只允许两处分支相对位移改变，逻辑目标仍为函数偏移60/44。后缀包含完整 FP 转换、两个乘法、原次序加法、组/行指针更新、Y输出和最终全部128B slots。

每组仍按原顺序执行 `float(dot)*Wscale*Xscale` 后累加；不使用 FMA，不跨组重排。FP筛选沿用 finite binary32/RNE 模型，独立 row-major C oracle 与整数 binary32 Python oracle 要逐位一致；没有 fflags、NaN/Inf、非RNE、异常/中断恢复资格。

预期整数核心：2条vset、9条whole2 load、8条地址addi、16条dot16、8条vadd，共43条；旧plain16为61条。新完整函数预期动态21090条，其中324次核心、5184条dot16、2592条vadd、2916条whole2 load。静态声明微操作账本为63，仅作为原配置下的源码计数，不是实际发射或周期结论。

本轮只核验完整函数入口到普通返回的机器路径；没有新的计时包装或实测计时区。若以后套用先前timer，必须重新绑定实际链接函数及timer边界，不能把完整函数21090条直接当作CSR区计数。GS32v2的完整函数20123条与其旧CSR区20134条分别比较，不能混用边界。

## 最小验证与三个反例

1. 用固定旧生成器原样生成五个保留函数；分别真实GNU汇编/链接旧集合与附加新符号集合，逐一比较完整函数机器字，保留原 old-dot16 机器字证书。输入源前后SHA一致，输出隔离。
2. 新证书独立解析实际ELF核心，不调用生成器的寄存器/行映射：逐字节跟踪两个whole2目的寄存器、W/X来源和每个乘积的(row,k,k)身份；全部256B W及32B X每组恰读一次，每行32项恰覆盖一次且high96为零；验证FP保护、X净步长、前后缀和两个分支逻辑目标。
3. 八个实际ELF主机输入沿用三个原dataset及0→1→0→2重复调用、全min/min、max/max、min/max与zero-W；后四组含不对齐字节地址。验证完整288个Y、最终八个完整128位slots、精确输入/输出足迹、只读context、ABI/CSR、严格FP顺序和动态路径。旧全域算术边界由范围推导支持，有限输入不是穷举。
4. 只加三个实际ELF反例：高半X错用v14；第二批W在第一批高半dot之前覆盖；后缀X错误保留+16。均由合法机器字修改或重排产生，必须被新证书及数值/完整状态检查拒绝，不以未知opcode代替语义拒绝。保存失败机器字和拒绝原因。

通过后仅交付候选身份供主端与consumer负责人决定目标实验；完整应用须保留更快合格RVV，并独立核对K768路由、量化/packing、调用频率、实际消费者和频率/面积代价。本合同不新增强制的大规模门槛。
