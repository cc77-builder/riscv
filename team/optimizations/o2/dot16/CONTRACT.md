## 1. 目标与候选选择

通过每条指令计算16对 INT8 的精确点积，减少 GS32×8行内核中的加载、寻址、点积和部分和指令。
保留赛题要求的八项 `vdot.vv` 的编码和完整语义。扩展使用另一个精确编码，不修改官方权威程序。
与4×dot4候选相比，单结果dot16沿用已有 `P[tile,group,row,k]` 权重布局，不需要广播gather；
两者都计算16个乘积，但单结果方案的完整软件映射更简单。先验证本方案，保留另一方案的既有数学记录。

## 2. ISA 候选合同

| 项目 | dot16 候选 |
| --- | --- |
| 名称 | `vdot16.vv vd, vs2, vs1`，团队扩展候选，非官方分配 |
| 编码 | `MATCH=0x0e00000b, MASK=0xfe00707f`；funct6=`000011`，vm=1，funct3=000，custom-0=0x0b |
| 源及通道 | 两个完整128位源；lane i 对应 bits `[8*i+7:8*i]`，i=0…15，均为signed INT8 |
| 算术 | 从零计算16项精确点积；不读取旧vd，不饱和、不舍入 |
| 精确范围 | `[-260096,262144]`；乘积16位，逐层17/18/19/20位，最后符号扩展到32位 |
| 目的 | 低32位为补码结果，高96位为零；完整覆盖128位，包括v0 |
| 合法配置 | VLEN=128、e8、m1、vl=16、vstart=0、vill=0、vm=1；所有vta/vma组合合法 |
| 别名 | 与旧dot8一致，所有单寄存器源/目的重叠均允许，按执行前源值计算 |
| 状态 | 保持vl/vtype/vstart/vxrm/vxsat/vcsr/fflags；向量使能检查和置脏沿用处理器机制 |
| 非法配置 | 精确非法指令异常，无目的/CSR部分更新；独立原型仅输出illegal与关闭写使能，尚未形成处理器陷阱证明 |

旧dot8仍精确匹配 `0x0200000b/0xfe00707f`，e8/m1/vl=8，只读取低8字节，高64源位不参与。
两个编码的寄存器位段均为vd[11:7]、vs1[19:15]、vs2[24:20]。
新match与旧match有两个固定bit差异，保留旧单bit邻居非法用例；它只新增一个原先未分配的精确编码。
静态查阅当前实际718项香山译码和固定NEMU主表未见交叠，仍须接入后的真实译码及全核验证。

## 3. 微架构与独立原型边界

单一上升沿时钟；同步高有效复位清除P/R valid，复位周期无输入或输出握手。
源与结果端口均128位，配置随请求在接受时检查；保存tag及目的类别与算术一同移动。
P槽保存16×16位乘积，dot8请求的高8乘积在接受沿置零，后级不需要额外mode位。
R槽有两种待筛选的实现：direct16保存最终32位结果；split16保存两个signed19部分和，输出侧再做20位加法。
对照baseline8使用相同简化控制外壳与8乘积、R32；它不是完整H1 FU或父级PPA对照。

无背压、无取消时：E0接受并锁存乘积，E1进入R，E2首次允许输出握手，理想II=1；该边沿定义与O2一致。
同一边沿可完成旧R响应、旧P迁移及新请求接受。R受阻时保持完整结果和tag；满槽时停止新接受。
任何flush禁止新接受；killP/killR只清除对应槽，未命中的老响应允许继续。
本原型的kill是外部布尔决策，不实现RobPtr比较、真实父级DIV互斥、译码、CSR、NEMU或DiffTest。
因此原型测试只能证明该算术及简化握手实现，不能替代生产FU/G1、父级G2或整核验收。

H1的P是8×16位乘积，R是32位结果；它并非两个可互换的结果队列。split16的R38不能沿用H1的R32结果。
时序比较须列出输入→寄存器、寄存器→寄存器、寄存器→输出的真实路径；加法层数只是设计依据。

## 4. 软件映射与公平比较

一个GS32×8行整数核使用2次16B X加载、16次16B W加载、16条dot16、8条vadd和2次配置，计划为61个32位机器字。
寄存器：X=v16/v17，W暂存=v20…v23，前半结果=v0…v7，后半结果=v24…v31；跨组FP累加v8/v9不动。
归并必须使用e32/m1/VL4，以便原有vmv/slideup形成v10/v11。每个row最终高96位仍为零，末尾完整raw slots保留。
核内X指针推进16B，组尾再推进16B；W组尾推进256B。原FP消费顺序、scale读取、输出/slots和CSR恢复均保留。
计划组内总82字，旧TA为152字，现有fused-rvv4为109字；这些静态数不是周期加速比。

生产候选正确后，以同一新硬件、同一ELF、同一输入/完整Q边界对比dot16、旧TA及较快合格RVV。
保留既有预热/运行顺序、FP32逐位输出、完整slots、CSR、读写范围和ABI检查；再扩大到实际消费者。
分别报告软件、硬件和组合影响，不把局部FU或指令数量替代应用周期，亦不把预打包Q等同完整token。
