# Dot16 complete-Q288 consumer contract v1

Status: implementation and static image review. A build PASS is not target execution.

## Purpose and fixed scope

Connect the existing q288_dot16_vdot to the already built dot16 EMU in a new
four-arm, complete prepacked 288-output Q288 AM image. This leaf reuses the
mature paired16-rvv target archive; it does not edit prior kernels, generators,
judges, official AM libraries, RTL, reference implementation, or frozen runs.

Contract ID: r3-dot16-q288-consumer-v1. Shape M=K=288, group size32, 36 row
tiles, nine groups, eight rows/tile. Context is the original 56-byte RV64/lp64d
q288_context. VLEN128. D uses the existing e8/m1/VL16 dot16 integer core and
returns the original VL8/e8/m1, vstart0/vcsr7 contract. Its low32 sum is exact,
high96 is zero. Strict binary32 conversion, separately rounded multiply by
weight and input scale, and group-order addition are retained. No ISA,
microarchitecture, pipeline, clock/reset, or RTL timing is changed here.

## Reproduction and rollback

image.py takes an explicit base archive, generated dot16.S, frozen helper
and fresh output. It extracts only required source files, reuses the
archive's ELF reader and build record, and leaves both inputs untouched.
Output snapshots retain the input archive, D source, controller and helper.
Runtime entry consumes the completed image; its preflight never starts EMU.

Rollback consists of not selecting this independent image. Published stable
kernels, source inputs and old run identities are unchanged. No deployment.
