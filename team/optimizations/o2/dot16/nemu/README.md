# dot16 的独立 NEMU 扩展候选

操作：`20261106-LiZufan001-dot16-nemu-0638`。接续同账号 WORK `6670578319`、范围 UPDATE `6670959414`；本子目录由主 Pro 维护，其他 dot16 原型由硬件子 Pro 维护。

本候选为后续新硬件差分验证准备独立的指令语义。它不是新的性能结果，也没有把旧 NEMU 或 T17 的资格转移到新编码。当前阶段不改已有 reference 物理目录、官方权威程序、旧补丁、旧验证器或冻结运行输入。

## 1. 输入及应用顺序

1. NEMU 固定基点 `a48a11f208ff81ad765591d83271d1b339fb3861`。
2. 原团队 dot8 补丁 `team/patches/nemu/vdot-s8x8-r32-v0.1.patch` 1.1.0，SHA256 `6c165bf5f94ef0bfb4f894a5f06eb6d620d4a7e0e12f3b1400fa72811f5d24db`。
3. 本目录 `dot16-s8x16-r32-v0.1.patch`，作为第二个、可区分身份的增量补丁；准确摘要及九个最终文件身份见 `manifest.json`。

不能把此补丁直接应用于未安装旧扩展的源码，也不能在一个正在使用的参考目录上补写。`manifest.json` 记录此次实际读取的五个原始 NEMU 文件、旧补丁后七个文件及新补丁后九个文件的 SHA256。两个旧 helper `vdot.h`、`vdot_tval.h` 保持逐字节不变。

规格来源是上级 `CONTRACT.md` v0.1，读取时 SHA256 `425a67aa3eb083609b284737c435c56314662363b32736cd562b0283f87c66bf`。这个身份记录只说明本候选的设计依据，不代表上级后续修改也已经审查。

## 2. 实现边界

| 项目 | 新候选行为 |
| --- | --- |
| 精确编码 | `MATCH=0x0e00000b`，`MASK=0xfe00707f`；主译码独立 custom-0 分派 |
| 合法配置 | VLEN128，e8/m1，VL16，vstart0，vill0，保留位0，向量已启用；vta/vma 均可 |
| 算术 | 从零累加16个 signed INT8 乘积，使用独立标量循环，不复制 RTL 归约树 |
| 两源 | 在目的写入前取得四个64位块；每次位移限定为0、8、…、56 |
| 结果 | 精确范围 `[-260096,262144]`；先取32位补码字段，再零扩展写入128位目的 |
| 别名 | 任意 vs1/vs2/vd 重叠，包括 v0，按执行前源值计算 |
| 非法状态 | 在源快照、目的更新和 VS dirty 之前抛出非法指令；真实陷阱入口另行验证 |
| 旧 dot8 | 原编码、VL8、仅低8字节、完整目的及异常 helper 均保留 |

`CUSTOM_VDOT16` 默认关闭，Kconfig 依赖原 `CUSTOM_VDOT` 与 RVV。新增声明、译码和执行入口均由新开关显式启用。不能把新操作码交给原 OP-V 子译码，也不能用旧 dot8 helper 的八次循环冒充完整128位源的计算。

## 3. xTVAL 平台选择

`CUSTOM_VDOT16_XS_TVAL` 是另一个默认关闭的候选开关，独立于旧 dot8 平台开关。开启后的候选谓词只对精确 dot16、其余配置合法且 VL≠16 的情况选择零 xTVAL；其他非法情况仍走原平台处理。它不读取 DUT 输出、PC、用例 ID 或期望答案，所有 xTVAL 比较保持启用。

这个谓词尚未获得新硬件资格。必须先确认新构建的实际分类、配置依赖、VecExceptionGen、FU 和 TrapInstMod 路径，再通过真正的 M 模式陷阱及整核差分验证确定所需配置。旧 dot8 的 M 模式通过记录不能代替此确认。S/HS/VS 与嵌套虚拟化也没有新增资格。

## 4. 验证层次

第一层只检查补丁和实际 helper 的宿主执行：使用五文件的只读部分源码快照，在新的输出目录应用两层补丁，核对每层身份；编译实际新旧 helper，检查有符号边界、上半源、全部寄存器别名、非法副作用和针对性错误注入。该层的模拟环境不是 NEMU 的真实状态 ABI，也没有证明实际译码、CSR trap 入口或动态链接行为。

2026-11-06 已完成两个新开关状态的真实 NEMU 构建及有界 reference API 验证，详见 [API_VALIDATION_RESULT.md](API_VALIDATION_RESULT.md) 与 [API_CONTRACT.md](API_CONTRACT.md)。开启态实际通过132240个dot16合法、1168个dot8合法及50个非法用例；关闭态和旧库bootstrap分别通过1168个dot8合法及82个非法用例，每态另有普通指令冒烟和两项真实拒错负控。实际库、配置、控制器与原始日志分别绑定，不把宿主helper筛查或旧库PASS转移到新候选。
