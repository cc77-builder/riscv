## 已核对的具体问题

### 1. 没有遗漏 read_liberty，也没有残留 D800

实际原 map 模板第一行已经是 `read_liberty -lib`，随后读取四件 SV、`hierarchy -check`、`synth -flatten -noabc`、原 dfflibmap/ABC、`clean`、`check -assert`。无需额外插入第二次库加载。

`derive_scripts` 只替换原 mapped 输出目录与唯一CSA输入路径，逆变换恢复完整原脚本；原 `-D 1000 -constr` 仍在。控制器又精确核 read_verilog 列表为“一份派生CSA＋三份原RTL”。STA逆变换保持原库、1ns及全部I/O、load、wire-load和五类报告；合同描述与保存的真实模板一致。

### 2. 实际生成的 named pins 已独立检查

本次读到的9,906B版本已包含主端刚补的独立解析：从实际派生文本匹配477条FA实例，重新拆分每个命名端口，拒绝重复/未知引脚；与原始配对的五端口字典逐项比较，并按实际A/B/CI连接重算每对八种二态输入及S/CO。全部实例集合一致，随后从派生文本逐条逆替换并比较完整原字节。

FA函数来自固定cell块的完整CO/S表达式，经过原Parser完整消费和八值检查；cell SHA绑定 `375af4ef…`，控制器此前还绑定完整Liberty SHA。17个HA不进入替换，源级全模块检查仍基于原e6924e40版本。未发现只比较“模板意图”而不检查实际输出的残留缺口。

已保存派生记录给出的93,526B、SHA `3e544a88ed7e4c76161fd93fee96670d262fc140ac615a8763e1a66214b8bcaf` 与该执行路径的字段相符；这是引用现有生成记录，不冒称本审查重新运行了转换。

### 3. mapped 检查是严格但可接受的本实验绑定合同

`audit_mapped` 要求954个真实FA_X1、两个各477的完整后缀集合，使用同实例层次前缀查找原信号netname，逐一比较4,770个实际pin连接；常量1按JSON常量处理。它检查每个CO/S为不同的实际bit且均有消费者，再由控制器核完整ports、1,678DFF、库面积独立求和和原STA输出。

此检查依赖本次flatten后的公开实例/信号名继续存在。如果实际优化删改了实例或名称，绑定检查会拒绝；**这不是目前已证实的Yosys失败，也不应预先绕过。** 若发生，应保留原mapped输出，区分“绑定合同未闭合”与“功能错误/无收益”；不能直接更名、减计数或放宽后把原尝试改称通过。它只影响这个显式FA分支，不涉及正在进行的core/smoke资格。

消费者计数证明的是静态使用，不是动态激活或完整网表等价；代码字段为 `both_outputs_used_cells`，没有虚报动态覆盖。两个完整实例集合加固定其他RTL输入适合本次限定绑定，不需要扩成通用网表等价器。

### 4. 资格与执行边界已分开

结果分别记录原生成RTL未改、映射输入已改、局部二态替换验证、broader qualification不转授和mapped-netlist equivalence未测；`new_chisel_generations=0`避免把Yosys读取SV描述成没有任何RTL处理。未借用旧FU/父级/core的执行资格。

一次map、一次STA沿用原420秒总边界和进程组清理；派生SV、脚本、转换记录及快照都进入前后pin核对。发生映射绑定失败时不会继续STA或输出成功状态。没有自动重跑、扩大预算或生产默认变更。
