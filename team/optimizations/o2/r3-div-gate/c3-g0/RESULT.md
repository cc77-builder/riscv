# C3-G0：最小改法可行性评审

日期：2026-10-25（UTC+08:00）。状态：**评审完成，建议仅保留一次 C3-HF 小范围试验；尚未实施，更未采用。**

当前生产实现继续保留 **O2＋H1＋DIV 取消关钟修复 0f12df6**。C1、C2 的否决结论不变。本轮只读源码和既有成本证据，并运行纯 Python 控制抽象检查；没有修改 RTL，没有新综合、STA、FU/父级仿真、全核/NEMU、周期测试或 GitHub 写入。

## 1. 决定：值得继续到哪一步

值得检验一个新假设：**保留 0f 的全部状态结构与开钟公式，只将浮点 DIV/SQRT 保持寄存器的置位条件，换成在有效可达状态下等价、但不直接含 ready/fire 的条件。** 名称 C3-HF 只表示设计候选，当前没有对应源码提交、生成 RTL 或实测成本。

这个方案直接针对已观察到的浮点保持寄存器 D 端长路径，范围小于 C1/C2。它有明确的逻辑依据和可否决门槛，因此建议允许一次独立试验。若实际功能或任一冻结成本门禁失败，就保留 0f、结束这一轮门控优化，把后续精力转回稳定集成与 T17 干净复现。新的、更大改法不自动接续。

不建议继续的方式包括：重新采用 C1/C2 的局部好数据、同时改两个 DIV 的门控与状态、反复改写布尔式挑选较好映射、放宽阈值或设置例外路径。当前也没有依据预测加速比、实际功耗或比赛分数会提高。

## 2. 为什么只选浮点保持位置位

以下全部为**此前固定父级、固定参考库和约束的历史实测**，不是本轮 C3 测量。

| 指标 | 0f 当前保留 | C1 已否决 | C2 已否决 |
| --- | ---: | ---: | ---: |
| 父级面积（同一参考库口径） | 284614.946 | 284587.548 | 284496.310 |
| 控制状态最差 D 端到达 / ns | 1.930584 | 0.798315 | 0.977028 |
| nominal 父级 r2r / ns | 3.261218 | 3.235859 | 3.296141 |
| nominal VDot r2r / ns | 1.356106 | 1.402385 | 1.378167 |
| nominal ready / ns | 0.247821 | 0.266115 | 0.349254 |
| 五档相对时序超限项 | 对照 | 15/45 | 25/45 |

0f 的三个控制状态 D 端分别为 FP hold **1.930584 ns**、INT hold **1.506153 ns**、divBusy **0.870094 ns**。现有内部筛选线为最差不高于 **1.737526 ns**，超线的是 FP hold，所以没有必要同时改整数保持位。

旧 FP hold.D 路径复用一段同时馈入 FP ICG.E 的组合与缓冲网络：报告可见 18 个 BUF，BUF 弧合计 1.344565 ns。直接网表连接已单独核对。这里说的是**共享组合网络**，并不是一条穿过 ICG E→GCK 的数据路径，也不能将缓冲延迟全部当作可回收收益。

C1 合并双 hold 为 busy/owner；C2 在其上进一步改变两个 DIV 的门控启动条件。C3-HF 保留双 hold 和所有 ICG 公式，只改变一个状态的置位来源，是此前未测试的新因素，不是简单补齐 C1/C2 的二因素矩阵。

风险仍在：新的条件会增加 busy、outValid、VDot、flush 等控制源的消费者；完整父级 flatten/ABC 可能再次重排共享逻辑、扇出和其他路径。源码改动小不等于物理影响小。父级最差 r2r 3.261218 ns 也不是该 hold 路径，因此不能从局部改善推导整核最高频率提高。

## 3. 具体概念改法

下面是设计方程，**不是已经实施的 RTL 补丁**。

~~~text
F_F = 浮点子单元实际 in.fire
H_F = 原浮点 uncer_en_reg
C_F = 原浮点 out.fire OR 匹配 ROB 的 divCancelled

P_F = parent.inputValid AND selectedFloatingDIV/SQRT
      AND NOT divBusy AND NOT anyDIVoutValid
      AND NOT VDotOccupied AND NOT flushValid AND NOT reset

原状态：H_F_next = reset ? 0 : F_F OR (H_F AND NOT C_F)
候选：  H_F_next = reset ? 0 : P_F OR (H_F AND NOT C_F)

原开钟表达式仍为：E_F = F_F OR H_F
~~~

实际实现还须保留 uncertain-latency 适用条件、原接受优先级、RegInit、ckAlwaysEn 和测试使能等外围规则。若先定义只读 Wire 来访问后面声明的 busy/outValid，不能新增状态或复制 ROB。

只改变 O2/VFEX4 配置中浮点 DIV/SQRT hold 的 SET 条件。整数 hold、全部门控表达式、busy/ROB、取消释放、父级 ready、子级 valid、实际 fire、写回、VDot 算术与两槽结构均在保留范围内。SQRT 必须随 vfdiv 功能单元选择一起覆盖，不能只匹配 DIV 操作码。

源码主要锚点为 ExeUnit.scala 的 126–159 行（保持位和门控）、166–186 行（busy/ROB/取消）及 300–334 行（分派和实际握手）。实际变更前仍须向用户说明准确修改点。

## 4. 为什么条件有等价依据，边界在哪里

已封存的 C2-G0 在固定实现、有效初始化的可达域支持：

~~~text
!divBusy => ready_INT AND ready_FP
F_F = P_F AND ready_INT AND ready_FP
因此 P_F = F_F
~~~

由相同初始 hold、相同 reset/release 和相同 SET 条件，可归纳保持位相同。C3-HF 的开钟表达式原样保留，因而在该抽象域中清理边沿和实际事务身份也相同。

这不是任意组合输入上的布尔恒等式，也不是新 RTL 的完整形式等价。无有效初始化时可以出现 busy=0、子 DIV 却不 ready，反例已保留。真实全核共享异步复位与同步成本夹具的初次有效 bootstrap 必须区分；TE=0 动态复位、取消与完成同拍、无关 redirect、输出反压、双 lane 不同步完成及 SQRT 均不能被简化掉。取消拍继续由旧 hold 供应清理边沿，不能用 flush/kill 提前切断时钟。

## 5. 本轮实际完成的检查

纯 Python 工具固定导入已审查 G0 状态模型和 0f 源码身份，枚举到可达集合闭合。两种假设方案（只改 FP hold、同时改 FP gate+hold）各检查两种复位合同。后者仅用于审查比较，**没有被选为后续试验**。

六种故意错误变体均被拒绝：遗漏 flush、VDot、busy、reset、SQRT，以及取消拍屏蔽时钟。遗漏 reset 的 hold-only 负控命中的是 P=F 合同失配，不能夸大为已发现该假设 RTL 的复位故障。无有效 bootstrap 的域外反例单独保留。

覆盖包括 DIV/SQRT 双 lane 偏斜、响应反压、匹配/无关取消、取消与完成/复位重叠、TE0 活跃复位、VDot 阻塞和 reset+valid。四组重叠状态不能相加成 RTL 覆盖率。没有重跑旧 G0 全套，更没有获得 C3 的真实 FU/父级资格。

两个独立 Agent 分别审查协议与投入价值；主 Agent 校核原始来源、方案边界和文件身份。Agent 审查不代替团队成员人工确认。旧 G0 的 65 项来源中，64 项现场不变；AGENTS 文档后续增补导致初次全匹配 FAIL，随后用此前已封存的历史文档恢复来源核对，初次失败与解决记录均保留，没有豁免生产源码漂移。

## 6. 后续一次试验的建议合同

这部分是下一步安排，**本轮未开始实施**。

1. **C3 实现与源码核查**：从 0f 建立独立身份，修改前说明；只实现 FP hold SET 的 F→P，保留其他表达式。检查生成物、P 的输入与全部真实接受/ROB 同拍绑定，不把旧 C2 PASS 直接转授。
2. **局部功能门禁**：状态/时钟等价、完整 128 位结果、身份与异常、FU/真实父级、DIV/VDot 切换、反压、ROB wrap、匹配与无关取消、复位及 SQRT 双 lane 偏斜；观察负控须继续有效。
3. **同约束成本筛选**：功能通过后，只做一版同库同工具的完整父级综合及五档 STA。保留三个控制状态的全部 D 端查询；最差 D≤1.737526 ns，面积≤284899.560946，45 项路径各自≤基线101%，原正 slack 的 ICG 检查保持非负，未知单元为0、三个 ICG 完整。沿用原合同对具体端点、负载、周期和时钟的定义；C3 明确保留两个 hold，不能照搬 C2 的“旧 hold 应消失”结构检查。不删除失败项、不重新选择基线。
4. **通过成本才进入全核**：新全核构建、NEMU 差分和同镜像周期不退化，分别固定源码、EMU、NEMU、镜像与观察器身份；全部通过后再决定采用。
5. **任一关键门禁失败则停止**：保留失败记录和 0f；不自动扩大为 gate+hold 或双 DIV 重写，不通过改门槛/false path/挑映射重试。若以后有新的具体证据，再单独立项评审。

这些是项目内部工程门槛，不是比赛官方面积或频率要求。当前布局前参考时序尚未达到绝对 1 ns 收敛；任何通过也不等于整核 Fmax、功耗或得分保证。
