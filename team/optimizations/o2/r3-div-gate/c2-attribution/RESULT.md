## 1. 整数 DIV 门控退化来自哪里

父级当前的接收规则要求**整数和浮点 DIV 都 ready**。因此，整数 DIV 的时钟启动也经过浮点 DIV 的 ready；这是真实设计依赖，不是 STA 误接了一条无关路径。C1 只是更换保持状态，没有消除这条依赖。

生成逻辑可整理为：

~~~text
P_j = parentValid & selected_j & !divBusy
      & !intOutValid & !fpOutValid & !VDotOccupied & !flush & !reset

fire_j = P_j & intReady & fpReady
E_int(C1) = fire_int | (divBusy & !ownerIsFp)
E_fp(C1)  = fire_fp  | (divBusy &  ownerIsFp)
~~~

原修复版 E 是 fire OR 对应保持位。两版实际接收规则相同。精确源码位置、生成方程和 reset／ROB 边界见 [语义审查](evidence/review-semantics/SEMANTICS_REVIEW.md)。

### 接收控制与大量寄存器写入选择共享缓冲网络

| 项目 | 修复版 | C1 |
| --- | ---: | ---: |
| 整数 DIV ICG.E 最差到达 | 1.128021 ns | 1.727299 ns |
| 所报最差路径的 BUF 数量 | 8 | 19 |
| 这些 BUF 弧延迟之和 | 0.595722 ns | 1.366627 ns |
| 路径中的主要接收控制分发树根 | c103／AND2_X1 | c100／OR2_X1 |
| 从树根经 BUF 可到达的非 BUF 输入端 | 697 | 563 |
| 其中 MUX 选择端 S | 675 | 524 |
| 整棵 BUF 分发树的缓冲数 | 77 | 62 |
| 分发树最大缓冲深度 | 5 | 16 |

这里的分发树只沿 BUF 走，到第一个非 BUF 单元输入即停止；它不是整个组合锥，也不把末端输入电容之和当作根驱动器实际承受的 STA 电容。根节点的逻辑极性／分解不同，不能把两棵树当作同一布尔节点的严格一对一替换。

直接可见的事实是：**负载数量和缓冲总数变少，关键分支仍可能变深、变慢。** 门控端与大量 MUX 选择端共用分发，C1 的整数 ICG 处在更深的分支末端。675／524 个选择端包含寄存器写入选择；这不是“新增 owner 位本身有数百个直接负载”。

浮点 ready 的上游 BUF 分发端点为 340→336、最大深度都为 22；两版都已有高扇出 ready 网络。额外退化主要沿接收控制后段的分发链出现，不能归因于简单的“ready 总负载增加”。

这支持调查**如何让门控启动项与实际寄存器接收选择项在结构上分离**。复制一根 Wire、重命名或抽成普通模块不够：当前流程会 flatten 后统一 ABC，等价组合表达式可再次合并。原始每级扇出、消费者及库输入电容见 [graph-01](evidence/graph-01/summary.json) 及其 before／after 明细。

## 2. ready 与 VDot 的退化不能忽略

**ready：相同起止点，同为四级组合逻辑，无 BUF。** 门型由 NOR2→NAND2→NAND3→AOI21 重排为 INV→NAND4→NAND3→AOI21；第二级负载由 5.056053 fF 增至 7.623661 fF，四级单元弧总延迟增加 18.290 ps，几乎解释全部 18.294 ps 到达增量。完整反向锥的 86 个输入／时序边界语义位相同；包含旧有 divBusy，不包含 owner 或旧 hold。

**VDot：源 SV 未改，映射后的同端点路径确实也退化。** 为排除“最差起点由 lane4 换成 lane6”的混杂，本轮对两个起点分别做了固定端点 STA：

| 起止点 | 修复版到达（ns） | C1 到达（ns） | 增量 |
| --- | ---: | ---: | ---: |
| pProducts_4[1] → rPacket_res_data[18] | 1.356106 | 1.401305 | +45.199 ps |
| pProducts_6[1] → rPacket_res_data[18] | 1.355025 | 1.402385 | +47.360 ps |
| io_out_ready → io_in_ready | 0.247821 | 0.266115 | +18.294 ps |

VDot 结果位反向锥的 169 个边界语义位相同，busy、owner、旧 hold 均不在其中；原最差路径 BUF 都只有一个，BUF 弧和发射 DFF 弧相同。证据支持**未改算术逻辑在整体映射中发生重排**，不支持“owner 解码直接串进 VDot 数据路径”。

同端点退化说明不能只归咎于最差路径换了起点。也没有证据可把它称为随机噪声并忽略。C2 即使改善整数 ICG，仍须通过完整 ready、VDot 和各 ICG 门槛。[旁路路径审查](evidence/review-side-paths/REPORT.md)保存了结构边界和完整指标。

## 3. 值得验证的 C2 新假设

建议只继续一个假设：**对固定 DIV 实现证明空闲就绪不变量，再考虑仅为时钟启动使用不含 ready 的 P_j。**

待证明条件可先写为：

~~~text
有效初始化与父子协议成立时：
!reset && !divBusy  =>  intReady && fpReady
~~~

也可证明更弱且足够的 `P_j => intReady && fpReady`。如果条件成立，则 `P_j == fire_j`，以 P_j 启动门控可以逐拍保持原时钟行为，同时实际 dispatch、child.valid、parent.ready、接收、ROB 更新和完成／取消协议全部保留。

这个方案与 C1 不同：它利用**时序可达状态**来移除门控启动锥的 ready 依赖；不是继续调整同一份 owner 布尔表达式。C1 的 busy／owner 可作为隔离候选的结构起点，但新候选仍应相对获保留的 0f12df6 比较，不能先把 C1 当成已采用基线。

本轮只读证据：

| 检查 | 结果 |
| --- | ---: |
| 复用历史父级轨迹 | 35075 拍 |
| 非 reset 且 divBusy=0 的采样 | 17666 拍 |
| 上述采样中任一 DIV 不 ready | 0 |
| P_j 对应实际 DIV 启动 | 1744 次 |
| P_j 与实际 fire／门控差异 | 0 |
| 6144 个布尔组合，在新不变量约束下 | 4992 个组合，差异 0 |
| 不施加新不变量的组合反例 | **12 个** |

**这是可行性证据，不是 RTL 不变量证明。** C1 的保守抽象域允许“父级无 busy，但子单元暂时未 ready”；在该域里直接删除 ready 会失败，不能借用 C1 的 PASS。

另一种简单写法“parent valid 且选中就提前开钟”，在历史轨迹投影中多开钟 **5321 拍**，直接否决。也不建议寄存 ready／门控导致首拍协议改变，或用 cancel 直接遮断必须送达的取消边沿。

## 4. C2-G0 的范围与停止条件

下一步只做可机检的控制状态证明和环境合同核对，尚不写生产 RTL：

1. **初始化和门控复位。** 证明有效 bootstrap 确实把复位送到每个 DIV；核查全核实际 reset／TE 分发。ClockGate 不自动用 reset 旁路。现有 DIV 动态复位用 TE=1，不能冒称已覆盖所有 DIV TE=0 情况。
2. **取消身份绑定。** 证明父级 divRobIdx 与子单元保存的 ROB 来自同一接受事件，匹配取消当拍两者都收到有效边沿；包含 ROB 回绕、无关 redirect、完成与取消交叠。
3. **浮点双 lane 和 DIV／SQRT。** 建模不同完成时刻、输出反压、特殊值和 early finish；先结束的 lane 必须等另一个 lane。不能只证明一个普通除法 FSM。
4. **机器检查及反例。** 用固定源码可追溯的控制抽象或实际控制 RTL，建立初始化与归纳步；完成延迟可非确定，但每条 reset／flush／accept／finish 转移必须有源码依据。仅重放旧日志或在模型里直接假定结论不算通过。

发现任何**合法环境**中 P_j=1 且任一 ready=0，就停止这个写法；不得改成容许额外脉冲，也不得为了消灭反例静默收窄真实使用环境。若证明代价超出有界控制分析，关闭门控探索，转向已规划的应用优化。

G0 真正通过后，才向用户提前说明 ExeUnit.scala 的具体改法并创建独立 C2；重新经过状态／FU／真实父级（补实际 SQRT、双 lane 和必要 reset 覆盖）→同约束父级面积／五档 STA→合格才全核。C1 的控制状态目标、所有相对路径容限和面积门槛不因本次归因放宽；具体 C2 主指标须在实现前另立合同。**本轮没有开始 G0 证明或 C2 RTL 实现。**
