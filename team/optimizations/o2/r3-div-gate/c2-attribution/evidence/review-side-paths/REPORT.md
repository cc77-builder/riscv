# C1 ready／VDot 连带退化：只读归因

2026-10-25。对象为基线 0f12df675378556670afd0dd2153f47fcb330610 与 C1 3be0e3d9e500bd1aa772bcc8d4f8b023a2877c66 的既有父级网表及 STA；未修改生产 RTL，未启动综合、STA 或功能回归，未修改冻结材料和 GitHub。

结论：**ready 与 VDot 的退化有直接网表证据，但不是把新 busy／owner 解码级串进 VDot 算术路径造成的。ready 的最差路径门型、负载发生重排；VDot 的最差起点及算术映射发生改变。这两项不能靠“修好整数 DIV ICG”就宣称已恢复。** 若主分析找到可隔离的 DIV 接收／门控负担，C2 仍须保留完整父级 ready／VDot 时序门禁，不能缩减为只看 ICG 或控制寄存器。

## 1. ready：相同起止，四级逻辑重排

两版最差路径均为 io_out_ready → io_in_ready（输入／输出各自同约束），输出到达由 0.247821 ns 增为 0.266115 ns，增加 18.294 ps。两版都只有四个组合输出弧，没有 BUF 输出弧。

| 项目 | 基线 | C1 |
| --- | --- | --- |
| 级联门型 | NOR2 → NAND2 → NAND3 → AOI21 | INV → NAND4 → NAND3 → AOI21 |
| 输入 io_out_ready 扇出／负载 | 4／6.984174 fF | 4／7.803934 fF |
| 第一级输出扇出／负载 | 3／5.406782 fF | 3／6.132999 fF |
| 第二级输出扇出／负载 | 3／5.056053 fF | 4／7.623661 fF |
| 第三级输出扇出／负载 | 3／5.416602 fF | 3／5.416602 fF |
| 四级单元弧总延迟 | 147.760 ps | 166.050 ps |
| 最终 AOI21 弧 | 25.472 ps | 26.134 ps |

总增加 18.294 ps 中，单元弧增加 18.290 ps，净互连模型项约增加 0.004 ps。这里的“单元弧”也受输入 slew 和负载影响，不能等同于不受扇出影响的纯逻辑固定延迟；此模型不是布局后提取。

第二级 NAND4 直接一个输入绑定 VDot.pValid，另一个为 io_out_ready 的反相；这段最差路径经过 VDot 接收／推进条件，与“新 owner 直接多了一层”不同。从完整 io_in_ready 组合锥反查到输入／时序边界：

- 基线 128 个组合单元，C1 122 个；减少单元不代表更快。
- 两版均为 86 个边界位，语义集合完全相同；反相 QN 按对应 Q 的取反名字归一后比较。
- 两版均含已有 divBusy 状态，均不含新 divOwner 或旧两个 hold 状态。
- 生产源 diff 未改变 ready／仲裁表达式或 busy 的状态更新优先级。C1 改变 busy 的消费者、删除旧保持状态并增加 owner，这可能通过综合共享和分解选择影响 ready 网络；当前证据未隔离某一个共享消费者为充分因果。

五档既有 STA 的 ready 到达分别为：nominal／period050／period200 都是 0.247821→0.266115 ns；load001 为 0.238594→0.256602 ns；load020 为 0.308999→0.325394 ns。差异并非只由最差起点改变导致；这对起止端本来就相同。

## 2. VDot：终点相同，最差起点与算术图重排

| 项目 | 基线 | C1 |
| --- | --- | --- |
| 最差起点 | VDot.pProducts_4[1] | VDot.pProducts_6[1] |
| 终点 | VDot.rPacket_res_data[18] | 同一语义位 |
| 到达 | 1.356106 ns | 1.402385 ns |
| 所报输出弧数，含发射 DFF | 32 | 35 |
| BUF 数量／BUF 弧延迟 | 1／78.907 ps | 1／78.907 ps |
| 发射 DFF CK→Q | 113.277 ps | 113.277 ps |
| 所报全部单元弧总延迟 | 1.355677 ns | 1.401914 ns |

差异 46.279 ps 中，单元弧增加 46.237 ps，其余约 0.042 ps 为报告累计互连项及六位小数舍入。发射 DFF 和末端 BUF 延迟相同；不是像整数 ICG 最差路径那样增加十余个 BUF。末端 BUF 都接 10 个 OAI21 输入，既有报告均为 21.365347 fF；BUF 前单元都为 OAI21，扇出 5／9.770764 fF。

完整 result_data[18].D 反向组合锥：592→593 单元；两版 169 个边界位且语义集合相同，busy、owner、旧 hold 都不在锥内。VDotElastic.sv 与 VDotReduce.sv 两版字节相同：
- VDotElastic.sv：644169c4c8b51c44b2ad30ee34e02f326519f4eed4bcecd431e81240b44f3790。
- VDotReduce.sv：bac7dbe900674f3e5df88a48f8576b18e26ee632b6a66b207c7e060e9e27fce1。

五档既有报告的这项到达相同。它们来自同一网表，且只改周期／顶层输出负载，因此不能计为五次独立综合证据。

这些事实支持**未改算术模块在整体映射中发生重排，且最差路径选择改变**。不能把“31 个组合弧变34个”写成“相同输入必然多三级”，因为起点不同；也不能把路径上没有 owner 误写成“DIV 修改绝对不可能间接影响 VDot”。

## 3. 同端点补充查询建议

现有报告足以证明筛选失败，但对两个发射 lane 的精确归因仍有选择混杂。若主 Agent 需要追加有界只读 STA，只需使用现有网表、既有 nominal 条件固定以下两组，各版各一份：

1. VDot.pProducts_4[1].Q → VDot.rPacket_res_data[18].D。
2. VDot.pProducts_6[1].Q → VDot.rPacket_res_data[18].D。

ready 已为同起止 io_out_ready→io_in_ready，无需仅为“固定端点”再跑。此子任务没有执行上述查询。后续新查询不得覆盖这份现有证据或替代原有最差路径筛选。

## 4. 对 C2 决策的约束

仅凭这两条路径，不足以立项一种可靠的关钟 RTL 改法；尤其没有证据表明“把 owner 解码改个写法”会同时回收 ready 和 VDot 退化。若 DIV ICG 主分析能找到明确的共享接收负担，并给出不改变接收／取消边沿语义的独立实现假设，可做一次有界 C2 候选；但 C1 的功能通过资格不能转授 C2，且不得因 VDot 源码不变而豁免其时序。

若没有这样的局部机制，应停止该硬件分支探索。已有结果没有证明综合随机性；同工具、同输入的行为变化来自输入改变后全局映射结果不同，不能用“噪声”直接抹去失败或重跑择优。

## 5. 复核入口与边界

- analyze.py：读取既有 mapped.json、instance-binding.json、报告和生成物；只写本目录。
- inputs.json：142 份输入 SHA256，完成后全部复核未变。

- cones.json：组合锥计数与时序／输入边界；无门控时钟物理提取。

- generated-comparison.json：58 份 SV 的全量 SHA256；只有 ExeUnit.sv 与 LogPerfEndpoint.sv 改变。后者综合排除性质已由 C1 原成果说明，本分析不重复新证明。
- production-source.diff：两个固定提交的 ExeUnit.scala diff。
- summary.json、status.json：紧凑指标及执行范围。

所有 fanout/cap/delay 均指 Nangate45 既有 STA 的抽象负载模型；不得据此声称布局布线后功耗、面积或整核 Fmax 的因果结论。
