## 1. 改动与状态关系

唯一生产源改动为 `src/main/scala/xiangshan/backend/exu/ExeUnit.scala`。修改前已向用户说明范围。O2 的浮点／整数 DIV 两份保持寄存器被以下组合信号替代：

- 整数 DIV 保持：`divBusy && !divOwnerIsFp`
- 浮点 DIV 保持：`divBusy && divOwnerIsFp`

沿用现有 `divBusy`、ROB 匹配取消和 busy 的更新优先级；新 owner 位只在 DIV 接收时捕获归属。取消当拍仍用旧 busy 保持时钟，保证子单元吃到取消边沿，随后空闲关钟。VDot 两槽、数据算术和门控表达式未改。legacy／O1 分支未改行为，未另跑这两种模式的动态验证。

前置条件和状态归纳见 [STATE_EQUIVALENCE.md](STATE_EQUIVALENCE.md)，阈值见 [CONTRACT.md](CONTRACT.md)。这是对抽象事件模型的状态等价检查和固定真实轨迹复算，不是全 RTL 形式等价证明。

### 映射归因与限制

DFF 语义别名检查确认两个旧保持 DFF 删除、新 owner DFF 增加。除此以外，整数 DIV 的 `Bypass_final_rem_plus_d_reg[2]` 在 `_16bit_divide_3` 与 `_16bit_divide_1` 之间出现一删一增的映射保留差异，净数量为 0；相应整数除法 SV 字节不变。初版检查器要求“只能删二加一”，因此给出 REVIEW_REQUIRED；这个结果原样保留，不能假称它直接 PASS。后续只读检查保留两处映射及消费者，解释计数，但未证明映射后网表形式等价。

因此“面积减少”是完整父级此次映射结果，不能全部归因为一个 DFF 的物理面积。全局组合映射重排也会影响未修改算术模块的路径。

整数 DIV ICG 最差路径的起点仍是浮点除法 ready 状态。所报路径缓冲单元从 8 个增为 19 个，缓冲弧延迟总和由 0.595722 ns 增为 1.366627 ns。新控制状态 D 端变短，但共享接收／门控网络的映射代价转移到了其他路径。这支持停止此候选，不能推出“owner 编码必然更慢”，也不是布局布线后的物理因果证明。

## 4. 取舍与下一步

按事先约定只筛一个主候选，C1 到此关闭，不继续换约束、重跑择优或追加第二种 RTL 写法。正确性修复仍保留在原 0f12df6 工作区；C1 独立检出和提交用于回看，不进入全核。

本轮带来的有效结论是：busy／owner 编码在已验证条件下可行，也能缩短状态 D 路径，但当前映射下整体代价不合格。没有新的周期、加速比、功耗或全核频率收益。

若未来重新开启关钟优化，应先只读核对“实际 DIV 接收信号→共享缓冲→整数 ICG.E”的扇出与逻辑共享；只有提出能隔离该路径、又保持接收／取消边沿语义的新假设，才另建候选合同。不能直接复用 C1 功能 PASS 作为下一版资格。软件优化及其他已认领工程包不受本轮关闭影响。**本次未实施这些后续修改。**
