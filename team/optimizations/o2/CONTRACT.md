# O2 设计合同 v0.1：VFEX4 内的两槽弹性 vdot 候选

状态：设计评估稿，可作为下一轮原型的约束；尚无 O2 RTL、真实 II=1、全核性能或人工会签结论。2026-10-18，基点 cd866d52d913f0ba21e50846b8b1ecd15287eacc。生产 src 树为 23e7d3115369fbd0094a0be6d98b0fd26ff1a8e7。

本合同选择范围较小的方案 A 作为首个待验证候选：保留 VFEX4、现有不定时延完成/写回接口，在 vdot 内允许两个请求在途。方案 B（迁往固定时延执行路径）仅作成本比较，不能与 A 同轮叠加。实际采用决策见 [评估入口](README.md)，源码依据见 [接口审查](INTERFACE_REVIEW.md)。

## 1. 不变合同与目标

- 指令编码、合法配置、异常、VLEN=128、8对INT8、有符号点积及完整128位结果全部沿用 [现行规范](../../spec/vdot.md)。低32位保存结果的二进制补码，高96位清零；非法请求返回既有 illegalInstr 结果合同并抑制 vec/v0 写使能。
- NEMU、T05的22+10000组黄金数据、原算术乘法/归约结构不因O2而改变；保留原基础版、T14和O1分支。
- 无反压、无重定向、输入持续有效时：接受间隔目标为1拍；接受E0、P到R转移E1、最早响应握手E2，保留2拍最早响应。停止、取消会使外部响应延迟变化，不承诺固定延迟。
- 最多两个未终结vdot请求；在同一时刻至多一个输出。输出保持幸存请求的接受顺序，不能假定接受顺序就是ROB年龄顺序。
- II=1仅为待验证目标，不承诺依赖链提速、每拍实际发射、应用加速或Fmax。

拟新增 elaboration-only 开关 VDOT_O2_ELASTIC，默认0；仅允许与 FUSED_INPUT=1、O1_HANDOFF=0组合。无O2时现有模式完全按原合同生成；非法开关组合必须在生成前拒绝。本轮尚未实现该开关，不能通过设置环境变量把旧EMU当作O2。

## 2. 接口与状态

方案A保留 FuConfig.piped=false、UncertainLatency()；这里piped字段属于现有框架配置约束，不表示新模块内部不能有两个流水槽。该字段若为true，现有FuConfig要求certain latency，不能为名称好看而更改时序合同。

新候选使用独立的FuncUnit实现（可复用VecFuncUnitAlias读取输入），不得直接依赖VecNonPipedFuncUnit的一份RegEnable/DataHoldBypass输出身份；也不得套用要求certain latency的VecPipedFuncUnit。

| 槽位 | 有效状态与数据 | 必须一同保存的身份 |
| --- | --- | --- |
| P：乘积槽 | valid、8个16位有符号乘积、输入合法性 | 接受时的ROB、pdest、vecWen/v0Wen、需要输出的完整vpu控制及perfDebugInfo；字段清单按FuncUnitOutput逐项核对 |
| R：结果槽 | valid、完整128位结果、异常向量 | 从P原样转移的同一包身份，不能从当前输入取得 |

非法请求照常占一个槽并终结一次，不能在算术或元数据通路上提前丢弃。v0与普通向量目的互相交替时，各自写使能及pdest不得串线。所有输出控制、异常及perf信息由R提供；输入在反压期间任意变化也不能改变旧响应。

给父级提供明确的功能状态端口：两个实际valid或其精确occupancy/empty归约。时钟门控和派发使用这些功能状态，不能用printf、调试seq、tap日志或推测的最近一条ROB替代。若父级为验证而保存副本计数，必须每拍断言与FU真实状态一致。

## 3. 每拍转移定义

以下量在同一时钟边沿前计算，ready/valid遵循Decoupled握手。P、R各自调用该请求的 robIdx.needFlush(io.flush)，保留硬件RobPtr的flag与环绕语义。

    killP = P.valid && P.rob.needFlush(flush)
    killR = R.valid && R.rob.needFlush(flush)
    liveP = P.valid && !killP && !reset
    liveR = R.valid && !killR && !reset

    out.valid = liveR
    out.fire  = out.valid && out.ready
    rReady    = !liveR || out.ready
    move      = liveP && rReady
    pReady    = !liveP || rReady
    in.ready  = pReady && parentAllowsVDot && !flush.valid && !reset
    in.fire   = in.valid && in.ready

    nextR.valid = (liveR && !out.fire) || move
    nextP.valid = (liveP && !move) || in.fire

当move为真，R锁存P的归约结果和整包身份；当in.fire为真，P锁存新输入的乘积和整包身份。move使用边沿前的旧P，绝不使用同拍新输入。reset强制两个valid及父级占用清零；无效槽的数据无需清零，但不得影响可见输出。

| 边沿 | 接受 | 槽间转移 | 输出握手 |
| --- | --- | --- | --- |
| E0 | A进入P | 无 | 无 |
| E1 | B进入P | A进入R | 无 |
| E2 | C进入P | B进入R | A |
| E3 | D进入P | C进入R | B |

表中为从空管线开始、持续ready且无取消的目标时序，不是测得的O2波形。已有R但输出阻塞时，空P仍可接收一条；两槽满且R阻塞时拒绝输入。R被取消而P幸存时允许P进入腾出的R；P被取消而R幸存时不能误清R。

重定向当拍统一不接受新请求；未被取消的旧R可正常握手，幸存P可转移。被取消请求的KILL优先于它的RESPONSE，二者不能同时计数。无关重定向不能破坏已有停顿响应。RESET优先级最高，复位当拍无输入/输出握手。计数时使用effectiveKillP=killP&&!reset、effectiveKillR=killR&&!reset；RESET丢弃数取边沿前两个valid之和，reset与flush同拍不能把同一请求同时记为取消和复位丢弃。

## 4. 父级资源、派发与除法切换

当前VFEX4含VDot、VIDiv、VFDivSqrt；共享输出是one-hot选择和ready广播，缺少多FU同时完成仲裁。本候选维持互斥：

1. 有任意vdot在途时，只能向vdot追加请求；DIV禁止接收。
2. 任意DIV在途时，vdot禁止接收，保持已有DIV串行行为。
3. vdot最后响应或取消当拍不切换DIV；在下一拍确认两个槽确实空、无旧vdot输出后，才可接受DIV。
4. DIV完成/取消后也必须确认旧输出已经撤销、子单元具备合法接收状态，再放行vdot；不依赖取消当拍旧DIV valid立即变低的假设。
5. 所有跨FU切换都不得出现两个out.valid同时有效。DIV自身已有取消当拍行为需原样观察并按现有全核合同解释；不能为了让新检查器通过而改写旧预期。
6. 持续vdot到来可能使排空切换延迟；不承诺新的公平调度。混合负载测试须记录等待，有限输入停止后必须能排空并完成DIV。

在O2专用的VFEX4路径局部选择被选FU的ready，或采用等价的原子派发实现；不修改所有EXU共享的Dispatcher语义。现有Dispatcher把所有ready相与，但child.valid并未与总ready相与，不能仅放宽父级busy而让child单独接受。必须断言：

    parent.in.fire == OR(all child.in.fire)
    PopCount(all child.in.fire) <= 1
    child.in.fire -> parent.in.fire && selected(child)

父级不能继续用单个busy和最近输入RobPtr表示多个vdot。vdot占用从真实槽状态取得；DIV占用及身份独立保存。任何一笔vdot响应/取消只释放该事务，不能把另一个在途请求一起“释放”。

输入选择只依赖已注册占用、当前合法选择及下游ready；不得构成valid/ready组合环。选择后未握手的输入仍由上游保存，FU不得提前更新身份。

## 5. 门控、唤醒与写回

- 当前不定时延门控只用一个uncer_en_reg，out.fire且没有in.fire时会清零；O2仍有P请求时这会错误关钟。vdot专用使能必须覆盖当前任一槽有效、当前输入接受以及必要复位/清除边沿。
- 当前槽有效时，即使flush将其全部取消，也必须保留处理本次清除所需的时钟边沿；排空后再关门。父级状态逻辑位于未门控时钟域。
- 只对O2 vdot改门控；DIV及其他EXU保持现状。真实父级测试使用真实ClockGate，不能用常开时钟替代最终验证。必须明确reset在实际门控使能/复位传播中的接法，并覆盖空槽且已关钟时reset、非空时reset、cancel/reset同拍及随后重新唤醒；抽象状态公式不能证明复位脉冲确实到达门控后的寄存器。
- A保留既有不定时延完成/唤醒与实际写回仲裁ready。某次输出未被接受时，R必须保持全包稳定；不得假定写回总是ready。
- 不新增固定延迟提前唤醒、写回预留或旁路承诺。若发现现有issue反馈限制II=1，先记录并评估，不自动扩大到调度重构。
- 若转选B，必须另修合同并重审FuConfig、ctrlPipe、调度/唤醒、寄存器读端口及写回预留；禁止在本合同下悄悄迁移执行路径。

## 6. 观察协议与不变量

另立O2_SCHEMA version=1，以未门控全局周期记录，不让O1单在途检查器“放宽后”兼任O2。每次父级接受产生唯一观察seq，槽间转移携带seq；seq仅用于观察，不参与硬件功能。

最低事件：父级接受与等待（请求种类、选择、ready及阻塞原因）、P_ACCEPT、P_TO_R、R_STALL、R_RESPONSE、P_KILL、R_KILL、RESET丢弃、槽占用、DIV开始/结束和重定向。按周期处理旧事务终结、移动和新接受，保留原始输出顺序，不假设printf先后决定硬件先后。

必须满足：
- 任意前缀：接受数 = 响应数 + 取消数 + reset丢弃数 + 当前在途数；同一事务恰好属于一个终结类别。
- 当前在途数在0..2；两个槽不能持有同一seq；输出来自R中那个身份。
- 幸存输出按接受顺序，不允许重复/幽灵响应；完整128位及异常/写使能与独立模型一致。
- 多槽取消逐笔按ROB年龄判断，覆盖年龄顺序与接受顺序相反、flag环绕、flushItself两种情况。
- 反压保持整个R包稳定；只有匹配取消/reset可以撤销旧响应。
- 父子握手一致，父级out与被选子输出一致，FU输出one-hot，门控不能冻结未终结请求。
- 正常运行结束无悬空请求；主动故障终止只能标部分检查，不能记为完整通过。

定向负控至少包括：交换P/R的pdest或ROB；篡改高位结果；漏取消其中一槽；误杀另一个幸存槽；重复/丢失响应；R反压时修改字段；父子握手不一致；双FU输出有效；有请求时误关钟。区分真实硬件故障注入与日志/检查器故障注入，不以后一种冒充前一种。

性能采用条件：先争取冻结batch128相对O1再降至少10%（362.50→不高于326.25 cycles），这是本合同新增的工程投入目标，不是预言、官方标准或正确性通过线；必须同时报告全部场景，其他保留场景均值退化超过2%先调查。若RVV保持678，这个目标约对应2.078×，正式加速比仍用候选自身实测RVV。达到2×本身不自动通过采用门禁。

## 8. 停止条件与范围控制

原计划O2为额外2–4个工作日的可选投入（按三人各每天约3–4小时估算，构建耗时不保证）。原型阶段若发现必须大改重命名/调度/通用写回，或正确性回归超过一天仍无法缩小范围，暂停扩展并记录证据，保留O1。不得挤占T17独立复现与最终交付。

如果旧日志无法量化供给/仲裁瓶颈，仅补最少的定向诊断或观察信号；不能把未知周期全部归为FU等待。若G1/G2无法在本范围兑现II=1，先重新评估路线，不连续叠加算术压拍、换执行单元及写回优先级修改。

本轮交付为评估工具、结果和本合同；未实施上述G1–G5。后续实施另起任务及输出目录，旧证据不覆盖。正式报告继续后置，工程记录随开发保存；核心接口按团队约定由另外两名成员确认，自动审查不代签人工ACK。
