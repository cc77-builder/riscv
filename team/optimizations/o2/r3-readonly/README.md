## 2. 为什么不优先裁剪元数据

按 H1 Nangate45 公共接口映射实际 DFF 计数：

| 存储 | 独立完整 FU | 完整 VFEX4 中的 VDot |
| --- | ---: | ---: |
| P 槽八个16位乘积 | 128 | 128 |
| R 槽结果 | 32 | 32 |
| 两槽 valid | 2 | 2 |
| 两槽必要控制 | 36 | 36 |
| 两槽 VPU 信息 | 390 | 0 |
| 两槽 perfDebugInfo | 1154 | 1154 |
| VDot 相关合计 | 1742 | 1352 |

完整 FU 面积为17298.246 μm²，完整 VFEX4（含整数／浮点 DIV）为284879.882 μm²、17171 DFF。这里不是整核面积。

**VPU 的390个 DFF在父级成本网表已经被裁掉。** 在独立 FU 中手动删包，只会改变该边界的观测接口，不能再宣称父级净省390个 DFF。

perf 的两份577位包在公共父级中确实较大，连同确认独占的保持 MUX，已有局部存储成本为7367.136 μm²，占该父级2.586%。但这只是现存单元归因，不能当成可获得节省：

- 实际 H1 全核的 DataPath.sv 明确把 VFEX4 的全部十个 perf 输入接为常零。源头 ExuInput.fromIssueBundle 没有复制 perfDebugInfo。这是诊断连接缺口，不能包装成已经设计好的轻量模式。
- 全核 SV／EMU C++ 仍有这些状态声明；没有整核映射结果，既不能断言最终全部消除，也不能把公共测试接口的1154 DFF当整核真实成本。
- ROB 使用多项时间信息做统计，公共 FU／父级测试和观察器也有完整非零身份合同。旧 writebackTime 虽在 CtrlBlock 重写，删除它仍需新诊断合同；不能靠削弱测试获得面积数字。
- 真正必要的控制已只有每槽18位：ROB 7、pdest 8、两写使能、illegal 1。它们负责独立身份和异常，不能合并两槽或用同拍输入重建。

建议保留当前接口。perf 上游连接可单独登记为诊断增强任务；既有 mcycle 性能窗口不依赖这些标签，不能因此否定已有周期结果。任何修接线实验都要与面积优化分开，绑定新的构建身份。

## 3. 值得优先做的门控修复

当前 O2 VDot 使用 P/R 实际占用作为时钟使能。任一槽有效时保留清理边沿，接受新请求及 reset 可以唤醒；这已覆盖两槽部分取消，不应改回旧 O1 的单事务忙标志。

问题在共享 DIV：uncer_en_reg 接受时置位、完成响应时清零，取消后可能没有响应，从而长期保持开钟。现有 divBusy 已清除，并不等于该时钟保持位也被清除。

| 已封存父级观测 | 当前 H1 | James 历史 O2 修复 |
| --- | ---: | ---: |
| 36组 DIV 取消后108拍空闲采样的多余脉冲 | 72 | 0 |
| VDot 时钟边沿 | 14851 | 14851 |
| VIDiv 时钟边沿 | 12875 | 11094 |
| VFDiv 时钟边沿 | 9078 | 7535 |
| 每条迹线帧数 | 34356 | 34356 |

两条迹线的非 clocks 事件字段逐帧一致，DIV 总边沿少3324。当前测试只累加 cancel_idle_clock_on，没有强制其为零，因此功能 PASS 与72个多余脉冲可以同时存在。James 严格测试有取消后关钟失败→通过的历史证据。

**这些数字说明无用时钟活动和检查缺口，不是功耗百分比或 CPU 加速比。** James green 使用 H1 前的128位 R 存储；当前 H1 与修复的组合尚未验证。也不应整体搬入其观察器／ROB／构建改动。

建议最小候选只在 O2 模式下复用 divBusy/divRobIdx 的 needFlush 条件清理 DIV 保持位：

1. 取消当拍保留真实 DIV 的清理边沿，之后空闲关闭；只有命中正在执行 DIV 的 ROB 才清理。
2. VDot 两槽占用门控保持，legacy/T14/O1 路径保持，减少新验证范围。
3. 下一请求能正常唤醒；取消／反压／reset／非取消 redirect、ROB 环绕及跨 FU 切换分别验证。
4. 把取消后空闲脉冲为零升级成严格门禁，不能仅计数后继续 PASS。

## 4. 时序路径说明：先确认是谁慢

既有公共接口映射使用 Nangate45 typical 25°C／1.1V，ABC D1000，同网表扫五档周期与负载；理想时钟、经验线负载，非布局布线。1 ns 是内部比较约束，不是官方达标线。固定约束和全部读数见[成本时序分析](timing/FINDINGS.md)及[CSV](timing/timing-all-profiles.csv)。

| H1 nominal 路径 | 到达时间 ns | 判断 |
| --- | ---: | --- |
| 父级 VDot 输入→乘积寄存器 | 1.511395 | 点积乘法路径 |
| 父级 VDot 乘积→结果寄存器 | 1.345889 | 点积归约路径 |
| 父级 out_ready→in_ready | 0.295424 | slack +0.554576 ns |
| 所谓 vdot_r2o | 2.832115 | 从 rValid 到 fflags，共享仲裁／DIV输出链，不是点积数据延迟 |
| 全父级最差门控 | 1.855397 | VFDiv FSM→VFDiv ClockGate，非 VDot 门控 |

ready 在五档均有正 slack；20 fF时相对B0回退89.237 ps，但仍有+0.436208 ns余量。当前已做到无停顿 II=1，贸然注册 ready 或加槽会改变反压／取消合同，尚无周期收益依据。

父级整体时序尚未在这些约束闭合，不能忽略；也不能把其最差路径全部归咎于 VDot。既有 gate_enable 报告只覆盖三门控端点中最差一条，没有各门控的独立最差报告。后续修 DIV 门控须复测同约束 STA，尤其关注新增取消逻辑，不承诺会消除原最差路径。

继续32→19位最多先减少13个存储位，裸 DFF成本58.786 μm²，仅相当于父级0.0206%；还需符号扩展、映射变化和扩展能力验证。当前暂缓。

## 5. 若目标是继续提高加速比

由 S1 已封存12个16×64 core/endtoend 进程重算96个正式 vdot 窗口，全部响应延迟为2周期，写回阻塞事件为0。S1 reuse/endtoend 这12个窗口：

- 平均701.25 cycles、665条退休指令，每窗128次点积。
- 1524个相邻接收间隔中，1152个为1拍、348个为13拍、6个为14拍、18个为15拍。
- 说明组内已经能连续接收，组间仍有供数／配置／依赖开销可调查。不能仅凭间隔认定全是 load 或 vset，也不能从窗口减去接受跨度就算出可节省周期。

这些是旧 S1 测量窗，不是 R4 新 C caller 的最新周期基线，不能混表比较。详细重算结果见[application-diagnostic.json](application/application-diagnostic.json)。

已有 firstdot 静态探针以首个 dot 直接初始化输出，去掉清零及首块相加。reuse/core 静态指令数为4×8：28→18，8×32：168→148，16×64：622→582。16份 AM ELF、8对布局、576次有限模型验证只是可行性证据，尚没有动态周期收益。

后续软件实验沿[已有首块初始化子项](../r2-vector-accum/VALIDATION.md)建立独立运行合同，先做8×32／dataset0／endtoend，与原 S1 及最快同入口 RVV 配对；验证实际目的寄存器改变后的拒错与正常恢复，再扩大尺寸和数据集。不要为等待该探索而阻塞 T17／稳定版本闭环。

## 6. 后续候选排序与停止条件

| 顺序 | 候选 | 预期价值与验收 | 本轮决定 |
| --- | --- | --- | --- |
| 1，硬件 | O2 DIV 取消保持位清理＋严格空闲门禁 | 减少已观察到的无用活动，完善工程验证；功能／周期不退化，新增 STA 代价可解释 | 建议下一项最小实现，尚未改 RTL |
| 可独立推进，软件 | firstdot 初始化 | 目标是真实 endtoend 周期；须胜过原 S1，并保留最快同入口 RVV | 从已通过静态探针接续，不重复探针 |
| 后置诊断 | perf 输入连接与非零全核观测 | 修复诊断链可信度；单独合同及受影响配置验证 | 不与面积候选混做 |
| 暂缓 | 删除 perf/VPU、压缩身份、19位结果 | 父级已消除或整核收益不明，风险大于现有收益依据 | 保留现有实现 |
| 有条件再开 | 反压停钟、乘法输入隔离、流水重构 | 先有代表性活动／关键路径／应用瓶颈依据，再付验证成本 | 不因出现空闲边沿就直接改门控 |

VDot 原父级迹线有872拍占用但未接受／移动／响应／取消／reset的停滞时钟，其中双槽559、仅R313。它只是诊断性活动上界；既有寄存器已有写使能，额外停钟可能把 ready/kill 接到时钟控制路径并影响断言。乘法器输入直通也可能在关钟时组合翻转，但没有活动与功耗模型，暂不承诺节能。

下一最小硬件实验的明确终点：

- **先证明测试能发现问题**：当前 H1 在新严格空闲门禁下出现预期失败，保留原始记录。
- **再验证修复**：同10022组向量、完整128位结果和非零身份，FU／真实父级覆盖正常、反压、取消、DIV切换、复位、部分取消；II=1、首响应2拍、16类父级读回负控保持。
- **通过局部再扩展**：新硬件身份重建并做受影响全核／NEMU差分与同镜像周期不退化；同工具同约束面积／STA，记录每个门控端点。
- **采用／停止**：严格门禁通过且无未解释功能、周期或时序退化才采用；不能以旧 James PASS 或本轮只读 PASS代替。若引入无法合理解释的代价，保留 H1基线并关闭或仅作一次有依据的修订。

本轮结论是“R3 调查完成，选出下一候选”，不是“R3 优化已经实现”。现有 T17 固定输入、原始运行和默认入口保持；本轮不提交、不推送 GitHub。
