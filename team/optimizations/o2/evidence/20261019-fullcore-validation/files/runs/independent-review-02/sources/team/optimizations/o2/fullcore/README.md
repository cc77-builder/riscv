1. 新 O2 MinimalConfig 单核 EMU，复用冻结正常 NEMU 与 flash。
2. 原 hello/vadd；117 个唯一功能/异常用例（八片执行 124 次）；bit100 故障参考库实际拒错，随后同镜像正常参考库恢复。
3. 原 F2v 控制程序独立满足七项既有覆盖；冻结 dense 程序验证完整状态和 12 个窗口，并出现两槽并发与三事件同拍交接。
4. 新定向诊断验证相同/不同输入、1/2/4 路、真实依赖链以及 vdot/VIDiv/VFDiv 切换。补充控制程序扫描投机取消与写回竞争。
5. 全部正常运行无悬空 FU/ROB 事务，完整 128 位结果、身份与元数据一致。六项新覆盖逐项绑定到实际运行来源：两槽并发、三事件同拍交接、满槽输出反压、P 取消、R 取消、两槽部分取消。
6. 保存分离的 stdout/stderr、真实退出码、精确命令、输入和工具摘要。离线工具重新读取原始字节核验，不能直接接受运行结果文件中的 PASS。

故障参考库运行仅进行部分轨迹审计，不计入正常覆盖；新诊断不能替代冻结矩阵。G1/G2 的 reset、反向年龄及 VFDiv 覆盖不自动算作本轮全核覆盖。G3 不测 O1/O2 公平加速比，也不产生 PPA、最终采用或人工 ACK 结论。

## 工具

- [观察协议](SCHEMA.md)：新的 O2 两槽全局时钟事件，旧 O1 观察器与证据保持原样。
- [补充程序说明](WORKLOADS.md)：构建、逐寄存器检查、冻结镜像和诊断边界。
- `build_fullcore.py`：检查提交及依赖身份后构建；存在旧 build/ 时拒绝覆盖。
- `run_suite.py`：冻结输入预检和十二项原有作业；退出正确性与六项新覆盖分别记录。
- `run_supplements.py`：新诊断的真实 EMU 驱动与逐项来源记录。
- `recheck.py`：对原始日志、Git blob、工具、镜像与参考库重新核验后做 G3 联合判定。
- `analyze.py`：从接受的源向量独立复算点积、逐拍恢复 P/R、绑定 ROB 分配/提交/取消。
- `check_control.py`：检查原 F2v 完整状态与七项既有控制覆盖。

构建默认两个编译线程、12 GiB JVM、单线程 EMU；同一时间只运行一个重构建。回归最多并行两个 EMU，单项超时保留原始日志且判失败。复现应先阅读脚本帮助，使用新输出目录，不能覆盖已经封存的运行。
