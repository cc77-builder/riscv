# R2-S1：向量累加的寄存器与 RVV 对等方案

2026-10-21，设计审查。**未实施 S1 生产内核，未进行 S1 EMU 或周期实测。** 写入仅限 zjhwork2。S2 保持单一尾部改动，不混入 S1，便于分别评价收益。

## 1. 解决寄存器已满的问题

不增加四个 scratch 寄存器，而使用当前四行本来就要写出的输出向量 `v[first]..v[first+3]` 作 INT32 累加器。first 依次为 0、4、8、12，已完成组的输出不再改写。每组仅初始化自己合法的输出，不能清空尚须保护的寄存器。

以 16×64/reuse 为例：

| 活跃对象 | vdot S1 计划 | RVV 对等计划 |
| --- | --- | --- |
| 当前四行输出/累加器 | v[first]..v[first+3] | 相同 |
| 四行 A 载入 | v16..v19 | 相同 |
| 部分积/部分和 | v20..v23（四个 dot8 结果） | v20:v21、v22:v23、v24:v25、v26:v27（四组宽乘结果） |
| x 预载块 | v24..v31（八个 dot8 块） | v28..v31（四个最多 16 项块） |
| 临时寄存器总预算 | 仍为 v16..v31 共 16 个 | 同为 16 个 |

`candidate.s1_register_plan()` 对三种整块 K、四个行组和两种方法检查分配区间、重叠及 scratch 上限；在已声明输出寄存器中累加，不是暗中扩大临时寄存器预算。4×13 的 S1/S2 联合方案另行评价，不在本轮合并。

## 2. vdot 路径

每组开头在 e32/m1/VL=4 下将四个输出向量完整清零。每块仍按原方式加载及计算 dot8，之后切换 e32/m1/VL=4，用 `vadd.vv` 把部分和累加到对应输出。

```asm
# 示例，仅为设计片段；不代表本轮已生成或验收的新内核
vsetivli zero, 4, e32, m1, tu, mu
vmv.v.i v0, 0
# ... 原 e8/VL=8 加载和 dot8，使部分和在 v20 ...
vsetivli zero, 4, e32, m1, tu, mu
vadd.vv v0, v0, v20
```

 dot8 的架构结果低 32 位为有符号和、高 96 位为零。四个 e32 lane 累加时，lane0 累加结果，另外三 lane 为 0+0，保持零；不需要把 128 位整体做符号扩展。原每块的 `vmv.x.s`/`addw` 和最终 `vmv.s.x` 具备消除机会，但要计入新向量加法和依赖链。

无符号按位加法的低 32 位与 INT32 二补码加法一致；本合同 K≤64 的精确和范围为 [-1040384, 1048576]，不存在 INT32 溢出。不能用 INT16 累加代替。

## 3. RVV 必须获得对等机会

不以旧 RVV 的标量搬运作为固定弱对照。RVV 每块 `vwmul.vv` 后，直接用当前输出向量低 32 位作宽归约的种子和目的地：

```asm
# 示例，v20:v21 为 16 个 INT16 乘积，v0 低32位为累计和
vsetivli zero, 16, e16, m2, tu, mu
vwredsum.vs v0, v20, v0
```

下一块继续以 v0 作种子，不再每块清零临时归约种子、搬到标量再 addw；每组最初仍完整清零输出高位。v1/v2/v3 等输出也可以作为归约标量操作数：归约的标量源/目的只占单个向量寄存器，不受向量输入组 LMUL=2 的偶数起始约束；乘积输入组 v20/v22/v24/v26 仍满足对齐。种子与目的同寄存器是允许形式，不与宽乘输入组重叠。

官方依据：RISC-V V 1.0，30.1.14 及 30.1.14.2：
https://docs.riscv.org/reference/isa/v20260120/unpriv/v-st-ext.html

保持 tu，以保留目的标量之外已清零的高位。保持动态 VL 和最多 16 项的 RVV 能力，不人为限制为 dot8。任何配置切换减少也应对称审查，不能选择较慢 RVV 抬高加速比。

## 4. 已检查与仍需检查

本轮自动检查了所有计划寄存器集合互斥，以及 300 组固定随机输入在 8/16 项块分组下的标量数学累加等价。它们是分配和数学检查，不执行 S1 指令，不证明新向量依赖链的延迟或全核行为。

实施前仍需生成并审计两条完整 S1 路径：检查 v0 输出与未掩码操作、寄存器保护、e8/e16/e32 切换、高 96 位、CSR、整块/尾部组合；实际反汇编必须确认无 spill、无额外隐藏加载保存。随后使用同一编译配置、输入布局、输出格式、计时窗口和硬件，对两个方法分别筛选，再与较快的合格 RVV 比较。

原来 vdot 的 128+128 次搬运/标量累加并不等于可省 256 cycles。改为向量累加可能引入新的向量 RAW 依赖、写回或执行端口竞争；RVV 种子累加也可能提高它的性能。两者相对变化必须实测，不能提前给出收益数字。
