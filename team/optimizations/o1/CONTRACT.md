# O1：vdot → vdot 同拍交接变更约定草案

历史状态：以下草案基于 `3d051f0d` 的实现前静态分析，保留当时约定。当前O1已完成候选RTL、真实父级、矩阵/负控与FTQ/计数窗口验证，默认仍关闭，完整软件/性能与独立复现待完成；审查发现的4项工具门禁问题已修复并复核，见[修复记录](../../docs/o1-gate-fixes-20261018.md)。本文件不是T16最终报告，不改变内部ISA合同。

## 必须共同解决的三处约束

1. `VDot.scala` 当前只在 idle 时 ready。候选仅在旧 vdot 响应真正握手、新输入也是 vdot、没有 reset/redirect 时开放交接。没有 out.ready 时仍保持旧结果和全部元数据。单笔在途，目标最早响应 2 拍、接受间隔 2 拍。
2. `ExeUnit.scala` 的 `!busy` 同时门控父级 valid/ready，现有 busy 更新中 out.fire 优先于 in.fire。候选必须限定 vdot→vdot 放行，并保证旧完成+新接受后 busy 仍表示新请求在途；不能仅改子单元 ready。
3. `VecNonPipedFuncUnit/FuncUnit` 中控制保存方式不同：ROB/pdest 使用 RegEnable，而 outCtrl 的 DataHoldBypass 在 in.fire 当拍直通。旧结果与旧身份必须配旧写使能/异常，新请求只能改变下一事务。优先局部修复 vdot，不修改全局 utility/Hold.scala 来影响其他 FU。

父级不定时延时钟使能当前 in.fire 优先于 out.fire；修改时不得破坏这一点。VFEX4 的 FU 输出是 one-hot 选择，不是多结果仲裁，不能同时开放 vdot 与除法在途。沿途 out.ready 反馈、Dispatcher、OG2 重试及写回路径还需组合环与联调检查。

## 单拍行为验收表

| 前态与输入 | 应有行为 |
|---|---|
| 空闲、合法输入、无重定向 | 接受并快照一次 |
| 运算未完成、输入改变 | 不接受，不改变已接受身份 |
| 响应有效、输出阻塞 | 旧结果及完整控制保持，不接受新请求 |
| 旧 vdot 响应握手、新 vdot 同拍有效 | 旧响应完整送出；新数据/身份锁存；busy 保持新事务 |
| 旧 vdot 响应、新请求为除法 | 不开放本 O1 的同拍旁路 |
| 旧请求为除法、新 vdot | 不开放本 O1 的同拍旁路 |
| 任意 redirect 当拍 | 不接受新请求；旧请求按真实 RobPtr 区分取消与存活 |
| 命中取消与 out.ready 同拍 | 取消优先，不得响应或写回被取消事务 |
| reset 与交接同拍 | 清空有效资格，无新接受/幽灵响应 |

## 测试器不能只改一个 II 常数

现有 `fu_test.cpp` 假定 `!pending` 才 ready；`drain()` 在等待期间持续送 valid 噪声。这些输入在新协议中可能被真正接受。必须让刺激明确表示“无新事务”还是“请求交接”，并让 scoreboard 在同一周期先结算旧响应，再登记新请求。

保留基础版和 T14 不重叠模式。新旧请求交替 vec/v0 目的、ROB/pdest、合法/非法配置、结果高低位；检查输出字段不串单。加入反压恢复当拍交接、连续交接、ROB 环绕、取消/复位和 vdot/除法切换。取消计数、响应计数、复位丢弃与在途数应满足事务守恒。

现有 FU 单元顶层不包含父级 ExeUnit，须新增真实父级联调。O0/T12 旧时钟映射要求前事务结束后才能接受下一事务，不能用于 O1；新协议映射应明确同拍旧结束与新接受，不通过删除旧模式断言得到通过。
