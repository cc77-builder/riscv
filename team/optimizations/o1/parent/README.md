## 本层验证了什么

`GenerateVDotParent.scala` 使用原 `MinimalConfig(1)` 的 VFEX4 配置，真实实例化 `ExeUnit`、`Dispatcher`、busy 寄存器、`VDot`、`VIDiv`、`VFDivSqrt` 及三个 `ClockGate`。没有用定长行为模型替代 DIV，也没有旁路门控。TE 只在复位时开启，功能运行中关闭；生成的门控模块体与 utility 原始 `always_latch` 实现一致。

本轮只新增适配器、测试器、运行脚本及 Mill 目标；相对已发布 `c3c417a`，生产 `src/`、依赖 gitlink、ISA、NEMU、原 22＋10000 黄金向量未变化。两模式都设置 `VDOT_T14_FUSED_INPUT=1`，分别设置 `VDOT_O1_HANDOFF=0/1`。O1 默认开关仍为 0。

适配器只读取真实 busy、子 FU 握手、门控时钟和输出控制。三个 128 位结果总线均核对，连同 ROB/目的寄存器身份、写使能、异常、fflags/wflags/vxsat 和调试标签。`out_ctrl` 是选中子 FU 的 VPU 快照观测口；父级 ExuOutput 本来没有该字段，不能把它称作新增父级写回接口。

## 实际结果

| 指标 | T14 对照 | O1 候选 |
| --- | ---: | ---: |
| 接受事务 | 13493 | 13659 |
| 完成响应 | 12919 | 13087 |
| 取消 | 514 | 510 |
| 复位丢弃 | 60 | 62 |
| vdot 同拍交接 | 0 | 10343 |
| 输出反压拍 | 27725 | 27788 |
| vdot 首次响应延迟 | 2 拍 | 2 拍 |
| 无反压连续 vdot 最小接受间隔 | 3 拍 | 2 拍 |

两模式及各 FU 都满足“接受＝响应＋取消＋复位丢弃”，结束时无未决事务。只有 O1 的 vdot→vdot 可同拍交接；所有涉及 DIV 的切换必须等旧事务退出后再接受。所测 VIDiv 首次响应延迟为 10～14 拍，FP32 DIV 为 8 拍，仅适用于本测试配置和输入，不能外推全部 DIV。

七项 C++ **观测值破坏**（身份、写使能、高位结果、取消泄漏、busy、子 FU 路由、门控时钟）全部由对应断言捕获：故障程序退出 1，严格校验器退出 0。另有 7 项主机测试证明校验器拒绝漏检、错原因、重复/额外行及错误退出码。这些负控没有改写生产 RTL，也不是全核 DiffTest 故障注入。

## 必须保留的边界

1. **T14 和 O1 并非完全相同的边界刺激。** T14 对照在 reset/redirect 周期主动抑制输入 valid，共 1009 次；O1 保持此类 valid 压力，抑制次数为 0。前者是测试采用的保守限制，未证明为真实上游合同。`Og2ForVector.scala:39–49` 按年龄过滤并更新下一拍 valid；`datapath/BypassNetwork.scala:133–136` 直接传递 valid；`Backend.scala:645–652` 和 `NewPipelineConnect.scala:40–50` 按事务年龄在边沿清除流水级，没有对所有 redirect 当拍组合屏蔽 valid。本轮不能判断 T14 所有原始边界组合下的整核安全性。
2. **DIV 取消当拍可能仍有旧 valid。** T14 的 VIDiv/VFDiv 原始取消响应次数为 34/37，O1 为 32/38；VDot 都为 0。测试先核对旧数据和身份，再按取消优先记账，并检查之后无幽灵响应。本层没有 ROB，因此这不是整核提交抑制的验证。
3. **取消后不保证立即关钟。** 两模式均记录 504 个取消后的空闲观测拍仍有门控开启。原 `uncer_en_reg` 在接受时置位、响应握手时清除，不因 redirect 清除。正常完成恢复后全部门控关闭检查通过；本轮不修改这项既有行为，也不声明功耗收益。
4. 未覆盖完整浮点格式/舍入/特殊值、平方根、全局写回仲裁、发射队列、OG2、ROB 提交及新全核 DiffTest。两模式总测试周期为 86759/76640，事务数和边界刺激不同，**不能用其比值计算应用加速比**。O1 尚无新的全核性能、STA/Fmax 或 PPA 结论。
