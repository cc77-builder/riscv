## Standards

- **P1，当前构建与配对验收缺少完整来源约束。** 导入的 O2 入口未覆盖宏及新增/忽略的编译输入，也没有绑定实际原生工具与受限环境。已复用共享 `build_inputs`/`build_recipe`，在构建、运行和比较前后检查完整库存；配对拒绝不同源码、工具合同、错误观察协议及布尔型核数。新 O1 参考构建必须显式指定 `--o2-build`，不能把旧回执补标成新实验。
- **P2，DIV 取消后保留空闲时钟。** O2 的 DIV busy 会清除，原时钟保持位却未释放。新父级检查在原实现上实际失败；修复复用 DIV 所有者的 ROB 取消信号，并在 C++ 和独立逐拍检查器中拒绝空闲残留时钟。这是门控修复，不据此宣称实测功耗收益。

## Spec

- **P1，优化模式删除归档验收。** O2/O3 归档使用 Python `assert`，`-OO` 下未完成状态、路径或字节错误可能被接受。改为显式异常，检查状态、类型、路径、符号链接、编码、库存及原始/存储摘要；新增真实优化模式子进程负控。首轮 O3 失败日志保留。
- **P1，O3 与合并后的共享严格检查器不兼容。** 新运行记录补齐核数/线程身份；O3 固定包装命令使用窄范围适配，仍由共享解析器拒绝重复或覆盖参数。生成器快照只接受明确已审查身份，使用当前生成器重新生成并核对模型、清单和文件，不执行任意快照代码。复审进一步修复了 O2 G4 的不兼容命令包装及遗漏的传递检查器快照；O3 必须显式指定当前 O1/O2 回执和配套校准，校准从原始记录重新验收，旧固定路径不作为来源回退。
- **P2，新导出递归收录旧证据。** O3 工具快照改为当前顶层源码及显式共享依赖，排除历史 evidence 和缓存，并用实际导出清单检查。
