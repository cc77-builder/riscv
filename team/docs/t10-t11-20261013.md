## 本轮实际实现

- 新增精确 `VDOT_VV` BitPat，`MATCH=0200000b` / `MASK=fe00707f`；`RiscvInst.isVDot` 与译码表共用此模式，邻近 custom-0 不成为向量指令。
- 专用 `VEC_VDOT=100110`（未占用的 6 位 split 编号），显式一个 uop/一个 WB，非法 LMUL 不按寄存器组展开。
- 两个向量源使用原编号，旧 vd 与隐式 mask 依赖关闭，保留 renamed VL 源；DecodeStage 既有 v0 源依赖、目的 v0Wen 路由保持原样。
- e8/m1 限制添加到生产 VecExceptionGen；VS Off/vill/vstart 继续由现有分类和异常路径检查，实际 VL=8 在既有 FU 接受时检查。
- 复杂译码末尾再次写 flushPipe，故 vdot 在该最终赋值后显式关闭它；非零 vstart 是非法指令，不通过正常向量完成清零。关闭 blockBackward、部分写回和旧目的依赖。
- VFEX4 增加既有 VDotCfg，不改变 RF 端口、优先级、时钟、复位、FU 状态机、算术参数或 II。沿用真实 RobPtr、整 128 位结果，不实例化 Mgu。
- 新增生产译码 RTL 测试顶层及 Verilator 检查器，覆盖 131072 个寄存器/策略组合、32 种 SEW/LMUL、VS Off/vill/vstart、后续输入配置变化和相邻编码。此测试源码尚未编译/执行，数量是计划刺激，不能当成实测覆盖。

## 接续验证顺序

先在有正常 WSL 和 Git 写权限的会话恢复本轮补丁并形成固定本地提交，核实远端、dirty、资源和子模块。在唯一新 Linux 原生检出中复用历史 tools/env.sh，默认并发2，实时检查内存后选堆大小，避免 make 的默认40G；不要覆盖旧检出/运行目录。

```bash
source /mnt/d/Projects/competitions/2026-10-CIE-RISCV-XiangShan/validation-20261013/env.sh
export BUILD_JOBS=2
# cwd 为实际新检出，VDOT_OUT_DIR 每次用新目录

VDOT_OUT_DIR="$RUNS/decode" bash team/scripts/check-vdot-decode.sh

TEAM_NEMU_BASE_ROOT="$NEMU_BASE" TEAM_NEMU_VDOT_ROOT="$RUN_ROOT/nemu" TEAM_EVIDENCE_DIR="$RUNS/nemu-standalone" bash team/scripts/prepare-nemu-vdot.sh standalone
```
