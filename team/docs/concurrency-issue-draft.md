# 双人 Agent 协调 Issue：任务认领与 zufan 集成

> 已于 2026-10-23 发布为 [Issue #2](https://github.com/cc77-builder/riscv/issues/2)。本文件保留登记模板，实时活动与首次同步结果只写该 Issue，不另建或重复发布。规则依据：[协作约定](collaboration-current.md)、[开发路线](development-route-current.md)、[计分板](../../开发计分板.md)。

本 Issue 平时只记录**哪个经认证的 GitHub 账号认领了哪个准确叶级任务包**及与他人的实际冲突；只有准备向 `zufan` 推送才登记短暂集成窗口。普通包内步骤不需重复登记。

## WORK：开始认领

```text
WORK | <唯一操作ID> | <工作包ID，如 R2-S2> | @<真实GitHub账号>/Agent | <含时区时间>
基点：<完整SHA>；工作区/本地分支：<标识>
范围：<拟改文件、公共生成器/接口、共享输入>
运行/资源：<实际任务ID、输出目录、同机重任务；无则写无>
```

发布后**重新读取**有效认领和最新活动；不同账号同包竞争以较小 GitHub 评论ID的有效 WORK 优先；同账号跨轮直接沿用原有效 WORK，不额外重发 WORK，后来者避让或协商拆包。Issue 非原子锁，不凭旧评论或无评论证明资源空闲。不同包仍检查共享生成器与构建输入。

## UPDATE / READY / DONE / PAUSE / CANCEL

```text
<事件> | <同一操作ID> | <包ID> | <含时区时间>
成果/变化：<简述；实际提交SHA；测试级别和证据链接>
认领：<保留/释放>；受保护运行：<继续/终结/未知，含任务ID>
```

READY 仍保留认领等待集成；DONE/CANCEL 结束认领；PAUSE 必须明确是否释放，未知运行保持保护。不用每日心跳、不用全员 ACK。

同 GitHub 账号的不同 Agent／PPA 轮次可自行接续已有 WORK，无需人工授权或因换会话重复发 WORK/UPDATE；在计分板／结果留自身操作ID及旧 WORK 引用，核实旧进程和隔离工作区，不抢占受保护运行。不同账号接管他人有效认领必须先取得用户明确授权，再用 UPDATE 明确原操作ID、批准接手账号、成果、认领转交及残留保护，接手方 WORK 引用。接管从不自动停止进程或解除输入保护。

## INTEGRATE：只在推送时

```text
INTEGRATE-BEGIN | <操作ID> | @<发布者> | <时间>
目标：cc77-builder/riscv:zufan；预期远端SHA：<完整SHA>
待推候选：<SHA、变更范围>；验证与剩余问题：<链接>
```

```text
INTEGRATE-END / INTEGRATE-ABORT | <同一操作ID> | <时间>
远端当前SHA：<完整SHA>；是否实际推送：<事实或待核实>
验证结果/在途任务：<证据链接>；窗口：<释放/待核实>
```

发布 INTEGRATE-BEGIN 后立即回读全部有效窗口和相关活动，确认自己是唯一有效发布者；推送前再回读并核对远端。对同一目标同时申请时，较小评论ID的有效 BEGIN 优先，后来者用 ABORT 退出自己的申请。已有窗口、首次同步未完成或状态不明时先核实，不凭超时抢占。

长构建与冲突修复在窗口外。仅经当前用户授权、核对最新远端、验证影响后正常快进推送；禁止强推及代签。长时间失联或未回复不视为窗口/包自动释放。

评论积累后可写 SNAPSHOT，标明覆盖到的评论ID/链接，列齐全部未释放认领（含 READY、PAUSE 保留）、全部未结束或待核实的运行保护、全部未结束窗口，并链接最后有效事件。即使任务已 DONE/CANCEL/释放认领，残留运行仍保留。恢复时读完整摘要及后续评论；摘要有缺项或冲突就回读原事件，遗漏不等于释放。无需第二套实时状态表。
