# 香山 vdot 项目当前状况

更新日期：2026-10-20。项目：第二届全国 RISC-V 高水平创新及应用大赛，CIE—香山社区应用创新赛题。

## 1. 当前结论

项目已建立从指令规范、独立数学模型、RTL 算术/FU、香山全核接入、NEMU/DiffTest，到功能回归和公平周期测试的完整技术链路。基础开发已完成，当前处于优化、代价评估和最终复现准备阶段。

**后续开发主线采用 O2 两槽弹性 FU。** O1 保留为冻结对照与回退。O2 的现有功能和周期收益已有证据，但最终参赛模式尚须完成 O5/T17、成员复核和 G5 采用冻结。源码默认开关尚未切换；构建时必须显式选择实际模式。

正式三阶段报告、答辩和演示继续遵循“工程完成并冻结后集中编写”的安排。已有工程记录和原始日志持续保留，本文件是项目状态快照。

## 5. 关键实测结果

### 5.1 O1/O2同镜像公平周期

| 场景 | O1 vdot cycles | O2 vdot cycles | O2周期降低 | O2相对自身实测RVV |
| --- | ---: | ---: | ---: | ---: |
| 单次点积 | 71.00 | 71.00 | 0.00% | 1.201× |
| 依赖链256 | 1857.00 | 1857.00 | 0.00% | 2.930× |
| 四路独立点积128 | 362.50 | 221.00 | 39.03% | 3.068× |
| 加载/计算/存储64 | 1127.50 | 1127.50 | 0.00% | 1.005× |

本轮36项真实运行、478个校验窗口、192条正式性能窗口及4次代表性重放有可复算记录。窗口周期包含合同约定的循环和测量开销，不等同FU固有延迟或II。

### 5.2 O3应用：数据复用版、端到端口径

| GEMV尺寸 | O1 vdot cycles | O2 vdot cycles | O2周期降低 | O2相对较快RVV |
| --- | ---: | ---: | ---: | ---: |
| 4×8 | 166.50 | 164.00 | 1.50% | 1.160× |
| 8×32 | 323.50 | 321.50 | 0.62% | 1.035× |
| 16×64 | 856.75 | 847.75 | 1.05% | 1.054× |
| 4×13 | 212.00 | 209.50 | 1.18% | 0.907× |

O3共56项合格作业、1280校验窗口、768正式性能窗口；另2项中断尝试保留。独立batch的39.03%不能推广到所有应用。K=13含诚实计入的尾部处理成本，目前仍慢于该合同下较快RVV。

### 5.3 O4结构与参考时序

| 指标 | O1 | O2 | 解释 |
| --- | ---: | ---: | --- |
| 完整FU单元面积和 | 12525.142 | 17711.610 | +41.41% |
| 含DIV的真实VFEX4单元面积和 | 281750.392 | 285271.700 | +1.25%，不是整核增幅 |
| FU寄存器位数 | 1048 | 1838 | +790位，其中577位为额外perfDebugInfo |
| 父级ready路径arrival | 0.339943ns | 0.274544ns | 固定约束下缩短19.24% |
| 父级vdot输入到寄存器arrival | 1.516260ns | 1.540559ns | 增长1.60% |
| 最坏门控使能arrival | 1.785938ns | 1.915197ns | 增长7.24% |

采用固定Nangate45 typical库、理想时钟和经验wire-load进行前布局比较。面积值为Liberty单元area之和，未换算为芯片版图面积。两版均未满足1ns参考目标；也没有实际整核Fmax、布局布线或活动率功耗结论。

O4封存687份载荷、约48.84MB，已完成跨平台字节/数值/连接复核。该复核说明证据一致，不能写成1ns时序闭合。1ns是项目自定参考约束；截至本次官网核查，公开评分没有面积或主频的数值门槛。

## 6. 当前正确性证据与未闭合项

O2 G3完成14项作业：13项正常完整通过、1项bit100差分负控按预期拒错，并完成同镜像正常恢复。正常程序5378条vdot提交、117唯一功能/异常用例和完整128位及身份检查已有记录；两槽占用、响应/移动/接受同拍、反压、P/R取消及一槽幸存均有实际全核覆盖。

真实父级测试包含VDot、VIDiv、VFDiv及ClockGate。G3全核运行期未注入reset等边界仍按对应报告说明，不能把单元/父级覆盖直接移算成全核覆盖。

尚需闭合：

- 非主开发成员的T17干净目录完整重建与运行、真实人工复核记录。
- 指令语义疑问的外部确认和最终三人接口/语义评审。
- O2额外字段与控制路径的减代价可行性审查，以及应用弱收益原因。
- 最终模式、源码默认/复现入口的一致性和G5采用记录。
- 正式团队标识、报告/PPT、三阶段录屏、彩排、访问权限与系统提交回执。

## 7. 后续执行顺序

1. 固定O2的复现入口、依赖与构建选项，准备O5/T17；由实际成员完成独立操作与复核。
2. 沿O4结果审查P/R槽性能字段的真实消费者及控制扇出，先确认能够安全减少哪些重复保存，再实施一个小改动。ROB、pdest、异常和必要观测合同保持完整。
3. 在固定O3合同下分析端到端开销与K=13尾部，选择单项软件或调度优化，RVV获得同等优化机会。
4. 按改动范围完成单元→真实父级→新EMU回归，复测公平周期及必要的同条件结构/时序；所有新输出使用新目录，不覆盖旧封存证据。
5. 最终候选完成O5/T17与G5冻结后，再集中执行T16、T18。若存在未解决正确性或复现问题，使用已验证O1回退。

评分结构为完整性60、可行性20、探索性10、创新性10。当前优先补齐复现与交付，再增加可解释的优化收益，不以某个加速比推算官方得分或奖项。
