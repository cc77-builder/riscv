## 3. 当前架构

生产目标是香山昆明湖 V2 上的自定义向量点积。按当前内部合同，从两个源向量各取低8个有符号INT8元素，乘积求和，结果置低32位、高96位清零。完整合法域、异常行为及待澄清项以[指令规格](../spec/vdot.md)和[赛题要求与评分总览](../../赛题要求与评分总览.md)为准。

| 层级 | 当前组成 | 主要责任 |
| --- | --- | --- |
| 应用与接口 | firstdot V2、配置复用、split-input、Q/QKV、W2与norm消费者 | 完整C调用、输入布局、数值顺序、适用形状及RVV回退 |
| 执行父级 | VFEX4／ExeUnit，共享VDot与DIV资源 | 接受仲裁、反压、取消、时钟门控、响应与写回路由 |
| O2点积单元 | P乘积槽、R结果槽，两槽弹性推进 | 支持旧R输出、旧P搬移和新请求接受同拍发生；H1仅保存低32位结果 |
| 事务控制 | ROB身份、目的寄存器、异常、写使能、VPU及577位perf元数据 | 保证数据与控制同事务传递，取消及复位后无幽灵响应 |
| 验证与证据 | 独立模型、真实RTL仿真、NEMU/DiffTest、计数器审计、归档复算 | 分层核对数学、协议、架构状态、性能边界及源码身份 |

O2在无停顿条件下已证明最小接受间隔1拍、首响应2拍。反压可能延长响应握手，不能理解为所有事务固定2拍完成。

### 4.1 最近修复的验证缺口

当前父级检查器曾存在两处覆盖误判：

1. 仅检查ROB关系和场景标签，交换“计算中／已停顿”标签仍可通过。现根据接受周期、响应可见性和实际停顿拍数验证阶段。
2. 复位仅统计DIV种类，重复场景可能代替缺失的组合。现要求两类DIV × 三阶段 × 有无取消的12种组合全部出现且不重复。

两项均以真实原流变异复现“旧检查接受、新检查拒绝”；未经修改的有效原流仍兼容。不是通过放宽检查器获得PASS。

修复后的当前父级实际验证包括：

- Windows／Linux各59项主机测试通过；14组真实父级场景共38,536拍。
- 14,765笔接受 = 14,276笔响应 + 426笔取消 + 63笔复位丢弃，最终无在途事务。
- 28项DIV ROB场景、12种复位组合、48个取消窗口／144个立即空闲采样全部复算；取消后残留时钟为0。
- 577位元数据47,067个事件审计通过，walking-one／walking-zero各覆盖577位。
- 20种C++观察故障均按预期类别拒绝；它们不是20个RTL故障变体。
- 源码与依赖前后不变；179成员证据包完成字节校验和独立解包复算。Git属性已补充字节保护，避免ZIP被换行转换损坏。

完整记录见[当前父级结果](../optimizations/o2/parent/RESULT_CURRENT.md)。DIV复位仍使用TE=1，未声称覆盖全部TE=0复位模式。本轮未发现该验证范围内的新RTL功能错误；这一结论不等同整个项目不存在漏洞。

### 5.1 仿真工具与工艺库的区别

本项目的功能仿真与工艺相关评估是两条不同的流程。当前Verilator测试执行RTL逻辑并统计周期，不加载Liberty中的工艺延迟；Nangate45用于综合映射和静态时序分析。报告中宜分别写“功能仿真环境”和“综合／STA参考工艺库”，避免把两者合称为已经完成的工艺级仿真。

| 流程 | 实际工具／对象 | 能支持的结论 |
| --- | --- | --- |
| RTL生成 | Chisel／firtool；工具版本与生成RTL随运行封存 | 将指定源码与配置展开为可核对的RTL |
| 当前父级功能仿真 | Verilator 5.020，C++测试夹具，真实VFEX4及ClockGate | 数学结果、协议、反压、取消、复位、元数据及周期行为 |
| 全核差分验证 | 对应固定版本的香山EMU、NEMU及DiffTest | 架构状态、真实指令执行和计数窗口；不能代替物理时序 |
| 逻辑综合与映射 | Yosys 0.9、Berkeley ABC 1.01 | 指定边界的映射网表、单元数量、寄存器规模和单元面积之和 |
| 静态时序分析 | OpenSTA 2.0.17、映射网表、Liberty及约束 | 指定参考条件下的路径到达时间和setup裕量 |
| 后布局／带延迟门级验证 | 本报告没有此类已完成证据 | 不宣称完成SDF门级时序仿真、布局布线或流片签核 |

上述综合／STA版本来自项目冻结工具合同，不表示工具的最新发行版。功能仿真通过、STA工具正常退出、参考时序目标满足，必须分别判定。
