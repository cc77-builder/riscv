# T14 消融图合同

- 问题：相同镜像在候选硬件上的周期变化是否依赖工作负载，RVV 对照是否也改变？
- 论点边界：展示同镜像周期收益及阶段敏感性，不推导 Fmax、面积、功耗或所有应用加速。
- 构图：quantitative grid，两面板；a 为 vdot 的主要效果，b 为 RVV 控制变化。两者共用相同横轴范围、配置顺序和阶段编码。
- 后端：沿用本任务已建立的 Python/Matplotlib；仅继承已有项目图的字体、阶段颜色与标记风格，重新实现硬件 A/B 数据逻辑。
- 数据：已验收 ablation/paired-windows.json 的全部 1,404 行；只显示 replay=0 的 468 行（每方法 234）。三个重放须已逐窗口一致。保留所有 13 种场景/数量组合、3 个输入数据集及首次/预热/4 个正式轮次。不按性能筛选。
- 映射：scenario+n -> 配置行；method -> 面板；phase -> 颜色/形状；baseline_cycles/candidate_cycles -> 无单位横坐标；dots -> 行标签实际点积数。所有分母须正且有限，检查记录中的 hardware_speedup 与重新相除一致。
- 统计：画原始配对点，不作均值、置信区间、显著性检验或误差条。为区分同一配置里的阶段/输入/轮次，只做固定的纵向显示偏移；横坐标不抖动。
- 全数据与抽取：导出绘图来源 CSV，明确源摘要、总行数、选中数量与确定性重放筛选理由。其余重放继续保存在完整归档，不作为独立样本。
- 版式：183×145 mm，字体至少 7 pt；SVG 保留文本，PDF TrueType，PNG/TIFF 600 dpi。横坐标 1 为不变，>1 为候选更快；同一横轴显示所有退化与收益点。
- 验收：绘图前源代码预检；布局完成后执行 1.5 pt 面板对齐门禁；导出后检查 PDF 字号和碰撞；以 Python 渲染预览，逐面板及整图目检。任何 FAIL 须修复后重跑。
- 输出属于比赛报告图，不声明满足某期刊的最终投稿规范。
