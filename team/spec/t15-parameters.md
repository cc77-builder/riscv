# T15 参数扩展合同

2026-10-17，基于已发布 T14 `6fea2969d05dc4cb168795a60e2e6ee9ca1f9988`。本轮用户明确要求本地完成，不上传 GitHub。工作分支 local/t15-s16x8-20261017。

## 唯一新增配置

| 参数 | 原配置对照 | 新配置 |
|---|---:|---:|
| 输入有符号元素位宽 | 8 | 16 |
| 乘加项数 | 8 | 8 |
| 每个输入容器位宽 | 128 | 128 |
| 使用位段 | 低 64 位 | 全部 128 位 |
| 精确和范围 | -130048..131072 | -8589672448..8589934592 |
| 必需累加位宽 | 19 | 35 |
| 结果字段 | 低 32 位补码 | 低 64 位补码 |
| 其余目的位 | 高 96 位零 | 高 64 位零 |

lane 0 位于最低元素位段。精确计算从零累加，无舍入、饱和、旧目的累加或掩码；两个源即使相同也按独立快照计算。最大正值 8×(-32768)×(-32768)=2^33，因此 signed34 的最大值 2^33-1 不够，需要 signed35。结果低 64 位的符号扩展与目的高 64 位清零分开处理。

本轮新增独立参数化算术核及单元测试包装，放在 team/rtl/vdot/param。原生产 VDotDatapath、FU、译码、NEMU 和旧数据原字节不改。测试基本配置时同时实例化原生产算术核，对相同 22+10000 输入与黄金结果交叉比较；int16 配置使用新的独立精确整数模型及固定种子数据。

## 参数约束与层次

构造参数支持元素位宽 8 或 16、正的 2 的幂项数、固定 128 位输入容器；输入总位宽不得超过容器，结果字段必须容纳精确正/负极值且不超过容器。本轮只验证 (8,8,32,128) 与 (16,8,64,128)，不据可构造参数推断其他配置已通过。

实验包装采用固定单请求协议：E0 接受并锁存乘积及 32 位事务标识，E1 锁存归约结果，E2 最早响应；最小接受间隔 3 拍。输出反压时保持数据/标识；flush 或 reset 优先取消事务，禁止同拍接受新事务。该标识仅用于独立测试，不是香山 ROB/异常状态接口。本轮不新增 ISA 编码、不修改 vl/vtype 合法域、不声称 SEW=16 的 vdot 已在全核执行。

## 验收顺序

1. 新数学模型用精确整数及手工极值交叉验证，检查非法参数/输入。新建独立数据和 manifest；原模型数据不重新生成。
2. 基本配置复用原 22 定向+10000 随机数据；扩展配置补正负极值、超过 32/34 位、每个 lane、错位 lane、高半参与、符号/字节顺序以及 10000 固定随机输入。
3. 两配置生成真实 Chisel/SystemVerilog 并用 Verilator 比较全部 128 位组合及寄存输出；对照原生产 int8 组合结果。
4. 验证延迟/接受间隔、连续事务、反压稳定、输入扰动、取消、复位和事务标识。结果位 0/33/63/127 及标识的受控读回错误须被拒绝。非法参数必须由 Python 和 Scala 构造器拒绝。
5. 保存真实 RTL、完整读回/握手记录、命令、退出码、工具版本及摘要；独立离线重算。对比乘法位宽、加法层级、寄存器声明和实测单元周期，不推导面积/Fmax/功耗或全核加速。
6. 输出报告及本地 Git 提交/备份。团队人工复核待实际发生后记录，不伪造 ACK，不自动开始 T16 或发布。
