## 2. v0.1 原型行为速查

**本节及第 3～6 节是完整的内部候选合同，不是命题方确认后的最终 ISA。** 若后续答复有变，先改合同和测试，再同时修改 RTL 与 NEMU。

| 项目 | 【原型约定】 |
| --- | --- |
| 指令名称与记法 | `vdot.vv vd, vs2, vs1`；助记符暂为文档约定，现有汇编器尚未注册 |
| 源寄存器 | 两个 128 位向量寄存器；每个只使用低 8 个字节，编号 0～7 |
| 输入解释 | 每个字节按二进制补码解释为 signed int8 |
| 运算 | `S = Σ signed8(vs1[i]) × signed8(vs2[i])`，`i=0…7`，初值为零 |
| 结果布局 | `vd[31:0]` 为 S 的 32 位补码；`vd[127:32] = 0` |
| 旧目的值 | 不参与累加，不保留任何目的位 |
| 合法向量配置 | `VLEN=128、SEW=8、LMUL=1、vl=8、vstart=0、vill=0` |
| mask 与策略位 | 只支持编码位 `vm=1`；`vta/vma` 的四种组合均接受，目的值始终完整覆盖 |
| 别名 | 允许 `vd=vs1`、`vd=vs2`、`vs1=vs2`，以及三者相同 |
| 配置不支持 | 完整指令模型和全核实现抛出非法指令异常；不写目的、不产生部分结果 |
| 算术副作用 | 无饱和、无舍入；保持 `vxrm/vxsat/vcsr`，保持 `vl/vtype` |
| 首版扩展边界 | 不支持可变项数、16 项、其他 SEW/LMUL、掩码计算或从非零 vstart 恢复 |

参数集中定义为 `INPUT_BITS=8、PAIRS=8、RESULT_BITS=32、RESULT_LO=0、VLEN_BITS=128`。参数化用于降低变更成本；修改参数不等于已经获得额外 ISA 能力，扩展时必须另行定义语义、编码和验收。

## 3. 数学语义与目的位布局

### 3.1 源元素编号

从指令执行前的源寄存器状态读取：

```text
byte_a[i] = vs1_before[8*i+7 : 8*i]
byte_b[i] = vs2_before[8*i+7 : 8*i]       i = 0…7
signed8(x) = x             if x < 128
             x - 256      otherwise
```

源 `[127:64]` 不参与运算。内存加载测试使用既有小端裸机环境，数组的第 0 个字节对应源 `[7:0]`；不能把打印的高位十六进制组误认成 lane 0。

### 3.2 精确范围与位宽

单项乘积范围为 `[-16256, 16384]`，因此八项精确和为：

```text
S_min = 8 × (-128) × 127    = -130048
S_max = 8 × (-128) × (-128) =  131072
```

有符号 18 位最大值为 131071，不能覆盖 S_max；至少需要 **19 位有符号数**。原型使用 32 位结果，合法输入不发生 32 位溢出。

RTL 可先采用 8 个 signed 8×8 乘积与加法树：乘积 16 位，按二项、四项、八项归并时分别至少用 17、18、19 位，再符号扩展到 32 位。也可全部以 32 位求和。A 决定结构和流水级，但所有中间结果必须保留符号和足够位宽；不得先用窄位宽加法溢出，再扩展结果。

### 3.3 输出定义

```text
127                                  32 31                         0
+--------------------------------------+----------------------------+
|             全部为 0                 |      S 的 32 位补码         |
+--------------------------------------+----------------------------+
```

示例：S=-8 时，完整目的值为 `0x00000000_00000000_00000000_FFFFFFF8`。负数只在低 32 位内采用补码，高 96 位仍为零。本文中的“结果字段”固定为 32 位，不把它称为 SEW=8 下的普通第 0 个元素；否则容易错误截断为 `0xF8`。

这是自定义指令的整寄存器写回约定。`vl=8` 用来限制合法输入配置，不控制目的只写低 8 个字节；不得由通用 tail/mask 合并逻辑保留旧目的高位，或把高位改成全 1。

### 3.4 参考伪代码

以下描述架构效果，不指定时钟周期和具体 NEMU 接口：

```python
def execute_vdot(inst, state):
    # 必须先完成编码、向量状态和配置检查；失败则走非法指令路径。
    require_vdot_encoding_and_supported_state(inst, state)

    src1 = read_full_vector_before_write(inst.vs1)  # 128-bit snapshot
    src2 = read_full_vector_before_write(inst.vs2)  # 128-bit snapshot
    total = 0                                    # 数学整数，不模拟 RTL 截断
    for i in range(8):
        a = (src1 >> (8 * i)) & 0xff
        b = (src2 >> (8 * i)) & 0xff
        a = a if a < 128 else a - 256
        b = b if b < 128 else b - 256
        total += a * b

    result128 = total & 0xffffffff               # 仅编码低 32 位补码
    write_full_vector(inst.vd, result128)        # 高 96 位因此为零
    # vl/vtype/vxrm/vxsat/vcsr 不变；vstart 仍为 0；向量状态按写回置脏。
```

独立数学模型只计算输入数据与输出；完整指令模型另外实现编码、配置检查和异常，不能把 Python `assert` 当成处理器异常机制。

## 4. 合法配置、别名、异常与状态

### 4.1 配置合同

| 条件 | 原型行为及测试要求 |
| --- | --- |
| VLEN | 目标固定为 128；RTL 构建与 NEMU 配置均检查该常量。不承诺跨 VLEN 可移植性 |
| 向量状态 | 运行环境支持并启用 V；`mstatus.VS` 不能为 Off；沿用处理器已有特权态检查 |
| `vtype` | `vill=0`，`vsew=000`（e8），`vlmul=000`（m1）；其他非法/保留 vtype 不接受 |
| `vl` | 必须等于 8。`vl=0、1、7、9、16` 等域外值均不执行点积 |
| `vstart` | 必须为 0；非零值不表示跳过前几个乘积，也不被静默清零后继续执行 |
| `vm` | 必须为 1；`vm=0` 的相邻编码不属于本版合法指令 |
| `vta/vma` | `tu/mu、tu/ma、ta/mu、ta/ma` 均合法；输出仍精确遵循第 3.3 节 |

推荐首个测试程序使用 `vsetivli zero, 8, e8, m1, tu, mu`，读取并核对实际 `vl/vtype`，并确保 `vstart=0`。该配置指令是准备工作，本身不能让未扩展的处理器识别 vdot。

**这是有意收窄的 custom 指令原型域。** 域外统一非法是团队选择；尤其 `vl=0` 在本版不作为空操作处理。标准 RVV 指令的通用循环、tail 和 restart 规则不能未经核对直接套入。有关标准向量状态、策略位和重启机制的背景参考 [RISC-V Vector 1.0 文档](https://github.com/riscvarchive/riscv-v-spec/blob/v1.0/v-spec.adoc)；它没有定义本项目的 vdot 行为。

### 4.2 寄存器别名

`vd/vs1/vs2` 均为 `v0…v31`，每个操作数只占一个寄存器，无偶数寄存器对齐要求。`v0` 在本版 `vm=1` 下可作为普通源或目的，不是零寄存器。

所有源值以指令前状态为准，再写目的。NEMU 应先缓存所需源数据，不能先清空 vd 再逐项读取源。RTL 应正确维护源、目的重命名关系，不能把目的新物理寄存器当作输入。由于完整覆盖目的，算术上不需要旧 vd；物理接入是否存在通用旧目的端口由 A 审查，不得让它改变结果。

### 4.3 成功执行与失败执行

成功执行时：

- 只更新一个向量目的寄存器的完整 128 位；其余向量寄存器、标量寄存器、浮点寄存器、内存不变。
- `vl、vtype、vlenb、vxrm、vxsat、vcsr` 不变；合法初态下 `vstart` 仍为 0，不能把原有 `vxsat=1` 清除。
- 沿用现有向量状态置脏机制；不产生浮点异常标志，不访问数据存储器。
- 正常进入下一条指令（本编码长度 4 字节），退休与计数行为沿用处理器正常指令机制。

匹配本指令但配置不合法时，**原型目标行为**为精确非法指令异常（异常码 2）。目的寄存器、运算相关向量 CSR 和内存不产生本指令的部分更新；陷阱 PC 指向该指令。陷阱入口对特权 CSR 的正常更新不属于“不变”范围，`tval` 填写和异常优先级沿用已验证的现有机制。测试在状态可达时优先使用单一非法条件，不在本版另造一套异常优先级；存在状态联动时按第 7.2 节记录。

VLEN 不符优先在构建/加载配置时拒绝；若未来允许在其他 VLEN 机器执行相同编码，应另立版本规定其行为。

乱序执行中的请求若被 redirect/flush 取消，不得形成已提交的目的更新。首版不提供从中间 lane 恢复的架构状态；中断与取消复用现有精确提交机制。这些均需全核验证后才能勾选完成。

## 5. 候选机器编码

### 5.1 编码选择

【原型约定】选择 32 位 `custom-0` 主 opcode `0x0b`。官方 opcode 表为自定义扩展预留 custom 空间；这不表示下列 funct 字段由官方分配。[标准 opcode 表](https://docs.riscv.org/reference/isa/v20260120/unpriv/rv-32-64g.html)

| 位段 | 字段 | v0.1 候选值 |
| --- | --- | --- |
| `[31:26]` | funct6 | `000000` |
| `[25]` | vm | `1`；本版只支持无掩码 |
| `[24:20]` | vs2 | 第二个编码源寄存器编号，0～31 |
| `[19:15]` | vs1 | 第一个编码源寄存器编号，0～31 |
| `[14:12]` | funct3 | `000` |
| `[11:7]` | vd | 目的向量寄存器编号，0～31 |
| `[6:0]` | opcode | `0001011`（`0x0b`） |

汇编记法沿用向量常用顺序 `vdot.vv vd, vs2, vs1`。数学公式中 vs1/vs2 的名称与位段一致；点积交换律会掩盖源颠倒，所以编码测试还必须检查字段提取本身。

```text
MATCH_VDOT = 0x0200000b
MASK_VDOT  = 0xfe00707f
识别条件： (instruction & MASK_VDOT) == MATCH_VDOT
编码公式： MATCH_VDOT | (vs2 << 20) | (vs1 << 15) | (vd << 7)
BitPat：   b0000001??????????000?????0001011
```

例：`vdot.vv v10, v8, v9` 的候选机器字为 `0x0284850b`；小端指令字节为 `0b 85 84 02`。寄存器编号为向量寄存器编号，即使字段位置与 R-type 相似，也不能在主译码中把它们当作通用整数寄存器。

`vm=0` 或 funct 字段不符时不匹配本版 vdot；若未被其他合法扩展占用，应走默认非法指令路径。不得通过缩小 mask 接受未定义的相邻编码。

### 5.2 工具链与冲突检查边界

首版先用独立 `.S` 文件中的 `.word 0x0284850b` 或经过校验的编码宏生成上述机器字。后续封装由 B 负责；宏必须检查寄存器编号范围。未新增助记符支持前，反汇编可能显示原始字或未知指令，应核验机器字和字段，而不能以“打印出了 vdot 名称”作为前置条件。

如使用 C 内联汇编，须另行处理寄存器绑定、clobber 与编译器重排；不要把 `.word` 放进没有约束的内联汇编后假定编译器知道它读写向量寄存器。

2026-10-11 的只读静态检查在锁定版本的 **XiangShan 当前实际译码表和 NEMU 主译码表**中未发现与上述候选 mask/match 的交叠。已有 `nemu_trap/TRAP` 使用 `0x6b`，并非 `0x0b`。rocket-chip 依赖中确有与候选重叠的 `CUSTOM0` 通配定义，但属于 Rocket RoCC 译码体系，未接入本版香山实际译码表；未来若启用该通路，必须重新审查分配与仲裁。此结论只覆盖已检查的静态模式，不能代替接入后的译码单测与全核回归；候选编码尚未实现。

以下是本版源码核查发现的具体接入风险；行号对应表中固定硬件/NEMU 提交：

- `RiscvInst.scala:93` 的向量分类需要识别精确 vdot 模式，不能把全部 custom-0 都归为向量。`DecodeUnit.scala:897` 的向量禁用检查还依赖 FU 分类，因此只加 BitPat 不够。
- `DecodeUnit.scala:775` 的输入带 vtype/vstart，未直接带实际 vl；`vl=8` 限制须通过正确的 VL 依赖，在能取得 `srcVConfig.vl` 的路径检查，例如 `fu/vector/VecPipedFuncUnit.scala:54`，并接通非法指令异常输出。
- `DecodeStage.scala:236` 对 v0 目的有单独写使能，重命名也有相应通路。允许 v0 就必须覆盖它，不能只测 v8/v9/v10 后认定全部寄存器均可用。
- NEMU 的 `instr/rvv/decode.h:167` 在既有 `vopivv` 子表中把 funct6=0 解释为 vadd，且不再检查主 opcode。**不能把 custom-0 直接分派到现有 OP_V 执行子表**；应建立独立 vdot 执行分派，可以复用字段解析和寄存器访问。状态检查/置脏参考 `instr/vp.c` 的 `vp_enable()`、`vp_set_dirty()`。

### 6.2 硬件接口边界

[RTL 接入接口草案](rtl-interface.md) 已给出配置依赖、完整写回路径和分层验收。A 在 T06 确定具体端口与时序，B/C 复核；草案尚未得到成员签字或实现验证。本文锁定必须实现的性质，不虚构固定周期数：

1. 运算请求携带正确的两个向量源值和请求身份；配置检查必须使用与该指令对应的向量状态。
2. 只有请求真正被接受后才进入执行；输出反压时保持结果及身份，不能丢失、重复响应。
3. 正常完成形成一个完整 128 位架构目的结果；内部微操作数和流水级由接入设计决定。
4. 结果与目的物理寄存器、ROB/取消标识保持一致；flush 后不能提交已取消的结果。
5. 全寄存器写回绕开或正确配置通用 tail/mask 合并逻辑，保留高 96 位清零要求。
6. 功能单元延迟和发射间隔分别定义、分别测量；本文不预先承诺“一周期”或加速倍数。

### 6.3 NEMU 与交付约束

共享参考库与 standalone NEMU 应分开构建，保存各自提交、配置和实际加载路径，避免覆盖已有环境产物。NEMU 修改应提交至团队可访问的 NEMU 仓库或采用明确可复现的补丁交付；确定方式并更新版本引用后，其他成员才算能够完整复现。

L01 无法检测“两侧同时采用相同排列”的内部置换，因为点积对这种置换本来就不变；不要为无法观察且不影响语义的内部排列编造失败标准。CSR/非法配置测试应使用合法准备指令并保存实际 CSR 值，避免测试准备过程就已失败。

非法配置须通过实际可达状态构造：用标准 `vset*` 指令设置非法 vtype 时，`vill=1` 与 `vl=0` 联动，此例只验证目标 vdot 的非法异常及无部分更新，不能据此声称单独覆盖了 vill 检查或异常优先级。测试非零 `vstart` 时，应在向量配置、加载等准备完成后最后写入，避免被准备指令清零。向量状态关闭案例也应先完成向量数据准备，最后再关闭 VS。

T05 的独立模型、定向及固定随机输入见 [模型与数据](../tests/README.md)。E01/E02 的陷阱处理、fault PC、状态观察、合法对照和失败判定见 [异常测试方案](exception-tests.md) 与 [异常 workload](../workloads/vdot-exceptions/README.md)；基础设施已实现并自测，但真实扩展运行待完成。C01 与完整写回分层覆盖见 [RTL 接入接口](rtl-interface.md)，RTL 接入与仿真仍待实现。

### 7.3 随机验证与证据

- 软件模型/算术单元起步使用固定种子 `0x20261011`，至少 10,000 组 signed int8 输入；全核冒烟先用上述定向用例，再选 32 组固定随机用例。数量是初始工程安排，不是官方评分门槛。
- 保存生成器版本、实际输入、完整期望值、合同版本。仅有随机种子不一定能跨语言复现随机数序列。
- 交叉检查交换两个源、同时重排两边低 8 项等不变量。涉及 int8 取负时排除 -128，避免把不可表示的 +128 当成合法输入。
- 失败应输出指令字、PC、配置、源/目的编号、指令前源值、完整实际/期望目的值；定向用例输出用例 ID。
- 独立模型、RTL 单元、NEMU、全核 DiffTest 分别保存结果，不能用某一层通过替代其他层。

软件读取结果时要覆盖全部 16 字节。例如执行后切换到 `e32,m1,vl=4`，保存四个 32 位元素，再恢复约定的配置；C 应区分“被测指令副作用”和“测试程序为读回结果而改变的配置”。只保存 e8 的 lane 0 会漏掉错误。

## 8. RVV 性能基线必须保持的等价性

【题目明确】需要用现有 RVV 指令组合完成相同功能，并比较延迟。候选基线按“8 位有符号输入 → 16 位精确乘积 → 32 位扩宽归约”设计，例如研究 `vwmul.vv` 与 `vwredsum.vs` 的组合；中间切换的 SEW/LMUL、寄存器分组和零初值必须匹配。这里不是已通过验证的汇编实现。

B/C 验收基线时必须逐项确认：

1. 只计算源低 8 项，从零开始，不把旧目的或源高半部分加入。
2. 不使用会在 8/16 位提前截断的组合；D06、D07 必须通过。
3. 最终目的低 32 位及高 96 位与第 3 节完全相同；普通归约指令的尾部策略不能代替显式验证。
4. 双方按共同约定的可观察入口/出口状态验证功能等价：目的 128 位结果及向量 CSR 必须一致，vl/vtype 恢复实际入态。允许破坏的临时（scratch）寄存器必须预先列明并排除于比较集合，源/目的别名用例另行证明等价。该口径不能被称为“除目的外所有架构状态都保持不变”；第 4 节的严格副作用限制仍适用于单条 vdot 本身。
5. 分别报告核心算术和上述合同范围内完整序列的周期；必要的清零、配置切换、恢复和搬运开销不得只从基线一侧隐藏。装载、存储是否计时，两边保持一致。
6. 同一硬件基线、同一输入和测量边界下比较；声明测量的是依赖延迟还是吞吐。Verilator 主机运行秒数不能当作处理器周期加速比。

具体序列与测量事件由 B/C 在后续 `team/spec/measurement.md`（待创建）中确定。本文不承诺加速比或获奖分数，先以完整性、正确性和可复现证据为验收顺序，再做流水线和扩展优化。
