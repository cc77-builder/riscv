# 审查结论：S2-10-v2 与 S2-05-v2（概念伴图）

我实际看了两张图，两个文件的 SHA256 都和你给的一致。我没有修改文件、没有生图，也没有运行构建。

## 1. 逐图判断

### S2-10-v2：**PASS**

- **结构**：三张同样的卡片横向排开，等宽、等高、间距相同，标题都是深蓝底白字。卡片之间没有箭头或连线，看不出优先级链或先后关系。之前"取消 → 复位 → 参考模型"串成一条链的问题已经修好。
- **用色**：
  - "保留有效事务"：蓝色事务卡加一个灰色软盘图标。
  - "撤销匹配事务"：整张卡只用橙色，虚线事务框加 ⊗ 圈叉，只有这里用了橙色，符合约定。
  - "继续处理"：蓝色事务卡、灰色箭头，再接一个灰色堆叠层图标。
- **是否有误导**：图里没有寄存器槽编号、流水级标记，也没有 NEMU 或参考模型的字样，读不出真实管线或控制关系。
- **可读性**：标题字大、笔画粗，缩到报告栏宽也能看清。
- **需要说明的风险**（我认为不到必须修改的程度）：
  - "继续处理"里的三层堆叠图标是常见的"图层"图标。读者如果对硬件比较敏感，可能把它看成三个条目或三级流水。好在它是孤立的灰色辅助图标，没有编号，也没和其他卡片连在一起，误读的可能性低。
  - 软盘图标在硬件白皮书里稍显过时，也带一点"写盘、持久化"的意思。不过它作为通用的"保存"符号，不会造成语义错误。

### S2-05-v2：**PASS**

- **结构**：一个灰色圆角大框，顶部是深灰胶囊标签"同拍重叠"，框里并排三张蓝色卡片，卡片之间没有箭头。只有卡片内部有图标箭头：
  - 新事务 C 进入空槽；
  - B 从虚线框（原位置）移到实线框；
  - A 通过握手图标交给输出。
- **与修订目标的对照**：之前跨卡片串成先后流程、颜色不一致的问题已经修好。三张卡都用同一种深蓝标题和浅蓝填充，大框把三项动作明确框成同时发生。
- **字母顺序**：从左到右是 C、B、A，正好是新的在左、旧的在右的快照式排列，和"同拍重叠"的意思一致，不会读成"先 C 后 A"。
- **轻微不足**（不影响语义）：
  - 大框边线和"同拍重叠"标签用的是很重的深灰，视觉上比三张蓝卡还抢眼。
  - 握手图标是商务插画式的写实双手，比其他线性图标更具象，风格略不统一。

## 2. 必须修改与可选优化

**必须修改：无。**

可选优化（最多两项）：
1. **S2-10**：如果后续还会再生成一版，可以把"继续处理"里的三层堆叠换成单个向前箭头或齿轮之类的中性"处理"图标，彻底避免被读成多槽或多级；软盘也可以顺带换成勾选或锁定图标。不重生成也可以直接用。
2. **两图统一**：把右下角"概念示意"标签调成同样大小。目前 S2-10 的明显更小，缩到栏宽后可能看不清。也可以把 S2-05 大框的边线调浅一档，让视觉重心回到三张蓝卡。

## 3. 建议图注

- **S2-10**：概念示意：发生取消时，未受影响的有效事务被保留，与取消匹配的事务被撤销，其余处理照常进行；三者为并列概念，不表示具体流水级、槽位数量或时序关系。
- **S2-05**：概念示意：同一拍内，接收新事务、推进在途事务与输出握手三项动作相互重叠，而不是依次执行；图中不表示具体流水级数、槽位或周期时序。

## 4. 两图一致性

**整体一致，可以作为同一批图使用。**

- **相同之处**：两图都是白底，都用"深蓝标题 + 白色内容区"的三卡并列版式；灰色只用于辅助图标和箭头，橙色只在 S2-10 的取消卡里出现；都没有装饰性的伪工程连线；都标了"概念示意"。
- **细微差异**（都不影响使用）：
  - S2-05 的蓝色标题略深，还多了浅蓝填充；
  - 两张图的"概念示意"字号不一样；
  - 虚线在 S2-10 表示"被撤销"（橙色），在 S2-05 表示"原位置"（浅蓝）。两者颜色不同，读者能区分，但如果报告里两图挨得很近，可以在正文里稍作说明。

我的判断和主端一致：两张图都已修好原来的实质问题，可以直接使用。
