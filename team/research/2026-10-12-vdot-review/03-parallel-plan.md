# 03｜可分配、可并行的实施计划与任务单

本文件是对现有 A/B/C 模式的细化，不代替成员认领，也不擅自把分支名映射为职责。以 [分支证据](01-evidence-audit.md) 为输入，保留原 T03/T07/T08/T09/T10/T11 等编号；下面 W 编号是可直接执行的子工作包，不再建立第二套互相竞争的总进度。

## 1. 总体组织

三条工作流同时启动，但必须共享一份明确标记版本的接口：

```text
W00 候选合同/版本/集成选择
 ├─ A: W10 全核适配 ── W11 小型全核闭环 ── W12 流水候选
 ├─ B: W20 B6/B7验证 ─ W21 长点积/分块内核 ─ W22 强RVV对照
 └─ C: W30 独立模型交叉/测试 ─ W31 DiffTest负控与测量
          └─ W32 H0综合约束检查 ── H0/H1 PPA对比
                            ↓
             W40 正确性＋性能＋PPA联合验收
                            ↓
             W41 清洁检出复现/交付/规则确认
```

C 的前半段不等 A 完成全核：可以完成独立模型转换、测量日志格式、测试输入以及 H0 的独立综合环境检查。B 的 B6/B7 和通用 RVV kernel 也不依赖新硬件。A 不等大规模随机测试写完，先用现有少量定向例验证完整处理器路径。

**只有明确的接口依赖才等待，不因“上一个阶段整体还没关”而空转。** 相反，独立 NEMU 通过、单元通过、所有计划文档写完，都不能替代 W11/W31 的全核验收。

## 2. 三个角色的具体产出

| 角色 | 主责 | 不应被全部转嫁给该角色 | 主要复核 |
| --- | --- | --- | --- |
| A：全核/RTL | 精确译码、源与控制、v0/完整写回、异常/取消，随后流水参数与回归 | 环境文档、模块测试和设计解释仍由 A 交付，不能留给 C 补齐 | B 审语义；C 审控制与测量事件 |
| B：语义/软件 | NEMU 补丁可复现，B6/B7 与强 RVV kernel，输入布局与汇编封装 | B 自己完成反汇编/模型/软件平台测试，不交空代码让 C 测 | A 审微操作/寄存器约束；C 独立核对输出 |
| C：独立验证/性能 | 双模型交叉、全核负控、统一性能采集、PPA实验组织与证据索引 | 不包办所有成员报告、所有测试实现和所有 Git 合并 | A 审硬件时间口径；B 审数值与实验公平性 |

三个人都应读懂核心合同；每个包只有一个主责和一个明确复核人。姓名、可用机器、每日时间、综合工具/工艺仍待团队填写。Zufan 可以认领其中任一条工作流，不根据其 Fork 或本报告作者身份默认分配。

## 3. 工作包定义

### W00｜版本和合同交接（关联 T02/T03）

主责建议 B，A/C 共同确认；可立即开始。

输入：三分支固定 SHA、最新规格 Q01～Q07、实际硬件与 NEMU 基线。输出：一页版本/接口交接，记录采用哪些 commit 或补丁、未决官方问题、可观察状态、scratch 规则、模型格式和异常范围。

验收：三方针对同一条机器字、同一组 128 位输入给出同一个完整结果；知道实际构建根是 XiangShan，外部 xs-env/NEMU/nexus-am 如何取得；没有假定“分支代码已自动合并”。P0 未获官方答复时显式写内部候选决定，不虚构外部确认。

### W10｜精确全核适配（关联 T06/T10）

主责 A；复核 B/C。输入为已存在 VdotExec 和接口草案，不再重新实现八路乘法。

改动边界：译码/向量分类、FuType/FuConfig/EXU 配置、适配 wrapper、必要源槽/控制与写回；公共热文件由 A 单独拥有本轮写权限。先确认实际调用路径，再改最小集合。

产出：一张源码路径/控制表和可构建 patchset。明确 robIdx/pdest、物理 VL、vtype/vstart 快照、v0、非法完成和取消逻辑；若实际核心没有直接提供独立单元要求的完整字段，说明如何从已有受验证控制信息构造等价检查，不能凭空填常数伪造状态。

验收：编译/生成成功，原向量回归仍可运行；局部握手/时序与 FuConfig 一致。此项只证明接入可构建，必须继续 W11，不能单独宣布全核成功。

### W11｜尽快完成最小纵向闭环（关联 T10/T11）

主责 A，C 提供程序和判定；依赖 W10 与现有 NEMU 扩展。

第一轮只运行少量具有区分力的案例：一般正数、负数 -8、最大和 131072、目的高位预填 FF、一个源目的别名、一个 v0 案例。顺序和数量按构建资源调整，不是官方固定门槛。

验收：每条有机器字/PC、实际输入、完整 128 位提交结果、DiffTest 开启证明、运行命令和 SHA；随后故意破坏一次结果，真实差分必须失败，恢复后通过。禁止以只打印 PASS、只比较低 64 位或 skip 自定义指令过关。

这个检查是里程碑，不是完整发布验收；异常、flush、依赖、策略和全部覆盖继续由 W30/W31 推进。

### W12｜只实现有价值的流水候选（关联优化任务）

主责 A；C 执行对照实验。依赖 H0 可追溯和 W32 初步路径信息；不阻塞 B/C 的软件任务。

先实现 H0/H1 选择参数或最小差异 patch，尽量保持一个生产算术源，不维护两套长期分叉 RTL。接口、ISA 和 workload 均不变；若变更延迟，连同配置、唤醒和测试一起改。

验收：两版功能/控制回归均通过；相同工艺/PVT/SDC 下报告面积、关键路径、寄存器、吞吐和 kernel 时间。只有确认算术仍为瓶颈才批准 H2/CSA，未改善就保留简单版而非继续叠补丁。

### W20｜接入 B6/B7 候选（关联 T09）

主责 B；C 独立复核，A 审向量寄存器组和微操作。

输入：[方案与证明](02-architecture-and-baselines.md)、本目录 host/汇编探针、现有 baseline harness。产出：在原 B13 旁边添加具名 variant，复用现有数据/异常分层/完整状态采集，而不是另写一套相近的测试平台。

验收：两候选在可用软件平台真实执行，全部共同输入的 128 位结果和入口/出口 CSR 符合合同；对源目的重叠、v0/v31、四策略、高半干扰、负数和极值进行测试；记录 scratch/t3/t4；反汇编确认无额外未知代码混入 ROI。然后在 W11 的硬件平台复验。仅本目录 host PASS 不可关闭 W20。

### W21/W22｜软件性能内核与强 RVV 对照（关联 T13）

主责 B；C 测量，A 解释硬件约束。

W21：实现展开 vdot 的长点积/小 GEMV，批量 dot 后统一 e32 收集，扫描 U=1/2/4/8，明确 int32 累加和尾部。W22：实现或复用合法的通用 RVV 宽化累加/延后归约内核（BK 为一个候选），允许同样展开、打包和预处理；选择最快已验证对照。

验收：精确整数 oracle 输出一致；冷/热缓存和打包成本分开；K 不整除 8 不越界；不把 e8 取值/16 位累加当 int32。先交小 dot/GEMV；GEMM/真实权重作为后续可选扩展，不等完整 LLM 跑完才验收基础功能。

### W30｜两套模型交叉及完整用例（关联 T05/T12）

主责 C；B 复核语义。

保留 James 与 zjhwork 的独立数学实现，编写轻量输入适配器，统一合同标识、端序、寄存器初态和期望格式。两模型对同一输入独立运算；不要让第二模型直接 import 第一模型的算术函数，否则丧失独立价值。

验收：覆盖签名、位宽、lane、高位清零、所有别名类别、策略、CSR；差异可以定位到输入/合同/实现。随机种子、实际生成算法和输入摘要均留存。数量是覆盖安排，不以扩大重复 case 数代替独立检出能力。

### W31｜真实 DiffTest 负控与性能采集（关联 T11/T13）

主责 C；A/B 各自负责修复其模块。依赖 W11 才进行真实全核部分，但输入格式与脚本可以先写。

产出：完整向量与需要的状态比较确认；受控算术错误、高位错误、错误路径提交等负控；基于真实发射/写回/退休事件的 ROI 与原始 CSV。依赖延迟、独立吞吐、完整序列、算子分别采集，不把不同指令流逐条相互差分。

验收：错时失败、修复后通过；无 skip、无漏报、无旧 PASS 残留。比较开始前保存两边相同输入、运行参数、源码/ELF/NEMU SHA；实际数据能由公式重算。

### W32｜并行的综合约束与 PPA 实验（关联优化分析）

主责 C 组织，A 审查电路与时序。先评估现有 H0，不等整个性能章节写完。

首先确认真实工具/库/SDC 是否可用；不可用时明确只能做结构估计，不填 Fmax/功率。若可用，锁定 cell library、PVT、时钟、IO 延迟、负载和实现阶段，记录算术及控制关键路径。

验收：相同脚本分别处理 H0/H1；未约束路径、hold/setup 问题不能被 PASS 掩盖；单元和整核面积/功率边界分开。A 尚未提供 H1 时先交 H0 分析，不私改公共 RTL 与 A 冲突。

### W40/W41｜联合验收与可交付版本

W40 由三方分别负责自己的技术章节，C 只组织统一索引。必须同时拥有正确性、最快有效基线、性能原始数据、优化代价及未完成限制。

W41 由非原作者从干净目录重建，验证外部 NEMU/子模块/补丁可取得、入口命令真实可用。公开/私有提交要求由团队确认；保留源许可证，禁止凭过时模板自动公开代码或提交比赛。

## 4. 热文件、集成与构建资源

| 区域 | 本轮建议唯一 owner | 其他成员如何贡献 |
| --- | --- | --- |
| 公共 decode、FuConfig、EXU 配置、ROB/写回适配 | A | 提测试或最小建议 patch，不同时独立改同一处 |
| NEMU 补丁、ISA/编码封装、baseline/kernel | B | C 提独立失败输入；A 提字段/延迟约束 |
| 双模型适配、性能 CSV/统计、回归索引 | C | A/B 交可运行脚本和自己的原始记录 |
| 总体进度/版本锁 | 约定的一位集成 owner | 所有人以短变更请求更新，不分别复制三份真相 |

根仓库实际是 XiangShan，不因旧文档画了 xs-env 外层就重建整个仓库结构。NEMU 由固定 commit＋补丁/自有可访问分支给出，关键是非作者可复现。不要只在本机 NEMU 改完后忘记交付外部依赖。

使用独立 Git worktree/分支和构建目录；生成的 RTL、ELF、波形及测试输出不得跨不同 SHA 复用。全核生成/链接通常是资源热点，按照实测内存安排同机并发，不把三人“逻辑并行”解释为同一台电脑同时启动三个大构建。先短日志、短回归，失败才开指定时间窗波形。

建议每人同时只有一个主要实现包和一个复核包。每完成一个小闭环就交集成，不等整条个人分支“全部完美”；但合并必须有明确授权和实际测试。连续构建失败或复杂度上升时优先复核版本、依赖、真正需要的配置，再扩展改动。

## 5. 以门槛而不是旧日期排期

| 门槛 | 定义 | 同时推进 |
| --- | --- | --- |
| G0 | 当前内部合同与已知风险、实现 SHA、机器/工具清单明确 | A 适配；B B6/B7；C 模型/PPA环境 |
| G1 | 最小全核 vdot 与一次故障检出完成 | B kernel；C 扩展回归；A 剩余控制覆盖 |
| G2 | 必需合法/非法/取消/依赖测试通过，目标基线也通过 | H0/H1 对照、完整算子比较 |
| G3 | 数据可重算，选出满足约束的方案而非只数指令 | 材料解释、第三人复现 |
| G4 | 清洁复现、交付访问与规则确认 | 团队决定最终同步/提交 |

建议以两天左右为一次短检查窗口，而非新的硬性截止：展示实际提交、卡点与下一次证据。现有历史截止日期需要重新核实后才转为日历计划；不承诺某个未测加速比或“几天必完成全核”。

## 6. 可复制给本机 Codex 的单包任务格式

本机 Codex 直接使用本地文件和 Git，不依赖 ChatPC。下面是任务格式，不表示本次已启动 Codex。

### 背景与目标

在明确的本机工作区实现一个 W 工作包。先读取本目录、当前仓库 AGENTS/规格/接口和实际 git 状态；以当前检出的源码为准，不能将本报告历史快照当最新工作区状态。验收目标写成具体可观察行为。

### 编号步骤

1. 输出工作区、分支、HEAD、未提交改动及将修改的文件；保护原有修改，不 reset/clean 覆盖。
2. 核对输入版本、合同、依赖和该包 owner；先定位真实路径，再实施最小改动。
3. 复用既有模型、harness、脚本；候选方案用显式 variant，不删除原基线或放宽判定。
4. 完成代码及模块说明；记录未决事项和回退方式，不扩大到无关工程。
5. 运行本包单元/软件平台/全核/综合中要求的层次。缺环境就标明未执行，不用低层 PASS 代替。

### 测试与真实验收

给出命令、返回码、SHA、完整结果/原始日志，以及一个受控失败能够检出的证据。性能任务必须有强对照、相同输入和计时边界；硬件任务必须区分组合逻辑正确、协议正确和整核正确。非作者至少复现一次关键入口。

### Commit / Push

只提交属于本包的文件，核对 diff 和外部子模块/补丁。Push 仅限用户本次明确授权的仓库与分支；没有授权则停在本地 commit。检查目标远端分支是否前进，冲突先整合，不 force 覆盖。向个人 Fork Push 与向 `cc77-builder/riscv:zufan` Push 是两个不同授权范围。

### 报告

报告改了什么、实际通过什么、没执行什么、结果与原目标的差距、commit 及是否 Push。不能仅凭单元测试宣布全核或性能验收完成。
