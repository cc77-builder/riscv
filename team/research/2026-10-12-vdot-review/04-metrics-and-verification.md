# 04｜评价指标、实验设计与真实验收

目标不是让某个数字最大，而是证明：正确完成赛题、可复现、相对强对照有收益，并交代面积/频率/能耗代价。引用依据见 [S02/S04/S05/S08/S09](SOURCES.md)；具体工作包见 [并行计划](03-parallel-plan.md)。本文件的数值测试规模是建议，不是官方评分阈值；没有填造性能结果。

## 1. 分层验收，任何一层不能冒充上一层

| 层次 | 实际要检验的对象 | 关键通过条件 | 不能由此推出 |
| --- | --- | --- | --- |
| L0 数学/编码 | 精确整数、位布局、机器字和别名输入 | 定向/随机期望正确，非匹配编码只被专用入口拒绝 | 真实 CPU 必然非法、CSR/陷阱已实现 |
| L1 独立 RTL | 算术、ready/valid、反压、取消、身份 | 输入/输出按 tag 匹配，无丢失/重复/污染 | 已接入核、达到目标频率 |
| L2 软件参考 | NEMU 扩展与标准 RVV 基线 | 真实程序执行，合法/异常现场及完整状态正确 | 目标周期或 RTL DiffTest 通过 |
| L3 全核 | 重命名、VL/v0 依赖、写回、ROB、精确异常、DiffTest | 真正执行新指令，完整比较；故意错误会失败 | 已有应用加速或物理时序 |
| L4 性能 | 单元/指令/完整 kernel 的不同时间边界 | 同平台强基线，正确性先过，原始数据可重算 | FPGA/ASIC 频率、能效自动成立 |
| L5 物理/应用 | 综合、STA、PPA、必要时真实算子/模型 | 约束有效，代价与收益同口径；模型精度单独验证 | 单元面积代表整核面积，随机 dot 代表 LLM 精度 |

本次目录中的探针属于 L0 加汇编语法/编码长度检查，尚未到 L2；团队历史报告提供部分 L1/L2 证据，当前审计未发现全核和 PPA 已完成的证据。

## 2. 正确性指标先于速度

### 2.1 合法算术与可观察状态

至少包括零、同号/异号、-128/127 边界、最小/最大总和、负数、交替位、每个低 lane 独立激活、源高 64 位干扰、目的预填非零。比较完整 128 位，不只最低元素/低 64 位。

别名覆盖分开列出：无重叠、vd=vs1、vd=vs2、vs1=vs2、三者相同；v0/v31；vta/vma 四组合；vxrm/vxsat 初值；实际 vl/vtype/vstart。初始化别名时必须是一份真实寄存器状态，不能先给同一寄存器装两个不同“源值”，再拿不可能同时存在的值算期望。

单条 vdot 的严格副作用与 RVV 序列允许破坏的 scratch 集合是两个合同。两个实现比较时先声明允许 clobber 的标量/向量寄存器，其余部分逐一核对。B6/B7 只在受限合法域等价，不用于替代非法指令测试。

测试数量报告 planned/executed/passed/failed/unreachable；未执行、超时、退出码错误、缺失日志、不可达初态均不能归入 PASS。基于 SHA 的输入数据和可重生成算法比只记录 random seed 更可靠。

### 2.2 精确异常与控制

沿用已有 exception harness，不新建第二套相近框架。检查合法对照先通过、异常次数、同步 cause=2、fault PC、目标平台约定的 mtval、异常前后完整向量状态及未发生部分架构写回。处理程序自身对 CSR/GPR/记录区的改动须单列，不要求陷阱前后整个 CPU 比特不变。

必须包含 vstart 最后设置后立即执行、vill/vl 联动记录、VS Off 的特殊观察顺序、邻近编码不误判，以及 ROB wrap-around/分支误预测/flush/回压组合。一个不匹配 vdot 的机器字可能是其他合法指令，不能把专用 decoder_reject 全部解释为 CPU 应报 illegal。

乱序核可以乱序完成和投机物理写回；检查的是按 tag 对应、取消后的最终架构行为以及按 ROB 规则退休，不错误要求所有 FU 输出按发射顺序返回。非法指令必须完成并携带异常，不能让 ROB 永久等不到结果。

### 2.3 必做负控：确认验证系统真的有用

| 注入/反例 | 应在哪层被检出 | 证明的能力 |
| --- | --- | --- |
| 一个乘积错误按无符号解释 | 数学↔单元、NEMU↔RTL | signed 路径检查有效 |
| 仅改目的 bit 100、低 64 位保持正确 | 全核 DiffTest/结果保存 | 完整 128 位比较真实启用 |
| 刻意漏掉应取消的新请求或保留错误路径提交 | 全核控制测试 | 不只测试 pending 槽 flush |
| 非法配置不回 completion 或仍写目的 | 超时/ROB/异常测试 | 既检查陷阱也检查无部分更新 |
| 基线恢复固定策略、在 e8 下读 int32 | 基线状态/极值测试 | 等价性和测量程序能检出自己的错误 |
| 旧 PASS 文件、缺案例或错误返回码 | 回归汇总脚本 | 不把基础设施失败伪装成通过 |

故障只在明确的测试变体中注入，不能提交到生产开关默认开启的路径。至少保存一次“注入时失败→恢复后通过”的实际日志；纸面反例不算已经完成 RTL 故障注入。

## 3. 把四种性能问题分开回答

### 3.1 算术单元延迟与发起间隔

记录输入 `valid && ready` 的接收时刻、首次输出 valid、输出消费时刻，分别得到计算响应延迟和因回压产生的等待。II 是连续无依赖请求可接受的最小间隔，不是延迟的同义词。H0 的“1 周期、II=1”仅限独立单元无回压条件；全核可能受调度、读数与写回限制。

### 3.2 单指令 RAW 延迟和独立吞吐

RAW 延迟可用真实依赖链或 RTL 事件观察。只重复写 `vdot v10,v8,v9` 是 WAW，不必然形成结果依赖；应使用有真实数据依赖的链并让 oracle 跟随状态，例如将前一次目的作为下一次源。吞吐测试用足够多独立寄存器/请求，避免把人为依赖误当执行单元 II。

记录 N 次操作的总周期与 fill/drain，扫描不同 N，以固定开销和稳态斜率区分启动成本与吞吐。输出 `dots/cycle`、`MAC-equivalents/cycle`；不只写 IPC，因为不同 ISA 完成同一任务需要的指令数量不同。

### 3.3 单条功能的完整等价序列

比较 vdot 与 B13/B6/B7：同一入口合法状态、同一源快照、相同结果/CSR约定、预先声明 scratch。清零、配置、恢复、必要搬运都计入；共同输入准备和结果观察要么双方都计入，要么双方都不计入。另列纯算术区，不把它叫完整接口开销。

### 3.4 完整 kernel 与软硬件协同

长 dot/GEMV/GEMM 比较最强已验证通用 RVV 与最强已验证 vdot 内核；两边都允许展开、重用、打包和延后归约。相同的边界输出与数值精度，不强迫 RVV 每八项恢复一次 CSR。

至少分别记录：计算循环、不含一次性打包的稳态 kernel、包括打包/尾部/结果收集的端到端。缓存预热、输入对齐、工作集、循环次数和编译参数一致；报告冷/热条件，不混合后只挑对自己有利的数。

## 4. 公式与单位

设对照周期 Cb、新方案周期 Cn、完成 N 个八项 dot：

```text
周期加速比       S = Cb / Cn
周期减少比例     R = 1 - Cn / Cb
每次 dot 周期    Cdot = Cn / N
dot 吞吐         Pdot = N / Cn
MAC 等价吞吐     PMAC = 8*N / Cn
物理运行时间     T = C / f       （f 必须是可信且满足约束的时钟）
物理时间加速     Stime = (Cb/fb) / (Cn/fn)
面积增量比例     ΔA/A0 = (Anew-A0)/A0
ROI 能量         E = Pavg * T    （Pavg、T 必须覆盖同一边界）
```

一次八项零初值点积有 8 次乘法、7 次非平凡求和。若采用“1 MAC=2 operations”的常见吞吐口径，则每 dot 记 8 MAC-equivalents / 16 operations，必须明确是约定口径，不声称电路执行了 16 个独立算术原语。

同时报告同频周期比较与各方案可实现频率下的时间比较；不要只提高新单元 Fmax、却忽略整核仍被别的路径限频。延迟 L 周期对应 L/f，吞吐 II 对应 f/II；增加一级流水可能改善吞吐频率，也可能使短依赖链更慢。

由资源守恒可写出上界（各项统一为 dot/s）：

```text
Pdot <= min(Pcompute, Pissue, Pwriteback, BW_bytes_per_s / bytes_per_dot)
```

不复用时每 dot 的两个八字节输入合计 16 字节，但这不等于处理器实际 RF 读端口位宽；有数据重用后有效 bytes/dot 会变化。测量哪一项饱和，才能知道增乘法器或压缩加法树是否有意义。Amdahl 估计只能作为带假设的上界，不能用泛称“LLM 大多是点积”代入并宣布模型加速。

多 workload 汇总时公布全部结果。几何平均适合汇总归一化加速比；真实应用总时间应按实际调用次数加权，不能用简单算术平均的几个加速比替代。缺失或失败样例不从分母偷偷删除。

## 5. 计时要证明顺序，而不是只写 rdcycle

优先在 RTL 事件记录中关联 PC/ROB/tag，明确开始/结束对应的是发射、结果可用、写回还是退休；不同边界不能同名混报。测量单元延迟和软件端到端时间本来就需要不同事件。

若使用 `rdcycle`，须检查目标实现的顺序与依赖。`volatile`、编译器 memory clobber 和普通 `fence` 并不自动构成向量算术的完整串行化证明。用反汇编和目标波形确认被测运算未越过边界，并保留结果消费者与空测量对照。空窗口用于揭示开销，不能无条件减去后把极小或负数当高性能。

周期来自被模拟处理器，不来自 Verilator 在宿主机跑了几秒。NEMU/QEMU 的本次功能运行也不能当香山精确周期模型。

确定性仿真重复运行主要检查可复现，不因三次完全相同就宣称统计置信度很高；非确定性实机测量记录预热、重复数、中位数和离散程度。性能跑前先核验该 ELF 的功能；必要时对正确性和性能使用明确不同日志选项，但不得关闭关键功能比较来隐藏错误。

## 6. 综合、时序、功耗和面积

分清证据级别：结构/算子统计、映射后综合、布局布线后 STA、实机测量。只比较同一级结果；Yosys 的 generic cell 数不等于某工艺面积或频率，FPGA LUT/DSP/BRAM 与 ASIC 标准单元面积也不能混成一个百分比。

每组 PPA 记录：工具/版本、顶层与配置、源码 SHA、库与 PVT、SDC 摘要、输入输出延迟/负载、目标周期、setup/hold、未约束路径、面积分类、寄存器数量、关键路径起止点。新单元与整个核分别给边界，整核原模块不能因新配置漏生成而“面积减少”。

功耗必须说明估计方法、时钟/电压、切换活动来源和输入分布，至少区分低切换与随机输入；平均功率、静态功率、动态功率以及单元/整核范围不能互换。用同一 ROI 的功率与时间计算能量；只有面积/周期时就只报告面积/周期，不估算没有依据的瓦数。

缺少真实工艺/库/约束时，先交生成 RTL、结构统计和可复现脚本，清楚标注 Fmax/功耗尚不可得。不能为填表自行决定学校 EDA 工艺、FPGA 型号或频率目标。

## 7. 最小实验矩阵与选优

| 维度 | 第一轮建议 | 目的 |
| --- | --- | --- |
| 实现 | H0；条件允许后 H1 | 隔离流水变化 |
| 单功能对照 | B13/B6/B7/vdot | 检查强基线与完整接口成本 |
| 算子 | dot；小 GEMV；再小 GEMM | 从单指令走向复用与访存 |
| K | 8/16/128/512/2048；尾部 7/9/127/129 | 短长、尾部及配置摊销 |
| 展开 | U=1/2/4/8 | 依赖隐藏与寄存器压力 |
| 数据 | 边界/负数、固定随机、低切换 | 功能与活动分布 |
| 内存 | 相同预热方式的热数据；明确的冷启动条件 | 区分算术和访存限制 |

不必第一天做全笛卡尔积。先用代表样例找瓶颈，再扩展保留候选；所有裁剪规则在看到最终结果前说明。只改变一个主要因素的消融用来解释因果，组合优化另外报告，不把各项独立改善百分比直接相加。

最优方案定义为：在已确认约束与实际工作负载下，没有另一个已验证候选同时更快且不增加关键成本。若 H0/H1 各有优势，保留 Pareto 结果，由实际评分/约束选择，不创造主观权重硬凑唯一冠军。

## 9. 最终接收标准

**功能接收**：必需可达案例真实执行，无遗漏；全核完整向量比较，合法/异常/取消/依赖链通过；负控真的能失败；原 hello/vadd 及受影响旧指令不退化。

**性能接收**：最快合法对照、相同边界、完整原始记录；至少解释一个决定收益的瓶颈及一个优化的代价。没有实际目标周期就只报告结构/指令计数，不写实测加速。

**物理接收**：具备相同可信约束下的 PPA/STA 才宣称时序/面积/能效优势；否则明确未完成，并提交可复现的后续入口。

**工程接收**：非作者清洁检出成功，外部依赖可获得，版本与命令完整；使用者能从最终 commit 回到每一组证据；保留失败和限制而不把所有格子填成 PASS。
